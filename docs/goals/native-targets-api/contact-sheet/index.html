Native integration contact sheet

Branch cw/native-integration (PR #820), the final full run. Each row is one rung at its launch screen (step 0): the web build in Chromium at the iOS proof device's size (402×778 CSS px, 3×), the iOS simulator (iPhone 17, iOS 27.2) and the Android emulator (API 36). Images are downscaled JPEGs.

Visible differences (judged by eye)

  • Every unstyled rung, iOS: Black background with white text. The simulator was still in dark mode from the run before this one (its last rungs switch the appearance), and an unstyled iOS page follows the system appearance, while the web's unstyled page stays light (no color-scheme). Two findings: the harness does not reset the appearance for a rung that does not set it, and unstyled pages differ from the web in dark mode.
  • Every unstyled rung, both phones: Real elements give headings their sizes and weights, emphasis its italics, lists their markers and rules their lines, as on the web; but blocks have no margins on the phones (paragraphs and headings sit line against line), and the phones use the system sans-serif where the web uses its default serif.
  • Every unstyled rung, Android: Text is light grey (low contrast), and the page starts under the status bar, whose icons do not show over it.
  • s2-shared-component, Android: Two labels are cut off at their end (already on the styles branch).
  • s1 to s5, z1 to z6 (styled): Close match in layout, colour and font. The phones add the system navigation bar and title; the z rungs' web page shows one line the phones do not ("On the web, the fruit open in a drawer"), by design.
  • 11-async, y4-sheet-beside-drawer: Web only: refused by name for the phones.
