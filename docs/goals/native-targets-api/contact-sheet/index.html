Native integration contact sheet

Branch cw/native-integration (PR #820). Each row is one rung at its launch screen (step 0): the web build in Chromium at the iOS proof device's size (402×778 CSS px, 3×), the iOS simulator (iPhone 17, iOS 27.2) and the Android emulator (API 36). Images are downscaled JPEGs.

Visible differences (judged by eye)

  • every unstyled rung (01, 03, 05 to 11, d1 to d7, p1, u1 to u14, y1 to y4, n1 to n4): Web shows the browser's default styles (serif font, large bold headings, bordered buttons, list bullets, blue underlined links, an 8 px page margin); both phones show plain system text in one size with no heading sizes, no button chrome, no bullets and no link styling, so the three never look alike. Not a defect of these branches: an unstyled page has no CSS for Dragon, and no host applies the browser's default style sheet.
  • Android, every unstyled rung: Text is drawn smaller and in light grey (low contrast) next to iOS's black, and the page starts under the status bar, whose icons are white on white and so do not show.
  • 02-styles: Android's button reads "Count" where web and iOS read "Count 0": the number is cut off. Also on the branch's own committed screenshot, so not from this integration.
  • s2-shared-component: Android cuts off the end of two labels ("Basil, in" for "Basil, in stock", "Thyme," for "Thyme, low"). Also on the branch's own committed screenshot.
  • 04-attributes: On both phones the heading and buttons touch the left edge (no page margin); web keeps its margin. The serif web heading is sans-serif on the phones.
  • s1 to s5 (styled apps): Close match in layout, colour and font. Differences: the phones add the system navigation bar with the page title (iOS white with a centred bold title, Android grey-lavender with a left title), which the web shows only as the tab title by design.
  • n1 to n4: Phones show the system navigation bar and a Back arrow (n4); Android's bar is grey and its page background lavender-grey, iOS's white.
  • d3-location, d4-camera: The phones' launch screen is covered by the system permission prompt (expected: the rung asks); the web shows its no-device text by design.
  • p1-platform: Android shows a system "App not found" toast over the page at launch; neither iOS nor web has it. Each platform shows its own "Built for ..." text by design.
  • 11-async, y4-sheet-beside-drawer: Web only: no native build (refused by name), so no phone screenshots.
