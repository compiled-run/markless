A1. `ui`: it's short, everyone knows what it means, and it reads well as `@markless/ui` for headless interface parts.
A2. `headless`: it's the term most web developers already use for "behaviour and accessibility, no styling," like Headless UI or Radix.
A3. `primitives`: it says these are unstyled building blocks you put together and style yourself, the way Radix Primitives does.
B1. `ui`: `<ui.button>` and `<ui.label>` read naturally and fit next to the family namespaces like `tabs` and `modal`.
B2. `base`: it suggests a basic standalone piece, as in `<base.button>`, and doesn't clash with the family names.
B3. `core`: it says "the plain building-block pieces," though it could be confused with the taken `@markless/core` package name.
