A1. `ui`: it's short and obvious, and it matches how most people already talk about headless libraries ("Radix UI", "Headless UI", "Ark UI"), so `@markless/ui` reads as "the components package" right away.
A2. `headless`: it's the word web developers already use for "behaviour and accessibility, no styles", so it says what the package ships.
A3. `primitives`: Radix made this word common for unstyled, accessible building blocks you style yourself.
B1. `ui`: `<ui.button>`, `<ui.label>` and `<ui.separator>` read naturally, and they match the package name.
B2. `base`: it suggests standalone basic pieces that sit below the families, and `<base.button>` is short and clear.
B3. `core`: people see these as the core single elements, though it could be confused with the existing `@markless/core` package.
