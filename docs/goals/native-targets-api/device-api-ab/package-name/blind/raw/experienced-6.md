A1. `ui`: It's the short, obvious name for an interface component library, and it reads cleanly as `@markless/ui` next to `core`, `router` and `web`.
A2. `headless`: Developers already use this word for "behaviour and accessibility, no styles," so it says exactly what the package does.
A3. `primitives`: Radix made this term familiar for unstyled, accessible building blocks you compose and style yourself.
B1. `ui`: `<ui.button>`, `<ui.label>` and `<ui.separator>` read naturally and match the package name, so there's nothing new to remember.
B2. `base`: It marks these as the basic standalone pieces, as opposed to multi-part families like `tabs`.
B3. `core`: It suggests the fundamental built-in elements, but the `@markless/core` package already uses the name, so it could confuse people.
