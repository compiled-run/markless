A1. `ui`: It's short and says exactly what it is, the interface layer, and it reads cleanly as `@markless/ui` next to `core`, `router` and `device`.
A2. `headless`: It's the term web developers already use for "behaviour and accessibility, no styling" (Headless UI, Radix-style), so it signals unstyled right away.
A3. `primitives`: It suggests unstyled building blocks you compose and style yourself, like Radix Primitives.
B1. `ui`: `<ui.button>`, `<ui.label>` and `<ui.separator>` read naturally as "the generic UI piece", and it's the obvious catch-all next to named families.
B2. `base`: It suggests the plain, foundational element that doesn't belong to any family.
B3. `el`: It's short for "element", it stays out of the way, and it hints that these are single standalone parts.
