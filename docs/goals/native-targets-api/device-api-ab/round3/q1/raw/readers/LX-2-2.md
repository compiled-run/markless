## Ranking
1. VR — It names the platforms directly with `platform.ios || platform.android`, so you can read off exactly what the website and the iPhone app each get without knowing anything about the library. The catch is that it says nothing honest about the Mac app, which would show "The camera works in the app." even though it is the app.
2. GP — Each feature carries its own `.supported` check with an explicit else message, and `platform.macos` makes the search hint obvious. You still have to guess which platforms count as "supported" for each feature, but the page's structure tells you what happens either way.
3. QT — It reads the same as GP for the features. `modifierKey === '⌘'` is less clear than `platform.macos` about which platforms show ⌘K, especially the iPhone.
4. LX — The difference between web and app is hidden in exceptions. You only learn that something fails on the web from the wording of the catch messages. You can't tell whether a failure happens when the feature is created or when it is used, and the empty catches hide what actually happens.
5. HN — Nothing tells the website apart from the iPhone. You can't tell from the code what a website visitor sees for the camera, location or Share, or whether the page errors.

B: I would trust GP most, with QT a close second. Both hide Share when `sharesheet.supported` is false and replace the camera with a message. I would trust HN least: the website shows Share and Take photo buttons whatever the platform supports, and nothing handles the case where they fail. Haptics is called without a guard in every version except LX, so Like may only partly work on the website in all of them.

C: Yes, the first version was LX, and four answers change.
Offline banner (1d): the others guard it with `network.supported`, which suggests the network feature may be unsupported on the web. In LX the banner probably never shows for website visitors, so I am now less sure it works there.
Haptics (1c, 3): the other versions call `haptics.tap` with no guard, which suggests it quietly does nothing where unsupported. The try/catch in LX is probably unnecessary, and Like on the website just counts.
Search hint (1f, 2f): VR and GP use `platform.macos`, which would make the iPhone show "Ctrl+K". `modifierKey` may give '⌘' on the iPhone instead, so the iPhone answer is still uncertain.
Camera, location and Share on the website (1a, 1b, 1e): the others confirm these are unavailable there. So "The camera works in the app.", "Location works in the app." and, after pressing Share, "Sharing works in the app." are now my firmer answers.
