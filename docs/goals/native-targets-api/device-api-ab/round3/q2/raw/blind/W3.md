import { platform } from '@markless/device';

const isMacBrowser =
	platform === 'web' &&
	typeof navigator !== 'undefined' &&

const onMac = platform === 'macos' || isMacBrowser;

		}

		}
	</main>
}

## Guesses
- `platform` is a plain string constant, not a function or object, typed as `'ios' | 'android' | 'macos' | 'windows' | 'web'`.
- The exact spellings are guesses: `'ios'` rather than `'iphone'`, `'macos'` rather than `'mac'` or `'darwin'`, and `'web'` rather than `'website'` or `'browser'`.
- `platform` names the build target, not the operating system underneath. So the website build always reports `'web'`.
- For the keyboard hint, I sniff `navigator.platform` on the website to catch Mac users in a browser. During server rendering there is no `navigator`, so the server shows "Ctrl+K". That could cause a hydration mismatch for Mac visitors. I don't know whether Markless handles that.
- I assume `@if` works with a plain, non-state value.

## Answers
A: iOS is `platform === 'ios'`. macOS is `platform === 'macos'`. The website is `platform === 'web'`.

B: It gives `false`. The website build reports `platform === 'web'` whatever computer or browser it runs on. `platform` says which build is running, not which operating system the person uses. That is why the ⌘K hint also checks `navigator.platform` when running on the web.

C: Two other spellings I'd find plausible are `device.os` (for example `device.os === 'macos'`) and an object of booleans such as `platform.isIOS` / `platform.isWeb`. I would rather read the plain string, `platform === 'macos'`. Its type lists every possible value, it's easy to use in a `switch`, and a typo fails the type check.
