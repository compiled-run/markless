import { platform } from '@markless/device';

const onMacWeb =
	platform === 'web' &&
	typeof navigator !== 'undefined' &&
	/Mac/.test(navigator.platform || navigator.userAgent);

export default function SearchHint() @{
	const isMac = platform === 'macos' || onMacWeb;
	<p>{isMac ? 'Press ⌘K to search' : 'Press Ctrl+K to search'}</p>
}

## Guesses
- `platform` is a plain string constant, not reactive state and not a function, with the values `'ios' | 'android' | 'macos' | 'windows' | 'web'`.
- The exact spellings are guesses: `'macos'` rather than `'mac'` or `'darwin'`, and `'web'` rather than `'browser'`.
- `platform` names the build target, not the operating system underneath. That is why I added a separate `navigator` check for Mac users on the website.
- The `typeof navigator` guard assumes the code may also run during server-side rendering.
- I assumed an `@if` with no `@else` is allowed, and that a component may wrap it in `<>…</>` as its one root element.

## Answers
A: `platform === 'ios'`, `platform === 'macos'`, `platform === 'web'`

B: It gives `false`. On the website build, `platform` is `'web'`, because the value describes which build is running, not the computer's operating system. So a Mac user in Safari would see "Ctrl+K" unless the `navigator` check is added, which is why SearchHint includes it.

C: `device.platform` (a property on a device object) and `os` (for example `os === 'ios'`). I would rather read `platform`: it is short, and it fits the "which build am I" meaning better than `os`, which wrongly suggests Safari on a Mac would report macOS.
