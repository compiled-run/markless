## Guesses

- `platform` is a plain string constant (not a function and not state). Its type is `'ios' | 'android' | 'macos' | 'windows' | 'web'`.
- The values are lowercase: `'ios'`, `'android'`, `'macos'`, `'windows'`, `'web'`. It could instead be `'mac'`, `'darwin'` or `'browser'`.
- `platform` is fixed when the app starts, so reading it once in the component body is fine.
- An `@if` with no `@else` is allowed inside a fragment root.
- `platform` names the build target, not the user's operating system. That means a website visitor on a Mac gets the Ctrl+K hint. To get the ⌘K hint there too, I would need a separate operating-system fact, such as a guessed `os` export, and I did not invent one.

## Answers

A: `platform === 'ios'`, `platform === 'macos'`, `platform === 'web'`

B: It gives `false`. In the website build `platform` is `'web'`, because it describes the build that is running, not the visitor's operating system. So a Mac user in Safari sees "Press Ctrl+K to search", which is wrong for that person. Telling them apart would need a separate operating-system value.

C: `platform.os === 'ios'` (an object with fields such as `os` and `isWeb`), or boolean flags such as `platform.isIOS` / `platform.isWeb`. I would rather read the plain string comparison `platform === 'ios'`: it is short, can be checked exhaustively as a union, and is easy to search for. The object form would be my second choice, because it could keep the operating system and the build target apart, which is exactly the problem in question B.
