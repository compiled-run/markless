## Ranking
1. DL — It's the shortest form. Comparing one string per check makes it obvious that `platform` holds a single value, so the branches can't overlap.
2. JE — Boolean flags read naturally (`platform.ios`). But nothing stops two flags from being true at once, such as `web` and `macos` together.
3. UF — It's the same as JE, but the casing is mixed (`macOS`, `iOS`, `web`, `android`). I'd have to remember each name's brand casing instead of following one rule.
4. XB — It's readable but misleading. `platform.os === 'web'` calls the website an operating system. The name `os` suggests it reports the user's real operating system, which contradicts 'web' being one of its values.

B: DL. It's the least to type and uses one consistent lowercase rule. A string union would also let the type checker catch typos and check that every platform is covered, assuming `platform` is typed that way, which I'm guessing. Comparing one value also tells me each build matches exactly one branch.

C: DL is the clearest. One value that can be 'web' or 'macos', but not both, can only mean "which build is this", so the Mac test is false on the website. JE and UF are less clear: separate flags could mean `macos` is true for a website open on a Mac, which would push me toward answer (c). XB is the most confusing, because `os` hints at the browser's operating system while 'web' is still listed as one of its values. None of the spellings changed my answer to question 2. I still pick (b), with the most confidence in DL, the version I first read.
