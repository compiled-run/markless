## Ranking
1. DL: `platform === 'macos'` reads as "this build is the Mac build". A single value makes it obvious that only one target applies at a time, so `web` and `macos` can't both be true.
2. JE: The short lowercase booleans are easy to scan. They don't show that the flags are mutually exclusive, though, so you have to infer it.
3. UF: It reads like Apple's own branding, but the casing is mixed (`macOS`/`iOS` next to `web`/`android`). That makes it easy to mistype and hard to guess for the next flag.
4. XB: It is the longest to read, and the name `os` is misleading. It suggests the device's operating system, yet `'web'` is not an operating system. That makes the Mac-in-a-browser question murkier, not clearer.

B: I'd rather write DL. It is short, comparing against a string literal can be autocompleted and type-checked against a union type, and the single value tells the next reader that exactly one target applies. JE would be my second choice. I'd avoid UF because of its casing traps.

C: DL is the clearest. Because `platform` is one value and `'web'` is one of its options, the website build cannot also be `'macos'`. So the Mac test is false in Safari on a Mac, and it plainly means "this is the Mac app". XB pulls the other way: the name `os` hints at the browser's operating system, but having `'web'` as an `os` value contradicts that reading. No spelling changed my answer to question 2, which stays (b). DL raises my confidence in it from 3 to about 4.
