## Ranking
1. RZ — `cameraApp.open()` says plainly that it opens the phone's camera app. Every system screen follows the same `x.open()` pattern, and the only on-page camera calls go through the `cam` instance, so the two kinds can't be confused.
2. NB — It uses the same `.open()` pattern. `cameraScreen` clearly names a separate screen, though "screen" is a bit vaguer than "app" about whose screen it is.
3. TJ — It also uses the same pattern. But `systemCamera` could be read as a camera object you use on the page, not a screen you open. `.open()` is what saves it.
4. WK — `openSettings`/`openShareSheet` signal that a screen opens, but `choosePhoto` and especially `takePhoto` don't. A bare `takePhoto()` sits right beside `cam.takePhoto()`, and nothing in the name says the bare one opens the phone's camera instead of using the camera on the page.
5. FD — `camera.takePhoto()` against `cam.takePhoto()` is the worst pair. `camera` is both the factory for the camera on the page and a namespace that opens the phone's camera, so the two calls differ by one identifier and mean opposite things.

B: `cameraApp` reads best. It names the thing the user actually sees: the phone's own camera app, with the app leaving the page. `cameraScreen` is close behind but vaguer about whose screen it is. `systemCamera` sounds like a device or object rather than a destination, so `.open()` on it is less obvious.

C: My answers about FD hold, and comparing the versions confirms the guesses I made. All four other versions turn "Use phone camera" into an explicit system screen (`cameraApp`/`cameraScreen`/`systemCamera.open()`, or a bare `takePhoto()`), which confirms that `camera.takePhoto()` opens the phone's camera app. `choosePhoto` maps to `photoLibrary.open()`, which confirms it opens the photo library or picker. `openShareSheet` maps to `sharesheet.open()`, which makes it a system screen in its own right; in answer 1 I had counted it only as an overlay.
