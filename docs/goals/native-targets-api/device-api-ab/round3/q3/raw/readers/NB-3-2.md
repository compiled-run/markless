## Ranking
1. RZ: `cameraApp.open()` clearly means the phone's own Camera app. It reads like `settings.open()` and `photoLibrary.open()`, so every external screen follows one `.open()` pattern. It also can't be confused with `camera()`, the on-page camera.
2. TJ: `systemCamera.open()` clearly marks the phone's camera as belonging to the system, not the page. "System" is slightly more abstract than "app", though.
3. NB: `cameraScreen.open()` follows the same pattern, but "screen" could mean the camera view on this page. `camera()` and `cameraScreen` differ only by a suffix.
4. WK: The `openSettings`, `choosePhoto` and `openShareSheet` verbs are readable. But `takePhoto()` and `cam.takePhoto()` share the same name, and nothing in the name says that the bare function opens the phone's camera instead of using the on-page one.
5. FD: `camera.takePhoto()` (the phone's camera) next to `cam.takePhoto()` (the on-page camera) is the easiest mix-up of all. The same `camera` export is both a function that makes the on-page camera and a namespace for the phone's camera, and only a variable name separates them.

B: `cameraApp` reads best. Users already know "the Camera app" as the phone's own camera screen. It shows plainly that you leave the page, and it doesn't overlap with `camera()` or `base.camera`. `systemCamera` comes next: it says the camera belongs to the phone but sounds more technical. `cameraScreen` is the weakest, because the page itself shows a camera screen.
