A: I prefer `sharesheet` (version PY). Next to `shared` from `@markless/core`, `share` is only one letter away, so the two are easy to confuse while scanning or typing, especially since both start with "share". `sharesheet` names exactly what it opens, the phone's native share sheet. It also matches iOS and Android wording, and `sharesheet.open()` reads naturally as "open the sheet". The cost is a longer and slightly less familiar name. Plain `share` is also something you do, so `share.open` reads a little oddly.

B: `share` is the risky one. A reader or autocomplete could take `share` for `shared`, or the reverse; one misplaced "d" changes which package and feature you get. It also looks like the browser's `navigator.share()`, which is a function you call directly. Someone might write `share({ title, url })` instead of `share.open(...)`, or assume it behaves exactly like the web API. `sharesheet` is very unlikely to be mistaken for `shared`. Its only small risk is that it could suggest a spreadsheet, a "shared sheet" or a CSS stylesheet, but the `.open({ title, url })` call clears that up quickly. When I read version KD, I did briefly have to check that `share` came from `@markless/device` and not `@markless/core`.

Tools used: none
