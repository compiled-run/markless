A: `sharesheet` (version PY) reads clearer. It names the thing that appears, the phone's system share sheet, so `sharesheet.open(...)` clearly means "show the share UI." Next to `shared` from `@markless/core`, it doesn't look like a variation of that word. `share` (version KD) is only one letter away from `shared`, and in a file that imports both, the eye can blur them.

B: `share` could be mistaken for `shared` because of the one-letter difference. Someone skimming or using autocomplete might type `shared.open` or `share(() => ...)`, or assume `share` is the core state-sharing primitive or related to it. It also reads as a verb ("share this"), so `share.open` is a slightly odd phrase. It also resembles the web `navigator.share()`, which is a function you call directly, not an object with `.open`. `sharesheet` is unlikely to be confused with `shared`. Its closest look-alikes are the platform terms (the iOS share sheet, the Android sharesheet), and that resemblance helps because it means the same thing. Its only small risk is that someone reads it as "spreadsheet"-like data or a style sheet, which I think is unlikely.
