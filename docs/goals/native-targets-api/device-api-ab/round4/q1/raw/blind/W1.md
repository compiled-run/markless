## Invented API

```ts
// Module: @markless/router (addition)
// How a page is shown on iPhone and Android. 'screen' is the default.
export type Presentation = 'screen' | 'sheet';
// Convention: a page file can export `presentation`. A sheet page slides up over the screen below it, and that screen stays visible behind it.
// A sheet is still a screen on the stack. Swiping it down is Back, back() closes it, and the screen below shows exactly as it was left.
// On the website `presentation` is ignored and the page loads as an ordinary page.
export declare const presentation: Presentation; // e.g. `export const presentation = 'sheet';` in pages/cart.tsrx
```

// file: pages/orders/[id].tsrx
import { computed, storage } from '@markless/core';
import { back, navigate, type PageProps } from '@markless/router';
import { platform } from '@markless/device';
import { modal } from '@markless/ui';
import { deleteOrder, getOrder } from '../../api.ts';

export default function OrderPage({ params }: PageProps<{ id: string }>) @{
	let ordersVersion = storage('orders.version', '');
	const order = computed(async ({ signal }) => await getOrder(params.id, signal));

	const remove = async () => {
		await deleteOrder(params.id);
		ordersVersion = String(Date.now());
		if (platform === 'web') {
			navigate('/orders', { replace: true });
		} else {
			back();
		}
	};

	<main>
		@try {
			<h1>Order {order.id}, total {order.total}</h1>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
		<modal.root alert>
			<modal.trigger>Delete</modal.trigger>
			<modal.backdrop>
				<modal.content>
					<modal.title>Delete this order?</modal.title>
					<button onClick={remove}>Delete</button>
					<modal.close>Cancel</modal.close>
				</modal.content>
			</modal.backdrop>
		</modal.root>
	</main>
}

// file: pages/checkout.tsrx
import { computed, storage } from '@markless/core';
import { navigate } from '@markless/router';
import { getAddresses } from '../api.ts';

export default function Checkout() @{
	let addressId = storage('checkout.addressId', '');
	const chosen = computed(async ({ signal }) => {
		const id = addressId;
		const list = await getAddresses(signal);
		return list.find((a) => a.id === id) ?? null;
	});

	<main>
		<h1>Checkout</h1>
		<p>
			Deliver to:{' '}
			@try {
				@if (chosen) {
					<span>{chosen.label}: {chosen.line1}, {chosen.city}</span>
				} @else {
					<span>No address chosen</span>
				}
			} @pending {
				<span>Loading…</span>
			} @catch (error) {
				<span>{error.message}</span>
			}
			<button onClick={() => navigate('/checkout/address')}>Change</button>
		</p>
	</main>
}

```tsrx
// file: pages/checkout/address.tsrx
import { computed, state, storage } from '@markless/core';
import { back, navigate } from '@markless/router';
import { platform } from '@markless/device';
import { addAddress, getAddresses } from '../../api.ts';

export const presentation = 'sheet';

export default function AddressSheet() @{
	let addressId = storage('checkout.addressId', '');
	let step = state<'list' | 'form'>('list');
	let label = state('');
	let line1 = state('');
	let city = state('');
	const addresses = computed(async ({ signal }) => await getAddresses(signal));

	const done = () => {
		if (platform === 'web') {
			navigate('/checkout', { replace: true });
		} else {
			back();
		}
	};
	const pick = (id: string) => {
		addressId = id;
		done();
	};
	const save = async (event: SubmitEvent) => {
		event.preventDefault();
		const created = await addAddress({ label, line1, city });
		addressId = created.id;
		done();
	};

	<section>
		@if (step === 'list') {
			<div>
				<h1>Deliver to</h1>
				@try {
					<ul>
						@for (const address of addresses; key address.id) {
							<li>
								<button onClick={() => pick(address.id)}>
									{address.label}: {address.line1}, {address.city}
								</button>
							</li>
						}
					</ul>
				} @pending {
					<p>Loading…</p>
				} @catch (error, reset) {
					<p>
						{error.message}
						<button onClick={reset}>Retry</button>
					</p>
				}
				<button onClick={() => (step = 'form')}>Add new address</button>
			</div>
		} @else {
			<form onSubmit={save}>
				<h1>New address</h1>
				<input placeholder="Label" value={label} onInput={(event) => (label = event.currentTarget.value)} />
				<input placeholder="Street" value={line1} onInput={(event) => (line1 = event.currentTarget.value)} />
				<input placeholder="City" value={city} onInput={(event) => (city = event.currentTarget.value)} />
				<button type="button" onClick={() => (step = 'list')}>Back</button>
				<button type="submit">Save</button>
			</form>
		}
	</section>
}
```

## Guesses

- I guessed that a page can export a value besides its default component, and that the router reads `presentation` from it.
- I guessed that a sheet is a normal stack screen: it gets its own state, and swiping it down is the same as `back()`.
- I guessed that a computed reading `storage` re-runs when another screen assigns to that key. The sheet says assigning "updates every screen at once", so I rely on that to refresh Orders after a delete and Checkout after picking an address.
- I guessed that a state read before the first `await` in an async computed is tracked.
- I guessed the `@if … @else` syntax, `{' '}`, and inline `@try` inside a `<p>`.
- I guessed that an `async` handler on a `modal` child is allowed and that code after `await` in a handler still runs. Only code after `navigate`/`back` is cut off.
- I guessed the `SubmitEvent` typing for `onSubmit`, and that `type` is passed through on buttons.
- I left out error handling for `deleteOrder` and `addAddress`, and any "saving…" state.

## Website

1: The Cart link loads `/cart` as an ordinary full page. There is no Close button, so visitors use the browser's Back.

2: The same alert dialog appears. Delete then loads `/orders` in place of the order page, so Back does not return to the deleted order.

3: Change loads `/checkout/address` as a full page. Picking an address saves it in a cookie and loads `/checkout`, which shows the choice.

4: The same two steps run on the `/checkout/address` page. Saving loads `/checkout` with the new address chosen.

5: Push notifications do not apply to the website. If the `/cart` path is opened in a browser, it is the full cart page.

## Answers

A: A page file that exports `presentation = 'sheet'` opens as a sheet over the current screen on iPhone and Android wherever it is reached from (a link, `navigate`, or a notification path); swiping down or calling `back()` closes it, and on the website it is an ordinary page.

B: The decision could have lived on the link (`<Link sheet>`), on the opening page, in app config, or on the page being shown. I picked the page being shown, because it is the only place every way of arriving agrees on. That includes a notification or outside link with no opener at all, and in those cases a link-level or opener-level flag would be missing.

C: State belongs to one screen, so the sheet writes the chosen address id to `storage('checkout.addressId')`. On a phone this updates the Checkout screen kept below at once, and `back()` reveals it. On the website the value is a cookie, and the sheet navigates to `/checkout`, whose freshly loaded page reads it.

D: With the app closed, opening `/cart` builds Home (`/`) and then the cart sheet over it, so the user sees the cart with Home behind it. Back (or a swipe down) closes the sheet and leaves them on Home; Back again exits the app.
