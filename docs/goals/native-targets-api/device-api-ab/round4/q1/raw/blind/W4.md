## Invented API

```ts
// Module: @markless/router (addition)
// How a page's screen is presented on iPhone and Android: 'screen' (the default) pushes a full screen;
// 'sheet' pushes a panel that slides up from the bottom over the screen below, which stays visible behind it.
export type Presentation = 'screen' | 'sheet';
// Optional named export of a page file. It sets how that page is presented wherever it is opened from:
// a Link, navigate(), or a deep link / push notification. A swipe down on a sheet is the system Back.
// On the website it is ignored, and the page loads as an ordinary page.
//   export const presentation: Presentation = 'sheet';
export declare const presentation: Presentation; // (page-module convention, read by the router at build time)
```

```tsrx
// file: pages/orders/[id].tsrx
import { computed, storage } from '@markless/core';
import { back, navigate, type PageProps } from '@markless/router';
import { platform } from '@markless/device';
import { modal } from '@markless/ui';
import { deleteOrder, getOrder } from '../../api.ts';

export default function OrderPage({ params }: PageProps<{ id: string }>) @{
	let ordersVersion = storage('ordersVersion', '0');
	const order = computed(async ({ signal }) => await getOrder(params.id, signal));

	const remove = async () => {
		await deleteOrder(params.id);
		ordersVersion = String(Number(ordersVersion) + 1);
		if (platform === 'web') {
			await navigate('/orders', { replace: true });
		} else {
			back();
		}
	};

	<main>
		@try {
			<>
				<h1>Order {order.id}</h1>
				<p>{order.placedAt}: {order.total}</p>
			</>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<button onClick={reset}>{error.message}</button>
		}
		<modal.root alert>
			<modal.trigger>Delete</modal.trigger>
			<modal.backdrop>
				<modal.content>
					<modal.title>Delete this order?</modal.title>
					<button onClick={remove}>Delete</button>
					<modal.close>Cancel</modal.close>
				</modal.content>
			</modal.backdrop>
		</modal.root>
	</main>
}
```

```tsrx
import { computed, storage } from '@markless/core';
import { navigate } from '@markless/router';
import { getAddresses } from '../api.ts';

export default function Checkout() @{
	let deliveryAddress = storage('deliveryAddress', '');
	const addresses = computed(async ({ signal }) => {
		deliveryAddress;
		return await getAddresses(signal);
	});
	const chosen = computed(() => addresses.find((a) => a.id === deliveryAddress));

	<main>
		<h1>Checkout</h1>
		<p>
			Deliver to:{' '}
			@try {
				<span>{chosen ? `${chosen.label}, ${chosen.line1}, ${chosen.city}` : 'No address chosen'}</span>
			} @pending {
				<span>Loading…</span>
			} @catch (error, reset) {
				<button onClick={reset}>{error.message}</button>
			}
		</p>
		<button onClick={() => navigate('/checkout/address')}>Change</button>
	</main>
}
```

```tsrx
// file: pages/checkout/address.tsrx
import { computed, state, storage } from '@markless/core';
import { back, type Presentation } from '@markless/router';
import { addAddress, getAddresses } from '../../api.ts';

export const presentation: Presentation = 'sheet';

export default function AddressSheet() @{
	let deliveryAddress = storage('deliveryAddress', '');
	let step = state<'list' | 'form'>('list');
	let label = state('');
	let line1 = state('');
	let city = state('');
	let saveError = state('');
	const addresses = computed(async ({ signal }) => await getAddresses(signal));

	const save = async () => {
		try {
			const address = await addAddress({ label, line1, city });
			deliveryAddress = address.id;
			back();
		} catch (error) {
			saveError = (error as Error).message;
		}
	};

	<section aria-label="Deliver to">
		@if (step === 'list') {
			<>
				<h2>Deliver to</h2>
				@try {
					<ul>
						@for (const address of addresses; key address.id) {
							<li>
								<button onClick={() => { deliveryAddress = address.id; back(); }}>
									{address.label}: {address.line1}, {address.city}
								</button>
							</li>
						}
					</ul>
				} @pending {
					<p>Loading…</p>
				} @catch (error, reset) {
					<p>
						{error.message}
						<button onClick={reset}>Retry</button>
					</p>
				}
				<button onClick={() => (step = 'form')}>Add new address</button>
			</>
		} @else {
			<form onSubmit={(event) => { event.preventDefault(); save(); }}>
				<h2>New address</h2>
				<input placeholder="Label" value={label} onInput={(event) => (label = event.currentTarget.value)} />
				<input placeholder="Street" value={line1} onInput={(event) => (line1 = event.currentTarget.value)} />
				<input placeholder="City" value={city} onInput={(event) => (city = event.currentTarget.value)} />
				<p>{saveError}</p>
				<button type="button" onClick={() => (step = 'list')}>Back to list</button>
				<button type="submit">Save</button>
			</form>
		}
	</section>
}
```

## Guesses

- The form of the API: an optional `presentation` export on the page file, which the router reads the same way it reads the default export.
- A swipe down on a sheet behaves exactly like `back()`. `back()` called from a sheet closes it.
- A deep link to a sheet page follows the usual rule (one screen for each leading part of the path), and the last part of the path is shown as a sheet over the screens below it.
- `api.ts` sits at the app root, beside `pages/`.
- `pages/checkout.tsrx` and `pages/checkout/address.tsrx` can exist side by side, the same way `orders.tsrx` and `orders/[id].tsrx` do.
- An order page is only reached from Orders (or from a deep link, which puts Orders below it). That is why `back()` after deleting lands on Orders on phones.
- A synchronous `computed` can read an async computed when it is read inside `@try`.
- The text `Deliver to:` and the `@try` block can sit as siblings inside the `<p>`.
- An async handler can be passed straight to `onClick` and `onSubmit`.
- A thrown `Error` inside a handler is caught by an ordinary `try/catch`.

## Website

1: The cart is an ordinary full page at `/cart`, with a "Continue shopping" link back to Home.

2: The same alert dialog appears. Delete then replaces the order page with a freshly loaded Orders page.

3: The address picker is an ordinary page at `/checkout/address`. Picking an address goes back, and the browser loads Checkout again with the choice, because the choice is kept in a cookie.

4: The form appears as the second step on that same address page. Saving it goes back to Checkout with the new address shown.

5: The website gets no push notification. If someone visits `/cart` directly, they get the cart page.

## Answers

A: Export `presentation = 'sheet'` from a page file, and every way of reaching that page shows it as a sheet on phones (a full page on the website); close the sheet with `back()` or a swipe down.

B: The decision could live on the link (`<Link sheet>`), on the page being shown, on the page that opens it (wrapping it in a component), or in app config (a route table). I put it on the page being shown. That way deep links and push notifications, which have only a path and no link or opening page, still present it correctly, and every way into the page agrees.

C: The sheet writes the chosen address id to `storage('deliveryAddress')` and calls `back()`. On a phone, the Checkout screen kept on the stack updates immediately, because `storage` updates every screen at once. On the website, the value is in a cookie, so the Checkout page the server sends again after Back reads it and shows the choice.

D: They see Home with the cart sheet over it, because the path `/cart` builds `/` and then `/cart` as a sheet on top. Back, or a swipe down, closes the sheet and leaves them on Home.
