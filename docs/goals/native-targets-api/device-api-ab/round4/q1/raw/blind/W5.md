## Invented API

```ts
// Module: @markless/router (addition)
// A page file may export `presentation`. On iPhone and Android, 'sheet' shows the page as a sheet sliding up over the screen below it, which stays visible; swiping it down is the same as Back. The website ignores it and shows a normal page.
export type Presentation = 'screen' | 'sheet';
// Page-file convention: `export const presentation: Presentation = 'sheet';` next to the default export. Leaving it out means 'screen'.
// A sheet is still a route on the stack: Link, navigate(), back(), deep links and notification paths all treat it like any other screen.
```

```tsx
// file: pages/orders/[id].tsrx
import { computed, state, storage } from '@markless/core';
import { back, navigate, type PageProps } from '@markless/router';
import { platform } from '@markless/device';
import { modal } from '@markless/ui';
import { deleteOrder, getOrder } from '../../api.ts';

export default function OrderPage({ params }: PageProps<{ id: string }>) @{
	let ordersVersion = storage('ordersVersion', '0');
	let deleting = state(false);
	let deleteError = state('');
	const order = computed(async ({ signal }) => await getOrder(params.id, signal));

	async function remove() {
		deleting = true;
		deleteError = '';
		try {
			await deleteOrder(params.id);
		} catch (error) {
			deleteError = (error as Error).message;
			deleting = false;
			return;
		}
		ordersVersion = String(Number(ordersVersion) + 1);
		if (platform === 'web') {
			navigate('/orders', { replace: true });
		} else {
			back();
		}
	}

	<main>
		@try {
			<>
				<h1>Order {order.id}</h1>
				<p>{order.placedAt}: {order.total}</p>
			</>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
		<modal.root alert>
			<modal.trigger>Delete</modal.trigger>
			<modal.backdrop>
				<modal.content>
					<modal.title>Delete this order?</modal.title>
					<modal.description>{deleteError}</modal.description>
					<button disabled={deleting} onClick={() => remove()}>Delete</button>
					<modal.close>Cancel</modal.close>
				</modal.content>
			</modal.backdrop>
		</modal.root>
	</main>
}
```

```tsx
// file: pages/checkout/address.tsrx
import { computed, state, storage } from '@markless/core';
import { back, navigate, type Presentation } from '@markless/router';
import { platform } from '@markless/device';
import { addAddress, getAddresses } from '../../api.ts';

export const presentation: Presentation = 'sheet';

export default function AddressSheet() @{
	let deliverTo = storage('deliverTo', '');
	let adding = state(false);
	let label = state('');
	let line1 = state('');
	let city = state('');
	let saving = state(false);
	let saveError = state('');
	const addresses = computed(async ({ signal }) => await getAddresses(signal));

	function done() {
		if (platform === 'web') {
			navigate('/checkout', { replace: true });
		} else {
			back();
		}
	}

	function pick(id: string) {
		deliverTo = id;
		done();
	}

	async function save(event: SubmitEvent) {
		event.preventDefault();
		saving = true;
		saveError = '';
		try {
			const address = await addAddress({ label, line1, city });
			deliverTo = address.id;
		} catch (error) {
			saveError = (error as Error).message;
			saving = false;
			return;
		}
		done();
	}

	<section>
		<h2>Deliver to</h2>
		@if (adding) {
			<form onSubmit={save}>
				<input placeholder="Label" value={label} onInput={(event) => (label = event.currentTarget.value)} />
				<input placeholder="Street" value={line1} onInput={(event) => (line1 = event.currentTarget.value)} />
				<input placeholder="City" value={city} onInput={(event) => (city = event.currentTarget.value)} />
				<p>{saveError}</p>
				<button type="submit" disabled={saving}>Save</button>
				<button type="button" onClick={() => (adding = false)}>Back to list</button>
			</form>
		} @else {
			<>
				@try {
					<ul>
						@for (const address of addresses; key address.id) {
							<li>
								<button onClick={() => pick(address.id)}>
									{address.label}: {address.line1}, {address.city}
								</button>
							</li>
						}
					</ul>
				} @pending {
					<p>Loading…</p>
				} @catch (error, reset) {
					<p>
						{error.message}
						<button onClick={reset}>Retry</button>
					</p>
				}
				<button onClick={() => (adding = true)}>Add new address</button>
			</>
		}
	</section>
}
```

Confidence: 3/5

## Guesses

- A page file can export `presentation` next to its default export, and the router reads it. This is the invented part.
- Swiping a sheet down is the same as `back()`. The sheet stays on the stack like any screen, and its own state lives as long as the sheet does.
- Plain function declarations (`function done() {}`) are allowed in a component body, and a handler outside `@try` may call them.
- Assigning to `storage` from a sheet re-runs async computeds that read that key on the screen below. This is how checkout and Orders refresh.
- On the website, Back may show a stale copy of a page, so after picking an address or deleting an order I use `navigate(..., { replace: true })` there instead of `back()`.
- `{' '}`, `?.` and `??` work in template expressions, and `disabled` is accepted on native elements.
- `modal.description` with an empty string is harmless.
- The server's push-sending code is outside this app; I only wrote the payload shape.

## Website

1. Cart: `/cart` is an ordinary full page. Close (or the browser's Back) returns to the previous page.
2. Delete order: the same alert dialog. After deleting, the order page is replaced by a freshly loaded `/orders`.
3. Change address: `/checkout/address` is an ordinary page. Picking an address saves it in the `deliverTo` cookie and replaces this page with `/checkout`, which reads the cookie.
4. Add address: the same two-step page. Saving adds the address, picks it and replaces the page with `/checkout`.
5. Notification: websites get no push here. Opening `/cart` directly shows the cart page.

## Answers

A: Put `export const presentation = 'sheet'` in a page file. On phones every link to that page then opens as a sheet over the current screen, closed by a swipe down or `back()`, and the website ignores it.

B: The decision could have lived in the link (`<Link sheet>`), in the page that opens it, in app config, or in the page that is shown. I put it in the page that is shown, for three reasons. The cart is a sheet no matter which of the three pages opens it. Deep links and notification paths have no link or opener to ask. And the sheet stays a route, so `back()`, the push `path` and the website all keep working unchanged.

C: The choice goes through `storage('deliverTo')`. On a phone, assigning it updates checkout, which is still on the stack under the sheet, and then `back()` closes the sheet. On the website the value is stored in a cookie, and the page is replaced with `/checkout`, which reads it.

D: The notification carries `path: '/cart'`. The app builds `/` and then `/cart` on top, so the user sees Home with the cart sheet over it. Swiping down or pressing Back closes the sheet and shows Home, and Back from Home leaves the app.
