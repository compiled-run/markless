## Invented API

```ts
// Module: @markless/router (addition: a page convention)
export type Presentation = 'screen' | 'sheet';
// A page file may export this beside its default component. With 'sheet', on iPhone and Android every visit to that route opens it as a sheet over the screen below; that screen stays visible and keeps its state. A swipe down, system Back or back() closes the sheet. On the website the route is an ordinary page. If the page does not export it, the value is 'screen'.
export declare const presentation: Presentation;
```

```tsx
import { computed } from '@markless/core';
import { back } from '@markless/router';
import { platform } from '@markless/device';
import { getCart } from '../api.ts';

export const presentation = 'sheet';

export default function Cart() @{

	<section>
		<h1>Cart</h1>

				@for (const line of lines; key line.id) {

				}
			</ul>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
		@if (platform !== 'web') {
			<button onClick={() => back()}>Close</button>
		}
	</section>
}
```

```tsx
// file: pages/orders/[id].tsrx
import { computed, storage } from '@markless/core';
import { back, type PageProps } from '@markless/router';
import { modal } from '@markless/ui';
import { deleteOrder, getOrder } from '../../api.ts';

export default function OrderPage({ params }: PageProps<{ id: string }>) @{
	let ordersChanged = storage('ordersChanged', '');
	const order = computed(async ({ signal }) => await getOrder(params.id, signal));

	async function remove() {
		await deleteOrder(params.id);
		ordersChanged = String(Date.now());
		back();
	}

	<main>
		@try {
			<>
				<h1>Order {order.id}</h1>
				<p>{order.placedAt}: {order.total}</p>

				{error.message}

			</p>
```

```tsx
// file: pages/checkout/address.tsrx
import { computed, state, storage } from '@markless/core';
import { back } from '@markless/router';
import { addAddress, getAddresses } from '../../api.ts';

export const presentation = 'sheet';

export default function AddressSheet() @{
	let deliverTo = storage('deliverTo', '');
	let step = state<'list' | 'form'>('list');
	let label = state('');
	let line1 = state('');
	let city = state('');
	const addresses = computed(async ({ signal }) => await getAddresses(signal));

	function pick(id: string) {
		deliverTo = id;
		back();
	}

	async function save() {
		const address = await addAddress({ label, line1, city });
		deliverTo = address.id;
		back();
	}

	<section>
		@if (step === 'list') {
			<div>
				<h1>Deliver to</h1>
				@try {
					<ul>
						@for (const address of addresses; key address.id) {
							<li>
								<button onClick={() => pick(address.id)}>
									{address.label}: {address.line1}, {address.city}
								</button>
							</li>
						}
					</ul>
				} @pending {
					<p>Loading…</p>
				} @catch (error, reset) {
					<p>
						{error.message}
						<button onClick={reset}>Retry</button>
					</p>
				}
				<button onClick={() => (step = 'form')}>Add new address</button>
			</div>
		} @else {
			<form
				onSubmit={(event) => {
					event.preventDefault();
					save();
				}}
			>
				<h1>New address</h1>
				<input placeholder="Label" value={label} onInput={(event) => (label = event.currentTarget.value)} />
				<input placeholder="Street" value={line1} onInput={(event) => (line1 = event.currentTarget.value)} />
				<input placeholder="City" value={city} onInput={(event) => (city = event.currentTarget.value)} />
				<button type="button" onClick={() => (step = 'list')}>Back</button>
				<button type="submit">Save</button>
			</form>
		}
	</section>
}
```

The notification carries the path `/cart`. It needs no extra code: the server sends it, and `pages/cart.tsrx` already says the page is a sheet.

Confidence: 3/5

## Guesses

- I guessed that the router reads a named export (`presentation`) from a page file next to its default export.
- I guessed that a sheet route counts as one entry on the system stack. That means `back()`, the system Back and a swipe down all close it, and the screen below stays as it was left.
- When a path opens the app from outside, I guessed a sheet route is built over the leading routes before it, just like a screen. So `/cart` gives Home with the cart sheet on top.
- I guessed that a computed which reads a `storage` value runs again when that value is assigned on another screen. Checkout and Orders depend on this to refresh.
- I guessed that plain `async function` helpers declared in a component body, `{' '}`, and template-literal `href`s are allowed.
- I guessed that a plain `<button>` inside `modal.content` is fine, and that a handler can call `back()` after an `await`.
- I guessed that `@try` can sit inline inside a `<p>` next to other nodes.
- I guessed that a sheet's content scrolls and sizes itself, with no detents (fixed sheet heights such as half or full screen) or drag handle API.
- If a website visitor lands on `/checkout/address` or `/orders/42` directly, `back()` leaves the site. I accepted that.

## Website

1: Cart is a separate `/cart` page reached by the Cart link. Browser Back returns to the page before it, freshly loaded from the server. The Close button is not shown.

2: The same alert dialog appears. Delete removes the order and goes Back to Orders, which the server sends again, so it no longer lists the order.

3: Change loads `/checkout/address` as a full page. Picking an address writes it to the cookie and goes Back. The server renders checkout again with the new choice.

4: The form replaces the list on that same page. Saving adds the address, picks it and goes back to checkout.

5: Nothing. The website gets no push notification. The `/cart` path is just the cart page.

## Answers

A: Put `export const presentation = 'sheet'` in a page file, and every visit to that route on iPhone and Android opens as a sheet over the current screen. Closing it is a Back, and on the website it is a normal page.

B: The choice could have lived on each link (`<Link sheet>`), on the page that opens it (a sheet component holding the content inline), in app config (a route table), or on the page that is shown. I picked the page that is shown, because three pages and a push notification all reach the cart by path, and only the destination is present in every one of those cases. Putting it on links would repeat it at every link and leave the notification without a way to say it. Putting it on the opening page would mean the cart has no path, so a notification could not open it.

C: Picking writes the address id to `storage('deliverTo')` and then calls `back()`. On a phone, the checkout screen kept under the sheet sees the new value at once, and its computed runs again to show the label. On the website the value is a cookie, so the checkout page the browser gets back from the server already shows the choice.

D: The app builds `/` and then opens the cart as a sheet over it, so the user sees the cart with Home visible behind it. Back, or a swipe down, closes the sheet and leaves them on Home. Back again leaves the app.
