## Invented API

```ts
// Module: @markless/router (addition)
export type Presentation = 'screen' | 'sheet';
// Page-file convention: `export const presentation: Presentation = 'sheet'` next to the default export. On iPhone and Android, the route then opens as a bottom sheet over the screen that went to it, with that screen visible behind. On the website it is an ordinary page.
// A sheet is a screen on the stack. A swipe down, system Back or back() closes it, and the screen below shows exactly as it was left.
// Results go back to the opening screen through `storage`, which already updates every screen on the stack.
```

```tsx
						Delete
					</button>
```

```tsx
// file: pages/checkout/address.tsrx
import { computed, state, storage } from '@markless/core';
import { back, type Presentation } from '@markless/router';
import { addAddress, getAddresses } from '../../api.ts';

export const presentation: Presentation = 'sheet';

export default function AddressSheet() @{
	let addressId = storage('delivery-address', '');
	let adding = state(false);
	let label = state('');
	let line1 = state('');
	let city = state('');
	const addresses = computed(async ({ signal }) => await getAddresses(signal));
	<section aria-label="Deliver to">
		@if (adding) {
			<form
				onSubmit={async (event) => {
					event.preventDefault();
					const created = await addAddress({ label, line1, city });
					addressId = created.id;
					back();
				}}
			>
				<input placeholder="Label" value={label} onInput={(event) => (label = event.currentTarget.value)} />
				<input placeholder="Street" value={line1} onInput={(event) => (line1 = event.currentTarget.value)} />
				<input placeholder="City" value={city} onInput={(event) => (city = event.currentTarget.value)} />
				<button type="submit">Save</button>
				<button type="button" onClick={() => (adding = false)}>Back to list</button>
			</form>
		} @else {
			<div>
				@try {
					<ul>
						@for (const address of addresses; key address.id) {
							<li>
								<button onClick={() => { addressId = address.id; back(); }}>
									{address.label}: {address.line1}, {address.city}
								</button>
							</li>
						}
					</ul>
				} @pending {
					<p>Loading…</p>
				} @catch (error, reset) {
					<button onClick={reset}>{error.message}</button>
				}
				<button onClick={() => (adding = true)}>Add new address</button>
			</div>
		}
	</section>
}
```

## Guesses

- That a page file can export a `presentation` constant beside its default export, and that the router reads it. This is the invented part.
- That a sheet is a normal stack entry, so a swipe down, system Back and `back()` all close it, and the "build one screen per leading route" rule still applies (`/cart` builds `/` and then the cart sheet).
- That `api.ts` is at the app root, beside `pages/`.
- That a `computed` re-runs when a `storage` value it reads changes, the same way it does for `state`.
- That async handlers and assignments to `storage` or `state` from inside closures work.
- That `@try` may sit inline inside a `<p>`.
- That `navigate(..., { replace: true })` on the web after a delete does not leave the deleted order's page in history.
- That bumping an `orders-version` storage key is an acceptable way to refresh the Orders list that is kept on the phone's stack.

## Website

1: `/cart` is an ordinary full page reached by the Cart link from each page. The browser's Back returns to the page it came from.

2: The same alert dialog appears. Delete removes the order, then loads `/orders` in place of the order page.

3: "Change" loads `/checkout/address` as a full page. Picking an address saves it in the cookie and goes back, and the server renders checkout again with the choice.

4: The form is a second step on that same address page. Saving adds the address, picks it and returns to checkout.

5: There is no push on the website. Anyone opening `/cart` just gets the cart page.

## Answers

A: A page that exports `presentation = 'sheet'` opens as a bottom sheet over whatever screen linked to it on iPhone and Android (and as a normal page on the web). You close it with `back()` or a swipe down, and you hand results back through `storage`.

B: The decision could have lived on the link (`<Link sheet>`), on the page that opens it, in app config, or on the page being shown. I picked the page being shown, because three pages and a push notification all open the cart. Only the destination can make every entry, including a deep link with no "opener", agree that it is a sheet.

C: The address sheet assigns the chosen id to `storage('delivery-address')` and calls `back()`. On a phone that assignment updates the checkout screen kept underneath, and its `computed` reloads. On the website the storage value is a cookie, so when `back()` loads checkout again the server renders it with the new choice.

D: The app builds `/`, then `/cart` on top, so the user sees the cart sheet over Home. A swipe down or Back closes the sheet and leaves Home, and a further Back leaves the app.
