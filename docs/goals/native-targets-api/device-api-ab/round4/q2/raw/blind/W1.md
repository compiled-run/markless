## Invented API

```ts
// Module: @markless/router (additions)

// Convention: a `tabs.tsrx` file next to `pages/` default-exports a component whose one root element is <TabBar>. On iPhone and Android it is the app's root; on the website it renders as a <nav> of links above each page.
export declare function TabBar(props: { children?: unknown }): Element;

// One tab: its root route, label and icon. `badge` is shown when it is above 0. `onSelect` runs whenever this tab becomes the shown tab (a tap, navigate(), or opening the app at a path in it; on the website, loading a page in it).
export declare function Tab(props: { href: string; label: string; icon: string; badge?: number; onSelect?: () => void }): Element;

// Page-module export: `export const tabBar = false;` hides the tab bar while this page is on screen (phone and website).
export type TabBarOption = boolean;

// Rule: a path belongs to the tab whose href is its longest leading match ('/' catches everything else). Links push onto the current tab's own stack.
```

```tsx
// file: tabs.tsrx
import { storage } from '@markless/core';
import { TabBar, Tab } from '@markless/router';

export default function Tabs() @{
	let session = storage('session', '');
	let newOrders = storage('newOrders', '0');

	<TabBar>
		<Tab href="/" label="Shop" icon="house" />
		<Tab
			href="/orders"
			label="Orders"
			icon="bag"
			badge={Number(newOrders)}
			onSelect={() => (newOrders = '0')}
		/>
		@if (session !== '') {
			<Tab href="/account" label="Account" icon="person" />
		}
	</TabBar>
}
```

```tsx
// file: pages/checkout.tsrx
import { state, storage } from '@markless/core';
import { placeOrder } from '../api.ts';

export const tabBar = false;

export default function Checkout() @{
	let newOrders = storage('newOrders', '0');
	let placed = state<string | null>(null);

	<main>
		<h1>Checkout</h1>
		<button
			onClick={async () => {
				const order = await placeOrder();
				newOrders = String(Number(newOrders) + 1);
				placed = order.id;
			}}
		>
			Place order
		</button>
		@if (placed !== null) {
			<p>Order {placed} placed.</p>
		}
	</main>
}
```

// file: pages/orders.tsrx
import { computed } from '@markless/core';
import { getOrders } from '../api.ts';

export default function Orders() @{
	const orders = computed(async ({ signal }) => await getOrders(signal));

	<main>
		<h1>Orders</h1>
		@try {
			<ul>
				@for (const order of orders; key order.id) {
					<li>{order.placedAt}: {order.total}</li>
				}
			</ul>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
	</main>
}

Confidence: 3/5

## Guesses

- That a root-level `tabs.tsrx` file is acceptable even though the router has "no layout files". I treat it as app chrome, not a layout.
- That `export const tabBar = false;` in a page module is a supported way to set per-page options.
- That `@if` inside `<TabBar>` can add or remove a `<Tab>` at runtime. When the shown tab disappears (sign-out while on Account), the system switches to the first tab.
- That `storage` holds strings only, so the badge count is stored as a string and converted with `Number(...)`.
- That `onSelect` also fires when the app opens at a path inside the tab (for example, from a notification for `/orders/42`), so the badge clears however Orders is reached.
- That an async click handler is allowed, and that `back()` after `await` in the same handler works.
- That `/checkout` and `/signin` go on the Shop tab's stack (by the longest-match rule), and that `tabBar = false` hides the bar as it is pushed, the way iOS `hidesBottomBarWhenPushed` does.
- That text and `{}` can sit side by side inside `<li>`, and that `@if … @else` nests a `@try` as its one node.

## Website

1: A row of links (Shop, Orders, and Account when signed in) appears at the top of every page; there is no bottom bar and no per-tab history.

2: The Orders link shows the count from the cookie-backed storage. Placing an order raises it, and loading any page under `/orders` resets it to 0.

3: `/checkout` is a normal page with no link row.

4: The Account link appears only while the `session` cookie is set. Shop shows a "Sign in" link when signed out, and `/signin` sets the cookie and goes back.

## Screens

`/`: shows the tab bar (Shop tab).

`/orders`: shows the tab bar (Orders tab).

`/account`: shows the tab bar (Account tab, only while signed in).

`/checkout`: no tab bar.

`/signin`: shows the tab bar (pushed on the Shop stack).

## Answers

A: List your tabs once in `tabs.tsrx` as `<Tab>`s inside one `<TabBar>`; every route belongs to the tab whose `href` is its longest leading match and stacks inside that tab, and a page hides the bar with `export const tabBar = false`.

B: The list could have lived in static app config, inside each page's markup, in each tab's route file, or in a component library. I picked one `tabs.tsrx` component next to `pages/`. Static config cannot read `storage`, so it could not show a live badge or a conditional Account tab. Putting the tabs in each page would contradict "a page renders its screen" and would duplicate the list. Spreading them across route files scatters order and labels. One reactive component keeps the list in one place and lets it use ordinary `state`/`storage` and `@if`.

C: The number lives in the storage key `newOrders`. Checkout raises it by assigning to `storage`, and the Orders tab's `onSelect` sets it back to '0'. Because assigning to `storage` updates every screen at once, the `badge={Number(newOrders)}` expression in `tabs.tsrx` re-reads it and the badge updates without any polling.

D: Add one `<Tab href=… label=… icon=… />` line in `tabs.tsrx` and create its `pages/<name>.tsrx`.

Tools used: none
