## Invented API

```ts
// Module: @markless/router (additions)
// Convention: an optional `tabs.tsrx` next to `pages/` default-exports a component whose root is <TabBar>. It is the only place tabs are declared, and it renders around every page.
// The bar of tabs. On iPhone and Android it is the system tab bar, and each tab keeps its own stack of screens. On the website it renders as a <nav> of plain links above the page.
// `hiddenOn` lists route paths whose screens show no bar. Those screens are pushed over the bar and still belong to the current tab's stack.
export declare function TabBar(props: { hiddenOn?: string[]; children?: unknown }): Element;
// One tab. `href` is the tab's root route. `icon` is a system icon name. `badge` shows a small count when it is above 0.
// `onSelect` runs each time the tab becomes the selected one: when the person taps it, when the app opens on it, or when a website visitor loads a page in it.
export declare function Tab(props: { href: string; label: string; icon: string; badge?: number; onSelect?: () => void }): Element;
```

```tsrx
// file: tabs.tsrx
import { storage } from '@markless/core';
import { TabBar, Tab } from '@markless/router';

export default function Tabs() @{
	let session = storage('session', '');
	let newOrders = storage('newOrders', '0');

	<TabBar hiddenOn={['/checkout', '/signin']}>
		<Tab href="/" label="Shop" icon="house" />
		<Tab
			href="/orders"
			label="Orders"
			icon="bag"
			badge={Number(newOrders)}
			onSelect={() => (newOrders = '0')}
		/>
		@if (session !== '') {
			<Tab href="/account" label="Account" icon="person" />
		}
	</TabBar>
}
```

```tsrx
// file: pages/checkout.tsrx
import { state, storage } from '@markless/core';
import { placeOrder } from '../api.ts';

export default function Checkout() @{
	let newOrders = storage('newOrders', '0');
	let status = state<'idle' | 'placing' | 'placed' | 'failed'>('idle');

	<main>
		<h1>Checkout</h1>
		<button
			disabled={status === 'placing'}
			onClick={async () => {
				status = 'placing';
				try {
					await placeOrder();
					newOrders = String(Number(newOrders) + 1);
					status = 'placed';
				} catch {
					status = 'failed';
				}
			}}
		>
			Place order
		</button>
		@if (status === 'placed') {
			<p>Order placed.</p>
		} @else {
			@if (status === 'failed') {
				<p>Could not place the order. Try again.</p>
			}
		}
	</main>
}
```

```tsrx
// file: pages/orders.tsrx
import { computed, storage } from '@markless/core';
import { getOrders } from '../api.ts';

export default function Orders() @{
	let newOrders = storage('newOrders', '0');
	const orders = computed(async ({ signal }) => {
		newOrders;
		return await getOrders(signal);
	});

	<main>
		<h1>Orders</h1>
		@try {
			<ul>
				@for (const order of orders; key order.id) {
					<li>{order.placedAt}: {order.total}</li>
				}
			</ul>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
	</main>
}
```

```tsrx
import { state, storage } from '@markless/core';
import { back } from '@markless/router';
import { signIn } from '../api.ts';

export default function SignIn() @{
	let session = storage('session', '');
	let failed = state(false);

	<main>
		<h1>Sign in</h1>
		<button
			onClick={async () => {
				try {
					session = await signIn();
				} catch {
					failed = true;
					return;
				}
				back();
			}}
		>
			Sign in
		</button>
		@if (failed) {
			<p>Sign-in failed. Try again.</p>
		}
	</main>
}
```

## Guesses

- The fixed file name `tabs.tsrx` next to `pages/`, and that the router finds it the way it finds `pages/`.
- That `TabBar` accepts `@if` among its children, so a tab can come and go as state changes.
- If the Account tab disappears while it is selected, the bar switches to the first tab and the Account stack is thrown away.
- That `onSelect` also fires when the app opens on a tab from a link or a notification, and on website page loads. Without that, opening Orders from outside the app would not reset the badge.
- `/signin` is in `hiddenOn` too, because it is a step in a flow like checkout. The task did not require this.
- That handlers can be `async`, that `return` in a handler is allowed, and that `disabled` and `@else { @if … }` nesting work as written.
- I made the orders list read `newOrders` so it fetches again when an order is placed. This also means it fetches again when the badge resets to 0.
- `/orders/42`-style screens that are not in `hiddenOn` keep the bar and stay in their tab's stack.
- Pushing a link to another tab's root route (for example Shop linking to `/orders`) pushes onto the current stack. It does not switch tabs.

## Website

1. Tab bar: no system bar. `<TabBar>` renders a `<nav>` of links (Shop, Orders, plus Account when signed in) above each page.
2. Badge: the count shows as text next to "Orders" in that nav. It is kept in a cookie and goes back to 0 when the visitor loads `/orders`.
3. Checkout: `/checkout` loads with no nav, the same rule as on phones.
4. Account: the Account link appears in the nav only when the `session` cookie is not empty. The Shop page shows the "Sign in" link when it is empty, and `/signin` sets the cookie and goes back to Shop.

## Screens

- `/`: shows the tab bar.
- `/orders`: shows the tab bar.
- `/account`: shows the tab bar.
- `/checkout`: no tab bar. It is pushed over the bar on Shop's stack.
- `/signin`: no tab bar. It is pushed over the bar on Shop's stack.

## Answers

A: All tabs are declared in one `tabs.tsrx` next to `pages/`, as `<Tab>` children of a single `<TabBar>`, and every route belongs to the stack of the tab it was opened from unless it is listed in `hiddenOn`.

B: The list could have lived in app config, in each page's markup (not possible here, because there are no layout files and a page draws only its own screen), as an export from each tab's route file, or in a component library. I picked one `tabs.tsrx` component file. Being a component, it can read `storage` directly, which handles the reactive badge and the signed-in-only tab. App config cannot react to state, and route-file exports spread one bar across several files.

C: The number comes from the `storage('newOrders')` value. Checkout adds one to it after `placeOrder()` succeeds, and the Orders tab's `onSelect` sets it back to '0'. The `<Tab badge>` in `tabs.tsrx` reads the same storage key, so it updates as soon as any screen assigns to it.

D: Add one `<Tab href=… label=… icon=… />` line to `tabs.tsrx`, and add that tab's root page under `pages/`.
