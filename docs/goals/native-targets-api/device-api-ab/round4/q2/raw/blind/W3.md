## Invented API

```ts
// Module: @markless/router (additions)
// Convention: an app-root file `tabs.tsrx` (beside `pages/`, not inside it) default-exports a component whose one root is <TabBar>; that component is the app's tab bar on iPhone and Android.
// The bar shows only on a tab's root screen (the screen whose path equals a <Tab href>). Any screen pushed on top of a tab's stack covers the bar.
// On the website, <TabBar> renders a <nav> of links at the top of those same tab root pages.

// The app's tab bar. Its children are <Tab>s, in display order. A <Tab> may sit inside @if, so it exists only while the condition holds.
export declare function TabBar(props: { children?: unknown }): Element;

// One tab. `href` is the tab's root route and starts its own stack. `badge` is shown when it is above 0. `onSelect` runs each time this tab becomes the shown tab, whether by a tap, a Link or navigate() to its href, or opening the app at a path inside it.
export declare function Tab(props: { href: string; label: string; icon: string; badge?: number; onSelect?: () => void }): Element;
```

```tsrx
// file: tabs.tsrx
import { storage } from '@markless/core';
import { Tab, TabBar } from '@markless/router';

export default function Tabs() @{
	let session = storage('session', '');
	let newOrders = storage('newOrders', '0');

	<TabBar>
		<Tab href="/" label="Shop" icon="house" />
		<Tab
			href="/orders"
			label="Orders"
			icon="bag"
			badge={Number(newOrders)}
			onSelect={() => (newOrders = '0')}
		/>
		@if (session !== '') {
			<Tab href="/account" label="Account" icon="person" />
		}
	</TabBar>
}
```

```tsrx
// file: pages/checkout.tsrx
import { state, storage } from '@markless/core';
import { back } from '@markless/router';
import { placeOrder } from '../api.ts';

export default function Checkout() @{
	let newOrders = storage('newOrders', '0');
	let status = state<'idle' | 'placing' | 'failed'>('idle');

	<main>
		<h1>Checkout</h1>
		<button
			disabled={status === 'placing'}
			onClick={async () => {
				status = 'placing';
				try {
					await placeOrder();
				} catch {
					status = 'failed';
					return;
				}
				newOrders = String(Number(newOrders) + 1);
				back();
			}}
		>
			Place order
		</button>
		@if (status === 'failed') {
			<p>Could not place the order. Try again.</p>
		}
	</main>
}
```

```tsrx
export default function Orders() @{
	const orders = computed(async ({ signal }) => await getOrders(signal));

			</ul>

			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
	</main>
}
```

## Guesses

- I assumed an app-root `tabs.tsrx` is not a route, and that the framework renders it once next to the screen stacks, so its `storage` reads stay live.
- I assumed a `<Tab>` inside `@if` is added and removed with the condition. I also assumed that removing the tab you are on switches to the first tab.
- I assumed `onSelect` also fires when the app opens or deep-links into a tab, not only when someone taps it.
- I assumed `back()` works as the last statement after an `await` in an async click handler.
- I assumed `storage` holds only strings, so the badge count is stored as a string and converted with `Number(...)`.
- I assumed a `<Link>` or `navigate()` to a tab's href switches to that tab and does not push a copy of it onto the current stack.
- The Orders screen stays on its stack, so its list is not refetched after a new order. Its own `@catch` reset would refetch it. Auto-refresh was not asked for, so I left it out.
- I assumed `/signin` and `/checkout` are pushed onto the Shop stack, because the tab bar is hidden on any screen pushed on top.
- I assumed `@else` can follow `@if` directly, and that a bare `catch {}` is allowed in handlers.

## Website

1. Tab bar: Shop, Orders and Account appear as a plain `<nav>` of links at the top of `/`, `/orders` and `/account`. There is no bottom bar and no per-tab stacks.
2. Badge: the Orders link shows the count from the `newOrders` cookie. It resets to 0 when the `/orders` page loads.
3. `/checkout`: an ordinary page with no nav, reached by the Checkout link. Placing an order goes back to Shop, which loads fresh from the server.
4. Account: the Account link appears in the nav only while the `session` cookie is set. Signed-out visitors see the "Sign in" link on Shop, and visiting `/account` directly shows a Sign in link.

## Screens

- `/`: tab bar shown.
- `/orders`: tab bar shown.
- `/account`: tab bar shown (the tab exists only while signed in).
- `/checkout`: no tab bar, because it is pushed on top of Shop.
- `/signin`: no tab bar, because it is pushed on top of Shop or Account.

## Answers

A: The app's tabs are the `<Tab>`s inside the `<TabBar>` that `tabs.tsrx` at the app root default-exports, and the bar shows only on a tab's root screen, with anything pushed above it covering the bar.

B: The list could have lived in app config, in each page's markup, in each tab's route file as an export, or in a component library. I picked one `tabs.tsrx` component file, because a component can read `storage` and use `@if`. That gives a live badge and a sign-in-only tab with no new concepts, keeps the list in one place, and stops pages from having to agree with each other about the tabs.

C: The badge number comes from the storage value `newOrders`. Checkout adds one to it, and the Orders tab's `onSelect` sets it back to `'0'`. `tabs.tsrx` reads that storage value, and storage updates every screen at once, so the `badge` prop follows it.

D: Add a page file such as `pages/saved.tsrx`, then add one `<Tab href="/saved" label="Saved" icon="…" />` line in `tabs.tsrx`.
