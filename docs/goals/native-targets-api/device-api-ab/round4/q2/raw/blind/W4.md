## Invented API

```ts
// Module: @markless/router (new exports and two file conventions)

// Convention: `tabs.tsrx` next to `pages/` default-exports a component that renders one <TabBar>. It is built only for iPhone and Android, and the website build ignores it.
// The bar of tabs at the bottom of the app. Each child <Tab> owns its own stack of screens, and its `href` is the root screen of that stack.
export declare function TabBar(props: { children?: unknown }): Element;
// One tab. `badge` shows a number on the icon, and 0 or no value shows none. `onSelect` runs when the person taps the tab.
export declare function Tab(props: { href: string; label: string; icon: string; badge?: number; onSelect?: () => void }): Element;
// Convention: a page file that exports `tabBar = false` is shown without the bar, even when it is pushed inside a tab's stack.
export declare const tabBar: boolean; // (page-file export, not an import)
// Rule: if a <Tab> disappears while its stack is showing, the app switches to the first tab, and the removed stack is dropped.
```

```tsx
// file: tabs.tsrx
import { storage } from '@markless/core';
import { TabBar, Tab } from '@markless/router';

export default function Tabs() @{
	let session = storage('session', '');
	let newOrders = storage('newOrders', '0');

	<TabBar>
		<Tab href="/" label="Shop" icon="house" />
		<Tab
			href="/orders"
			label="Orders"
			icon="bag"
			badge={Number(newOrders)}
			onSelect={() => (newOrders = '0')}
		/>
		@if (session !== '') {
			<Tab href="/account" label="Account" icon="person" />
		}
	</TabBar>
}
```

// file: pages/checkout.tsrx
import { state, storage } from '@markless/core';
import { platform } from '@markless/device';
import WebNav from '../components/WebNav.tsrx';
import { placeOrder } from '../api.ts';

export const tabBar = false;

export default function Checkout() @{
	let newOrders = storage('newOrders', '0');
	let placedId = state('');
	let failed = state('');

	<main>
		@if (platform === 'web') {
			<WebNav />
		}
		<h1>Checkout</h1>
		<button
			onClick={async () => {
				try {
					const order = await placeOrder();
					newOrders = String(Number(newOrders) + 1);
					placedId = order.id;
					failed = '';
				} catch (error) {
					failed = (error as Error).message;
				}
			}}
		>
			Place order
		</button>
		@if (placedId !== '') {
			<p>Order {placedId} placed.</p>
		}
		@if (failed !== '') {
			<p>{failed}</p>
		}
	</main>
}

## Guesses

- `tabs.tsrx` is a file convention. It is read once per app, and its body reacts to `storage` like a screen does.
- A page opts out of the bar with `export const tabBar = false`. Without it, a screen pushed inside a tab's stack keeps the bar.
- `badge={0}` shows no badge.
- `onSelect` runs on every tap of the tab, including a tap on the tab that is already open.
- If the Account tab is removed while its stack is showing, the app switches to the first tab.
- Assigning to a `storage` value in a page body (Orders sets the count to `'0'`) is allowed and runs when the screen is built.
- Async handlers with `try`/`catch` are allowed.
- A `<>` fragment and an `@if` can sit together inside `<Link>` children.
- Opening the app from outside at `/orders/...` or `/account` builds the stack inside the matching tab.
- `/signin` is pushed onto the Shop stack.

## Website

1. Tab bar: no bar. Every page shows a top `WebNav` with links to Shop, Orders and Account.
2. Badge: the Orders link in the nav shows the count, which is kept in a cookie. Placing an order raises it, and loading `/orders` sets it back to 0.
3. Checkout: a normal page with the nav at the top. There is no tab bar to hide.
4. Account: the nav shows an Account link only when signed in, and a "Sign in" link otherwise. A signed-out visitor who goes straight to `/account` sees a "Sign in" link. After signing in, `/signin` replaces itself with `/`.

## Screens

- `/`: shows the tab bar (it is the root of the Shop tab).
- `/orders`: shows the tab bar (it is the root of the Orders tab).
- `/account`: shows the tab bar (it is the root of the Account tab, and only exists while signed in).
- `/checkout`: no tab bar (`tabBar = false`).
- `/signin`: no tab bar (`tabBar = false`).

## Answers

A: List the tabs once as `<Tab>`s inside a `<TabBar>` in `tabs.tsrx`. Each tab's `href` is the root of its own screen stack, and a page leaves the bar with `export const tabBar = false`.

B: The list could have lived in app config, in each page's markup, in each tab's route file, or in a component library. I picked one app-level component file (`tabs.tsrx`) for three reasons. The bar spans every screen, and there are no layout files, so no single page owns it. The badge and the Account tab must react to `storage`, which a static config file cannot do. And keeping all tabs in one place keeps their order and existence obvious.

C: The number comes from the storage value `newOrders`, a string. Checkout raises it after `placeOrder()` resolves. The Orders tab's `onSelect` sets it to `'0'`, and so does the Orders page body when that screen is built. Because `storage` updates every reader at once, `tabs.tsrx` re-renders the `badge` value as soon as it changes.

D: Add one `<Tab href=... label=... icon=... />` line in `tabs.tsrx`, add the page file under `pages/`, and add a link to it in `components/WebNav.tsrx` for the website.
