## Invented API

```ts
// Module: @markless/router (additions)

// File convention: `pages/_tabs.tsrx` default-exports the tab bar. It is not a route. On iPhone and Android it is built once,
// lives as long as the app, and is drawn under every screen. The website build never renders it.
// Bar container. Its children are <Tab>s, which may sit inside @if / @for.
export declare function Tabs(props: { children?: unknown }): Element;
// One tab. `href` is the root screen of the tab's own stack. Tapping an inactive tab shows that stack as it was left; tapping the active tab pops it to its root.
// `badge` is shown on the icon when it is set and not 0. `onSelect` runs every time the tab is tapped.
export declare function Tab(props: { href: string; icon: string; label: string; badge?: number; onSelect?: () => void }): Element;
// Page-file export: `export const tabBar = false;` hides the bar while that page's screen is on top.
export type TabBarExport = boolean;
// Routing rule: a link pushes onto the current tab's stack. Opening the app from outside picks the tab whose href is the longest
// leading part of the path ('/' if none), then builds that stack as usual.
```

```tsx
// file: pages/_tabs.tsrx
import { storage } from '@markless/core';
import { Tabs, Tab } from '@markless/router';

export default function AppTabs() @{
	let session = storage('session', '');
	let newOrders = storage('newOrders', '0');

	<Tabs>
		<Tab href="/" icon="house" label="Shop" />
		<Tab href="/orders" icon="bag" label="Orders" badge={Number(newOrders)} onSelect={() => (newOrders = '0')} />

			<Tab href="/account" icon="person" label="Account" />
		}
	</Tabs>
}
```

```tsx
// file: pages/checkout.tsrx
import { state, storage } from '@markless/core';
import { platform } from '@markless/device';
import { placeOrder } from '../api.ts';
import WebNav from '../components/WebNav.tsrx';

export const tabBar = false;

export default function Checkout() @{
	let newOrders = storage('newOrders', '0');
	let placedId = state<string | null>(null);
	let failure = state('');

	<main>
		@if (platform === 'web') {
			<WebNav />
		}
		<h1>Checkout</h1>
		<button
			onClick={async () => {
				try {
					const order = await placeOrder();
					newOrders = String(Number(newOrders) + 1);
					placedId = order.id;
					failure = '';
				} catch (error) {
					failure = (error as Error).message;
				}
			}}
		>
			Place order
		</button>
		@if (placedId !== null) {
			<p>Order {placedId} placed.</p>
		}
		@if (failure !== '') {
			<p>{failure}</p>
		}
	</main>
}
```

```tsx
// file: pages/orders.tsrx
import { computed, storage } from '@markless/core';
import { platform } from '@markless/device';
import { getOrders } from '../api.ts';
import WebNav from '../components/WebNav.tsrx';

export default function Orders() @{
	let newOrders = storage('newOrders', '0');
	newOrders = '0';
	const orders = computed(async ({ signal }) => {
		newOrders;
		return await getOrders(signal);
	});

	<main>
		@if (platform === 'web') {
			<WebNav />
		}
		<h1>Orders</h1>
		@try {
			<ul>
				@for (const order of orders; key order.id) {
					<li>{order.placedAt} {order.total}</li>
				}
			</ul>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
	</main>
}
```

## Guesses

- I guessed that `storage` (and other state) works inside `_tabs.tsrx`, and that the tab bar updates live when a `storage` value changes.
- I guessed that a `<Tab>` can sit inside `@if` within `<Tabs>`. I also guessed that removing the active tab (on sign-out) switches the app to the first tab.
- I guessed that a page-level `export const tabBar = false` is how a screen hides the bar.
- I guessed that `/checkout` and `/signin` are pushed onto the Shop tab's stack because they are linked from Shop.
- I guessed that an `async` handler may assign state after `await`, and that a `try/catch` inside a handler is allowed.
- I guessed that assigning `newOrders = '0'` in the Orders body clears the badge when the app opens `/orders` from outside. Tapping the tab is covered by `onSelect`.
- I guessed that `computed` re-running getAccount when `session` becomes `''` is harmless, because the `@if` hides the result.
- I guessed that `@else` can follow `@if` here, and that text plus `@if` is allowed as `Link` children.

## Website

1. Tab bar: there is no tab bar. Instead, each tab page renders a link row at the top (Shop, Orders, and Account when signed in), built by `WebNav`.
2. Badge: the Orders link shows the count, which is kept in a cookie. Placing an order adds one; loading `/orders` sets it back to 0.
3. Checkout: `/checkout` is a normal page with the link row and a "Place order" button.
4. Account: the Account link appears only when the session cookie is set. "Sign in" on Shop goes to `/signin`, which then returns to `/`. Visiting `/account` while signed out shows a "Sign in" link.

## Screens

- `/` (Shop): tab bar shown.
- `/orders`: tab bar shown.
- `/account`: tab bar shown, and this tab exists only when signed in.
- `/checkout`: no tab bar.
- `/signin`: tab bar shown, pushed on the Shop stack.

## Answers

A: List your tabs as `<Tab href icon label>` inside `<Tabs>` in `pages/_tabs.tsrx`. Each tab's `href` is the root of its own stack, and a page that should not show the bar exports `tabBar = false`.

B: The tab list could have lived in app config, in each tab's route file, or in every page's markup. I picked one special component file, `pages/_tabs.tsrx`, because the bar needs live values (the badge count and the sign-in check from `storage`) and normal `@if` syntax. Static config can't hold those, and "no layout files" rules out repeating the bar in every page.

C: The badge number is the `storage('newOrders')` string. Checkout adds one to it, and tapping the Orders tab (`onSelect`) or building the Orders screen sets it to '0'. Because every reader of a `storage` key updates at once, the tab bar and the Orders screen see each change straight away.

D: Add one `<Tab href="/x" icon="..." label="..."/>` line to `pages/_tabs.tsrx`, create `pages/x.tsrx`, and add a link to `components/WebNav.tsrx` for the website.
