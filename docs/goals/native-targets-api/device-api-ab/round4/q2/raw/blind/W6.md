## Invented API

```ts
// Module: @markless/router (additions)
// Convention: an optional `tabs.tsrx` beside `pages/` default-exports a component whose one root element is <TabBar>. It is built once per app run and kept for the whole run, so its state and storage reads stay live.
// On iPhone/Android it draws the system tab bar. Each <Tab> owns its own stack of screens, rooted at `href`.
// On the website it renders as a <nav> of links at the top of every page that shows the tab bar.
export declare function TabBar(props: { children?: unknown }): Element;
// One tab: its root route, label, system icon name, and an optional badge. An empty badge string shows no badge.
// onSelect runs whenever this tab becomes the one shown: a tap, a link, or opening the app at a path inside it.
export declare function Tab(props: { href: string; label: string; icon: string; badge?: string; onSelect?: () => void }): Element;
// Page-file convention: `export const tabBar = false;` in a page hides the tab bar while that screen is on top (and leaves the web nav out of that page).
export type PageTabBar = boolean;
```

```tsx
// file: tabs.tsrx
import { computed, storage } from '@markless/core';
import { Tab, TabBar } from '@markless/router';

export default function AppTabs() @{
	let session = storage('session', '');
	let newOrders = storage('newOrders', '0');
	const badge = computed(() => (newOrders === '0' ? '' : newOrders));

	<TabBar>
		<Tab href="/" label="Shop" icon="house" />
		<Tab href="/orders" label="Orders" icon="bag" badge={badge} onSelect={() => (newOrders = '0')} />
		@if (session !== '') {
			<Tab href="/account" label="Account" icon="person" />
		}
	</TabBar>
}
```

```tsx
// file: pages/checkout.tsrx
import { state, storage } from '@markless/core';
import { placeOrder } from '../api.ts';

export const tabBar = false;

export default function Checkout() @{
	let newOrders = storage('newOrders', '0');
	let placedId = state('');
	let failure = state('');
	let busy = state(false);

	<main>
		<h1>Checkout</h1>
		<button
			disabled={busy}
			onClick={async () => {
				busy = true;
				failure = '';
				try {
					const order = await placeOrder();
					newOrders = String(Number(newOrders) + 1);
					placedId = order.id;
				} catch (error) {
					failure = error instanceof Error ? error.message : 'Could not place order';
				}
				busy = false;
			}}
		>
			Place order
		</button>
		@if (placedId !== '') {
			<p>Order {placedId} placed.</p>
		}
		@if (failure !== '') {
			<p>{failure}</p>
		}
	</main>
}
```

```tsx
// file: pages/orders.tsrx
import { computed, state, storage } from '@markless/core';
import { getOrders } from '../api.ts';

export default function Orders() @{
	let newOrders = storage('newOrders', '0');
	newOrders = '0';
	let reload = state(0);
	const orders = computed(async ({ signal }) => {
		reload;
		return await getOrders(signal);
	});

	<main>
		<h1>Orders</h1>
		<button onClick={() => reload++}>Refresh</button>
		@try {
			<ul>
				@for (const order of orders; key order.id) {
					<li>{order.placedAt} — {order.total}</li>
				}
			</ul>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
	</main>
}
```

## Guesses

- I guessed that a root-level `tabs.tsrx` file is allowed alongside the "no layout files" rule because it holds only the tab list, not page content.
- I guessed that `storage` stays live inside the tabs component, so the badge and the Account tab update when other screens assign to it.
- I guessed that a tab whose `@if` turns false while it is shown drops its stack, and the bar switches to the first tab.
- Shop's stack holds `/checkout` and `/signin`. I guessed that a route not under another tab's `href` belongs to Shop (`/`).
- I guessed that `onSelect` also fires when the app opens at `/orders` from outside it. The Orders page body also resets the count, which covers the website and the first build of the screen.
- I guessed that `{badge}` passes a computed value through as a live prop.
- I guessed that `error` in a handler's `try/catch` is an ordinary JS error. That rule differs from `@catch` blocks.
- I guessed that the Account page's signed-out fallback is needed only on the website, or if someone reaches `/account` directly.

## Website

1. Tab bar: every page shows a top `<nav>` with links to Shop, Orders, and Account (Account only while signed in). There are no separate per-tab stacks.
2. Badge: the Orders link shows the count from the `newOrders` cookie. It goes up after Place order and resets when the Orders page loads.
3. Checkout: the page loads without the nav. The visitor uses the browser's Back to leave.
4. Account: the Account link appears only while the `session` cookie is set. Shop shows a "Sign in" link when it is not set. `/signin` sets the cookie and goes back. Opening `/account` while signed out shows a Sign in link.

## Screens

- `/`: tab bar shown (Shop tab).
- `/orders`: tab bar shown (Orders tab).
- `/account`: tab bar shown (Account tab, only while signed in).
- `/checkout`: no tab bar (`export const tabBar = false`).
- `/signin`: tab bar shown (pushed on the Shop stack).

## Answers

A: Put one `<TabBar>` of `<Tab href label icon>` elements in `tabs.tsrx` next to `pages/`. Each tab gets its own stack rooted at its `href`, and a page hides the bar with `export const tabBar = false`.

B: The list could have lived in app config, in each page's markup, in each tab's route file (for example `export const tab = {...}`), or in a component library. I picked one `tabs.tsrx` component. It is a single place that can read `storage` for the live badge and for the signed-in condition, which static config cannot do. Putting it in each page's markup would conflict with tabs owning stacks that outlive pages. A per-route export would scatter the order of the tabs and the condition on the Account tab across several files.

C: The number lives in `storage('newOrders')` on the device, a cookie on the web. Checkout increments it, and the Orders tab's `onSelect` and the Orders page reset it to `'0'`. The tabs component reads the same storage key, so every assignment updates its `badge` computed, and with it the tab, at once.

D: Add a `pages/<route>.tsrx` file and add one `<Tab href=... label=... icon=... />` line to `tabs.tsrx`.
