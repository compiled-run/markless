## Invented API

```ts
// Module: @markless/router (additions)

// Convention: an app may have one `tabs.tsrx` beside `pages/`. Its default export renders <TabBar> as its root. It is built once, kept for the app's whole life, and used only by the iPhone and Android builds.
// Each <Tab> roots its own screen stack at `href`. Links inside that stack push onto that tab's stack.
export declare function TabBar(props: { children?: unknown }): Element;
// One tab. `badge` shows a number on the tab and is hidden at 0. `onSelect` runs when the person taps the tab, including when the tab's stack already exists.
export declare function Tab(props: {
	href: string;
	label: string;
	icon: string;
	badge?: number;
	onSelect?: () => void;
}): Element;

// Convention: a page file may export `const tabBar = false`. The phone then shows that page's screen without the tab bar. The website build ignores it.
export declare const tabBar: boolean; // (per page file, optional, default true)
```

```tsrx
// file: tabs.tsrx
import { storage } from '@markless/core';
import { Tab, TabBar } from '@markless/router';

export default function Tabs() @{
	let session = storage('session', '');
	let newOrders = storage('newOrders', '0');

	<TabBar>
		<Tab href="/" label="Shop" icon="house" />
		<Tab
			href="/orders"
			label="Orders"
			icon="bag"
			badge={Number(newOrders)}
			onSelect={() => (newOrders = '0')}
		/>
		@if (session !== '') {
			<Tab href="/account" label="Account" icon="person" />
		}
	</TabBar>
}
```

```tsrx
// file: pages/orders.tsrx
import { computed, state, storage } from '@markless/core';
import { getOrders } from '../api.ts';

export default function Orders() @{
	let newOrders = storage('newOrders', '0');
	newOrders = '0';
	let reload = state(0);
	const orders = computed(async ({ signal }) => {
		reload;
		return await getOrders(signal);
	});

	<main>
		<h1>Orders</h1>
		<button onClick={() => reload++}>Refresh</button>
		@try {
			<ul>
				@for (const order of orders; key order.id) {
					<li>{order.placedAt} {order.total}</li>
				}
			</ul>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
	</main>
}
```

```tsrx
// file: pages/checkout.tsrx
import { state, storage } from '@markless/core';
import { placeOrder } from '../api.ts';

export const tabBar = false;

export default function Checkout() @{
	let newOrders = storage('newOrders', '0');
	let message = state('');

	<main>
		<h1>Checkout</h1>
		<button
			onClick={async () => {
				try {
					const order = await placeOrder();
					newOrders = String(Number(newOrders) + 1);
					message = `Order ${order.id} placed`;
				} catch {
					message = 'Could not place the order';
				}
			}}
		>
			Place order
		</button>
		<p>{message}</p>
	</main>
}
```

```tsrx
import { state, storage } from '@markless/core';
import { platform } from '@markless/device';
import { back, navigate } from '@markless/router';
import { signIn } from '../api.ts';

					session = await signIn();
				} catch {

				}

				} else {
					back();
				}
			}}
		>
			Sign in
		</button>

	</main>
}
```

```tsrx
// file: pages/account.tsrx
import { storage } from '@markless/core';
import { Link } from '@markless/router';
import { getAccount } from '../api.ts';

function Details({ session }: { session: string }) @{
	const account = computed(async ({ signal }) => await getAccount(session, signal));
	@try {
		<p>{account.name} {account.email}</p>
	} @pending {
		<p>Loading…</p>
	} @catch (error, reset) {
		<p>
			{error.message}
			<button onClick={reset}>Retry</button>
		</p>
	}
}

export default function Account() @{
	let session = storage('session', '');

	<main>
		<h1>Account</h1>
		@if (session !== '') {
			<Details session={session} />
		} @else {
			<Link href="/signin">Sign in</Link>
		}
	</main>
}
```

Confidence: 3/5

## Guesses

That `@if` can sit among `<TabBar>` children and add or remove a tab while the app runs.

That when the Account tab disappears while it is selected, the system switches to the first tab and throws away the Account stack.

That a screen pushed from a tab, like `/checkout` from Shop, goes onto that tab's stack, and that a page exporting `tabBar = false` hides the bar only while that screen is on top.

That a deep link to `/orders/...` selects the tab whose `href` is the longest leading match. Leading routes outside any tab land on the Shop stack.

That writing to a storage value in a component body (`newOrders = '0'`) is allowed and updates the tab badge right away.

That a component body may contain only an `@try` block, as in `Details`, and that text nodes and template strings inside `<Link>` children are fine.

That the website build ignores `tabs.tsrx` completely.

## Website

1 (tab bar): No tab bar. Shop shows a plain nav with links to Orders and, when signed in, Account.

2 (badge): The Orders link on Shop shows "(N)" when there are new orders. The count is kept in a cookie. Opening `/orders` resets it to 0.

3 (checkout): An ordinary page with no nav. There is nothing to hide.

4 (account): The Account link and the Sign in link on Shop follow the session cookie. Visiting `/account` while signed out shows a Sign in link. Signing in goes to `/`.

## Screens

`/`: shows the tab bar.

`/orders`: shows the tab bar.

`/account`: shows the tab bar, and the tab itself exists only while signed in.

`/checkout`: no tab bar.

`/signin`: no tab bar.

## Answers

A: Put one `<TabBar>` of `<Tab href label icon>` items in `tabs.tsrx` beside `pages/`. It runs once for the app's whole life, so anything that changes it (badges, a tab that comes and goes) must come from `storage`. Each tab's `href` is the root of its own screen stack.

B: The list could have lived in app config, in each page's markup, in each tab's route file as an export, or in a component library. I picked one `tabs.tsrx` file, because the tab bar outlives every screen and is shared across stacks, so it cannot belong to any one page (there are no layouts). It also has to be live markup rather than static config, since the badge and the Account tab change while the app runs.

C: The number comes from the storage value `newOrders`. Checkout increments it after `placeOrder()` resolves. The Orders tab's `onSelect` and the Orders page body set it back to '0'. `tabs.tsrx` reads that same storage key, and assigning to storage updates every reader at once, so the badge redraws by itself.

D: Add one `<Tab href="/x" label="..." icon="..." />` line to `tabs.tsrx` and create `pages/x.tsrx`. On the website, also add a link to Shop's web nav.
