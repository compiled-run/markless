## Invented API

```ts
// Module: @markless/router (additions)
// Convention: an optional `tabs.tsrx` beside `pages/` default-exports a component whose root is <Tabs>; that one file defines the app's tabs.

// The tab bar. Its children are <Tab>s, which may sit inside @if or @for. On iPhone and Android it is the system tab bar. On the website it is a <nav> of links.
export declare function Tabs(props: { children?: unknown }): Element;

// One tab. Its `href` is the root screen of the tab's own stack. Pushes from that screen stay in this tab.
export declare function Tab(props: {
	href: string;            // the route at the root of this tab's stack
	label: string;           // the text under the icon
	icon: string;            // a system icon name, such as 'house', 'bag' or 'person'
	badge?: number;          // a count shown on the tab; 0 or absent shows no badge
	onSelect?: () => void;   // runs each time the person taps this tab, even if it is already selected
}): Element;

// Visibility rule: the bar shows only on a screen whose path is exactly a tab's href. Every screen pushed above a tab root hides it.
```

```tsx
// file: tabs.tsrx
import { storage } from '@markless/core';
import { Tab, Tabs } from '@markless/router';

export default function AppTabs() @{
	let session = storage('session', '');
	let newOrders = storage('newOrders', '0');

	<Tabs>
		<Tab href="/" label="Shop" icon="house" />
		<Tab
			href="/orders"
			label="Orders"
			icon="bag"
			badge={Number(newOrders)}
			onSelect={() => (newOrders = '0')}
		/>
		@if (session !== '') {
			<Tab href="/account" label="Account" icon="person" />
		}
	</Tabs>
}
```

```tsx
// file: pages/checkout.tsrx
import { state, storage } from '@markless/core';
import { placeOrder } from '../api.ts';

export default function Checkout() @{
	let newOrders = storage('newOrders', '0');
	let status = state('');

	<main>
		<h1>Checkout</h1>
		<button
			onClick={async () => {
				status = 'Placing…';
				try {
					const order = await placeOrder();
					newOrders = String(Number(newOrders) + 1);
					status = `Order ${order.id} placed`;
				} catch (error) {
					status = (error as Error).message;
				}
			}}
		>
			Place order
		</button>
		<p>{status}</p>
	</main>
}
```

```tsx
// file: pages/orders.tsrx
import { computed, state, storage } from '@markless/core';
import { getOrders } from '../api.ts';

export default function Orders() @{
	let newOrders = storage('newOrders', '0');
	newOrders = '0';
	let reload = state(0);
	const orders = computed(async ({ signal }) => {
		reload;
		return await getOrders(signal);
	});

	<main>
		<h1>Orders</h1>
		<button onClick={() => reload++}>Refresh</button>
		@try {
			<ul>
				@for (const order of orders; key order.id) {
					<li>
						{order.placedAt} — {order.total}
					</li>
				}
			</ul>
		} @pending {
			<p>Loading…</p>
		} @catch (error, reset) {
			<p>
				{error.message}
				<button onClick={reset}>Retry</button>
			</p>
		}
	</main>
}
```

```tsx
import { computed, storage } from '@markless/core';
import { Link } from '@markless/router';

export default function Account() @{
	let session = storage('session', '');

				</div>

				<p>Loading…</p>
			} @catch (error, reset) {
				<p>
					{error.message}
					<button onClick={reset}>Retry</button>
				</p>
			}
		}
	</main>
}
```

```tsx
import { state, storage } from '@markless/core';
import { back } from '@markless/router';
import { signIn } from '../api.ts';

export default function SignIn() @{
	let session = storage('session', '');
	let failure = state('');

					return;
				}
				back();
			}}
		>
			Sign in
		</button>
		<p>{failure}</p>
	</main>
}
```

## Guesses

The `tabs.tsrx` file at the app root is a convention I invented. Because its body runs once and its props follow `storage`, the badge and the `@if` for the Account tab stay live.

`storage` holds only strings, so the badge count is stored as a numeric string and converted with `Number(...)`.

Tapping a tab does not rebuild its kept root screen, so the Orders body alone cannot reset the badge. `onSelect` covers taps on the tab, and the assignment in the Orders body covers deep links and first builds.

Opening the app from outside at a path inside a tab (for example `/orders/42`) selects the tab with the longest matching href and builds that tab's stack (`/orders`, then `/orders/42`). This replaces the single stack `/`, `/orders`, `/orders/42`.

When a tab disappears while it is selected (signing out on Account), the app switches to the first tab and discards that tab's stack.

`/signin` and `/checkout` are pushed onto the Shop tab's stack, so `back()` from `/signin` returns to Shop. Shop's Sign in link then disappears through `storage`.

I assumed `Number(newOrders)` in a prop is tracked as a read of `newOrders`.

I assumed `try`/`catch` and an early `return` before `back()` are allowed in a handler.

## Website

1. Tabs: `<Tabs>` renders a plain `<nav>` of links (Shop, Orders, Account) above the page, on the same screens where a phone shows the bar.
2. Badge: the count shows next to "Orders" in that nav. It is read from the `newOrders` cookie and resets when the person clicks Orders or loads `/orders`.
3. `/checkout`: the page has no nav, the same as on a phone.
4. Account: the Account link appears in the nav only when the `session` cookie is set. A signed-out visitor sees the "Sign in" link on Shop. After signing in, Back reloads Shop from the server, which has the cookie and so no longer shows the link.

## Screens

`/`: tab bar shown (root of the Shop tab).

`/orders`: tab bar shown (root of the Orders tab).

`/account`: tab bar shown (root of the Account tab) while signed in.

`/checkout`: no tab bar (pushed above Shop).

`/signin`: no tab bar (pushed above Shop).

## Answers

A: List the tabs once, as `<Tab>`s inside `<Tabs>` in `tabs.tsrx`; each tab's `href` is the root of its own stack, and the bar shows only on those root screens.

B: The list could have lived in static app config, in every page's markup, in a flag in each tab's route file, or in a component library. I picked a single `tabs.tsrx` component. Unlike static config, it can read `storage` to drive badges and hide tabs with `@if`. Unlike page markup, the stacks are app-wide, so the list cannot be repeated per page. It also keeps the tab list in one place rather than spread across route files.

C: The badge number comes from the storage value `newOrders`. Checkout increments it, and `onSelect` plus the Orders page body reset it to 0. The `<Tab badge={Number(newOrders)}>` prop reads that storage value, and because `storage` assignments update every screen at once, the tab bar sees each change.

D: Add a `<Tab href=… label=… icon=… />` line to `tabs.tsrx` and create its `pages/<name>.tsrx`.
