## Ranking

1. embed — a box whose inside is drawn by someone else, not by the page. That is exactly what these are, and HTML's `<embed>` already shows PDFs this way.
2. native — something the platform draws itself rather than Markless. That fits on iPhone and Android, and loosely fits the browser too.
3. view — a generic on-screen box. It is accurate but says nothing about why these two are different from other boxes.
4. element — just "an element", which is true of every tag, so it doesn't tell these two apart from anything.

B: Yes, two of them do.

`native` suggests the elements work only in the iPhone and Android apps, or that they skip the web build. In fact they work on the website too, where the browser draws them.

`element` collides with `element()` from `@markless/core`. A reader could take `element.camera` for an element handle or a way to bind to an existing DOM node, not a box with drawn content. It also suggests the namespace holds general-purpose HTML-like elements.

`view` borrows from React Native and iOS, where a "view" is a plain container that styles and lays out its children. These boxes have no children and their contents can't be styled.
