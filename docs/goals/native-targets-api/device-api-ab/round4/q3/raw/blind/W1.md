## Invented API

```ts
// Built-in intrinsic elements: the compiler maps each one to a native view per target
// (iPhone and Android system views, the browser's camera picture and PDF viewer on the web).
// They need no import, the same way <div> needs none.
declare global {
	namespace JSX {
		interface IntrinsicElements {
			camera: { el: import('@markless/device').Camera; class?: string };
			pdf: { src: string; page?: number; onLoad?: (info: { pages: number }) => void; class?: string };
		}
	}
}
```

```tsrx
// file: pages/media.tsrx
import { state } from '@markless/core';
import { camera, type Photo } from '@markless/device';
import { base, tabs } from '@markless/ui';

function CameraPanel() @{
	const cam = camera({ facing: 'back' });
	let photo = state<Photo | null>(null);

	<div class="panel">
		<camera el={cam} class="fill" />
		<div class="controls">
			<button
				disabled={!cam.ready}
				onClick={async () => {
					photo = await cam.takePhoto();
				}}
			>
				Take photo
			</button>
			<base.button pressed={cam.facing === 'front'} onChange={() => cam.flip()}>
				Flip camera
			</base.button>
		</div>
		@if (photo) {
			<img class="fill" src={photo.url} width={photo.width} height={photo.height} alt="Last photo taken" />
		}
	</div>
}

function DocumentPanel() @{
	let page = state(1);
	let pages = state(0);

	<div class="panel">
		<pdf src="/guide.pdf" page={page} onLoad={(info) => (pages = info.pages)} class="fill" />
		<div class="controls">
			<button disabled={page <= 1} onClick={() => page--}>Previous</button>
			<span>Page {page} of {pages}</span>
			<button disabled={pages === 0 || page >= pages} onClick={() => page++}>Next</button>
		</div>
	</div>
}

export default function MediaPage() @{
	let tab = state('camera');

	<main>
		<style>{`
			.panel { display: flex; flex-direction: column; gap: 0.5rem; width: 100%; }
			.fill { display: block; width: 100%; }
			.controls { display: flex; gap: 0.5rem; align-items: center; }
		`}</style>
		<tabs.root value={tab} onChange={(value) => (tab = value)}>
			<tabs.list>
				<tabs.trigger value="camera">Camera</tabs.trigger>
				<tabs.trigger value="document">Document</tabs.trigger>
			</tabs.list>
			<tabs.content value="camera">
				<CameraPanel />
			</tabs.content>
			<tabs.content value="document">
				<DocumentPanel />
			</tabs.content>
		</tabs.root>
	</main>
}
```

## Guesses

- **Tags and imports:** I guessed the tags are the lowercase built-in elements `<camera>` and `<pdf>`, and that they need no import. This is the biggest guess.
- **Flip button:** the sheet gives `base.button` no `onClick`. So I made it a toggle: `pressed` is true when the front camera is in use, and `onChange` calls `cam.flip()`.
- **Live fields:** I assumed `cam.ready` and `cam.facing` are live (the sheet says so) and can be read straight in the markup, the same way state is.
- **Async handler:** I assumed a click handler can be `async` and assign to state after `await`.
- **Shutter button:** it is a plain HTML `<button>` with `onClick`, because the brief only requires `base.button` for the flip button.
- **Styles:** I put an inline `<style>` block inside `<main>`. The guidance does not say how a page attaches a stylesheet, and the one-root-element rule rules out a sibling `<style>`.
- **Tab state:** I assumed `tabs.root` is controlled, so `value` comes from state and `onChange` writes back to it.
- **Hidden Camera tab:** the camera keeps running while the Document tab shows, because the panel stays in the page.
- **Page label before load:** it reads "Page 1 of 0" until `onLoad` reports the page count.

## Website

Camera preview: the visitor sees the browser's camera permission prompt, then the browser's live camera picture stretched to the panel's width.

PDF page: the visitor sees the browser's own PDF viewer showing one page of `/guide.pdf` at the panel's width.

## Answers

A: I assumed both are built-in elements that the Markless compiler knows about, so there is no import, the same as `<div>`. They have no parts or behaviour, so they don't belong in `@markless/ui`. The PDF element has nothing to do with device hardware, so I didn't expect it in `@markless/device`. Only the `camera()` function comes from `@markless/device`.

B: `<camera el={cam} />`. Two other spellings I'd find natural are `<camera-view el={cam} />` and `<CameraView el={cam} />` (imported from `@markless/device`).

C: A reader could take it for an HTML element. It is lowercase and written exactly like `<img>` or `<button>`, and only knowing that HTML has no `<camera>` tag gives it away. A reader would not take it for a `@markless/ui` part, because those are always written with a family prefix such as `tabs.trigger` or `base.button`.
