## Ranking

1. native — the device or browser draws it, not HTML or Markless. This matches what the elements are, including on the website, where the browser's own camera picture and PDF viewer are native to that platform.
2. system (my addition, ranked above `view` but not above `native`) — the system's own camera preview and PDF view, matching the sheet's wording "drawn by the device".
3. view — a display surface you can't interact with. This fits, but it is generic: every UI part is a view in some sense. It also echoes the iOS and Android term "View", which over-hints that these are mobile-only.
4. element — just "an element", which says nothing about what makes these two special. It also clashes with `element` imported from `@markless/core`.

B: Yes, two of them. `element` suggests these are ordinary DOM elements, or the handles that `element()` from `@markless/core` binds. Neither is true: they are opaque boxes whose contents the device draws and the author cannot style or reach into. `view` slightly suggests a styleable layout container like a mobile `View` that can hold children, but these boxes take no children. `native` might suggest to some readers that the element is iPhone or Android only, when it also works on the website. This is a minor risk, because the browser's viewer is native to the website.
