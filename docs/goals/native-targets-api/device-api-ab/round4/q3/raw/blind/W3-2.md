## Ranking
1. `system`: my own addition. It says the device or system draws the content, which the sheet states directly. It also reads naturally as `<system.camera>`.
2. `native`: the inside is drawn by the platform (iPhone, Android or the browser), not by Markless. This is the closest of the three, but it leans toward "mobile-native".
3. `view`: a display surface that shows something, like a camera view or PDF view. It fits, but it is vague, and nearly every component could be called a view.
4. `element`: a raw DOM or HTML element. It says nothing about what makes these two special.

B: Yes, two of them do.

`element` clashes with `element()` from `@markless/core`, which makes element handles. It suggests these are generic HTML elements or handle factories, and they are neither.

`native` can suggest the elements work only inside the iPhone and Android apps, or that they are raw native widgets with no website version. In fact the website draws them too, as the browser's camera picture and PDF viewer.

`view` suggests something read-only and passive, which fits. It could also be read as a layout or container primitive, like a React Native `View`, and these elements are not that either.
