## Ranking
1. `system`: a box the operating system or browser draws itself, so you can't style what's inside it. That is exactly what these are.
2. `native`: platform-drawn, not built from Markless parts. It's accurate, but it leans toward the phone apps, and on the website the box is drawn by the browser.
3. `view`: a generic display box. Almost anything on screen is a "view", so the name says little and hints at a layout part you could style or fill with your own content.
4. `element`: a plain host or HTML element. It also clashes with `element()` from `@markless/core`, which hands out DOM handles.

B: Yes, two of them. `element` suggests an ordinary HTML element you can style and query, and, through `element()` in `@markless/core`, an element handle. These are neither: they are opaque boxes drawn by the device. `view` suggests a container whose inside you lay out and style yourself, but the contents can't be styled. `native` is slightly off for the website, where nothing is "native" in the phone-app sense; still, the browser's camera picture and PDF viewer are close enough.

Tools used: none (apart from the one required Read of the task file)
