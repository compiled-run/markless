## Invented API

```ts
// Module: @markless/device
import type { Camera } from '@markless/device';

// Shows a camera made with camera(); the device draws the picture inside the box.
export declare function CameraView(props: { el: Camera; class?: string }): Element;

// Shows one page of a PDF; the device draws the page inside the box.
export declare function PdfView(props: {
	src: string;
	page?: number;
	onLoad?: (info: { pages: number }) => void;
	class?: string;
}): Element;
```

```tsrx
// file: pages/media.tsrx
import { state } from '@markless/core';
import { camera, CameraView, PdfView, type Photo } from '@markless/device';
import { base, tabs } from '@markless/ui';

function CameraPanel() @{
	const cam = camera({ facing: 'back' });
	let photo = state<Photo | null>(null);

	<div class="panel">
		<CameraView el={cam} class="fill" />
		<div class="controls">
			<button disabled={!cam.ready} onClick={async () => (photo = await cam.takePhoto())}>Take photo</button>
			<base.button pressed={cam.facing === 'front'} onChange={() => cam.flip()}>
				Flip camera
			</base.button>
		</div>
		@if (photo) {
			<img class="fill" src={photo.url} alt="Last photo" />
		}
	</div>
}

function DocumentPanel() @{
	let page = state(1);
	let pages = state(0);

	<div class="panel">
		<PdfView src="/guide.pdf" page={page} onLoad={(info) => (pages = info.pages)} class="fill" />
		<div class="controls">
			<button disabled={page <= 1} onClick={() => page--}>Previous</button>
			<span>Page {page} of {pages}</span>
			<button disabled={pages === 0 || page >= pages} onClick={() => page++}>Next</button>
		</div>
	</div>
}

export default function Media() @{
	let tab = state('camera');

	<main>
		<style>{`
			.panel { display: flex; flex-direction: column; gap: 0.5rem; }
			.fill { display: block; width: 100%; }
			.controls { display: flex; gap: 0.5rem; align-items: center; }
		`}</style>
		<tabs.root value={tab} onChange={(value) => (tab = value)}>
			<tabs.list>
				<tabs.trigger value="camera">Camera</tabs.trigger>
				<tabs.trigger value="document">Document</tabs.trigger>
			</tabs.list>
			<tabs.content value="camera">
				<CameraPanel />
			</tabs.content>
			<tabs.content value="document">
				<DocumentPanel />
			</tabs.content>
		</tabs.root>
	</main>
}
```

Confidence: 2/5

## Guesses

- The element names `CameraView` and `PdfView`. I also guessed they are exported from `@markless/device` and used as capitalized components.
- Whether `<style>` inside a page is written like this. I passed the CSS as a template-literal child.
- I made the flip button a toggle (`pressed` set to whether the front camera is in use). I did this because a plain `base.button` has no click or `onChange` prop on the sheet, so a toggle is the only way to react to a press.
- That the `pressed` prop follows `cam.facing` as it changes. The sheet says the camera's fields are live.
- That `Photo` can be imported as a type, and that `@if (photo)` narrows it so `photo.url` is safe to read.
- That the shutter can be a plain HTML `<button>` with an async `onClick`.
- That a handler which only assigns state can be written as an arrow function returning that assignment.
- That an "Page {page} of {pages}" label showing "of 0" before the PDF loads is acceptable.
- That the camera runs while its tab is hidden. Hidden panels stay in the page, so the camera may keep running until the panel is shown.

## Website

- Camera preview: a box the full width of the panel, showing the browser's live camera picture after the visitor allows camera access in the browser's prompt.
- PDF page: a box the full width of the panel, showing page N of `/guide.pdf` in the browser's own PDF viewer.

## Answers

A: From `@markless/device`. That package already owns `camera()` and the `Camera` and `Photo` types, and both elements show content drawn by the device itself. They are not parts with behaviour, so they don't belong in `@markless/ui` families.

B: `<CameraView el={cam} />`. Two other spellings I'd find natural: `<CameraPreview el={cam} />` and `<device.camera el={cam} />`.

C: No to both. A capitalized tag like `CameraView` reads as a component, not a lowercase HTML tag, so it can't be mistaken for an HTML element. It also isn't written as `family.part` (like `tabs.trigger`), so it doesn't look like a @markless/ui part. The import from `@markless/device` confirms where it comes from. Had I picked `<device.camera>`, it could have been taken for a @markless/ui family part.
