## Ranking

1. system — drawn by the system (the phone's OS, or the browser on the website), so you cannot style what is inside it. This is the name I would add, and I rank it first.
2. native — rendered by the platform itself rather than by Markless or by HTML you write. This is close to the real meaning.
3. view — a box that shows something, such as a viewer or a display surface. It says nothing about who draws the contents.
4. element — a raw element or element handle. It fits almost anything and tells you nothing about these two.

B: Yes, all three suggest something these elements are not.

`element`: this is the most misleading. It collides with `element()` from `@markless/core`, so `element.camera` reads like an element handle or a bound reference rather than a thing you render. Every `@markless/ui` part is already an element, so the name also tells you nothing.

`native`: this could suggest the element works only in the iPhone and Android apps and not on the website. It could also suggest a plain HTML element, as in "native `<video>`". In fact it works on the website too, through the browser's camera picture and PDF viewer.

`view`: this suggests a general layout container, like React Native's `View`, that could hold children or be styled inside. These elements are fixed device-drawn boxes with no parts and no children.

Tools used: none
