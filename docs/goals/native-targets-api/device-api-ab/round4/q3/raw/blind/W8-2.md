## Ranking

1. device: drawn by the device, not by the page. This matches the sheet's own wording ("drawn by the device"), and these elements sit next to `@markless/device`'s `camera()`.
2. native: drawn by the platform's own UI, such as the iOS or Android view or the browser's built-in viewer. This is close to the truth.
3. view: a box that displays something, like `CameraView`. It says what the element does but nothing about who draws it.
4. element: just "an element". It says nothing about what makes these two special.

B: Two of them do. `element` collides with `element()` from `@markless/core`, so `element.camera` reads like an element handle or a helper for binding one, not a box drawn by the device. It could also read as "generic HTML elements". `native` can read as "native HTML element", as in the browser's built-in `<video>`. It can also read as "iPhone and Android only", which hides the fact that these elements work on the website too. `view` is a smaller risk: it can suggest a page or route view, or a layout container you can style inside, and you cannot style inside these.

Tools used: none
