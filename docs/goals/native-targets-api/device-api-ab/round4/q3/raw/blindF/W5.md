## Invented API
```ts
// Module: @markless/device
// One element shows any device object (a camera from camera(), a PDF from pdf(), and others later).
// The box is sized and placed with `class`; what is inside it is drawn by the device.
export declare function View(props: { el: Camera | Pdf; class?: string }): Element;
```

```tsx
// file: pages/media.tsrx
import { state } from '@markless/core';
import { camera, pdf, View } from '@markless/device';
import type { Photo } from '@markless/device';
import { base, tabs } from '@markless/ui';

function CameraPanel() @{
	const cam = camera({ facing: 'back' });
	let last = state<Photo | null>(null);

	<div class="panel">
		<View el={cam} class="fill" />
		<div class="controls">
			<button disabled={cam.access === 'denied'} onClick={async () => (last = await cam.takePhoto())}>
				Take photo
			</button>
			<base.button pressed={cam.facing === 'front'} onChange={() => cam.flip()}>
				Flip camera
			</base.button>
		</div>
		@if (last) {
			<img class="fill" src={last.url} width={last.width} height={last.height} alt="Last photo taken" />
		}
	</div>
}

function DocumentPanel() @{
	const doc = pdf('/guide.pdf');

	<div class="panel">
		<View el={doc} class="fill" />
		<div class="controls">
			<button disabled={doc.page <= 1} onClick={() => (doc.page = doc.page - 1)}>Previous</button>
			<span>
				@if (doc.pages > 0) {
					<>Page {doc.page} of {doc.pages}</>
				} @else {
					<>Loading…</>
				}
			</span>
			<button disabled={doc.pages === 0 || doc.page >= doc.pages} onClick={() => (doc.page = doc.page + 1)}>
				Next
			</button>
		</div>
	</div>
}

export default function Media() @{
	let tab = state('camera');

	<main>
		<style>{`
			.panel { display: flex; flex-direction: column; gap: 0.5rem; width: 100%; }
			.fill { display: block; width: 100%; }
			.controls { display: flex; gap: 0.5rem; align-items: center; }
			[ui-selected] { font-weight: bold; }
		`}</style>
		<tabs.root value={tab} onChange={(value) => (tab = value)}>
			<tabs.list>
				<tabs.trigger value="camera">Camera</tabs.trigger>
				<tabs.trigger value="document">Document</tabs.trigger>
			</tabs.list>
			<tabs.content value="camera">
				<CameraPanel />
			</tabs.content>
			<tabs.content value="document">
				<DocumentPanel />
			</tabs.content>
		</tabs.root>
	</main>
}
```

Confidence: 2/5

## Guesses
- The tag name `View`, and that it is a named export of `@markless/device`. The sheet does not publish either.
- That `tabs.root` is controlled and does not track its own value, so I keep `value` in state and update it from `onChange`.
- `base.button` has no `onClick`. I made the flip button a toggle (`pressed` = front camera) and call `cam.flip()` from `onChange`. The shutter, Previous and Next buttons are plain `<button>` elements with native `onClick`.
- That an async click handler which assigns state after `await` is allowed, and that reading device-object fields (`cam.facing`, `doc.page`, `doc.pages`) in markup updates live like state.
- That writing to `doc.page` is the right way to change the page, and that the object clamps out-of-range values or ignores them.
- That an `@if` block may hold a fragment with text and expressions, and that `@if (last)` narrows the type so `last.url` is safe.
- That a `<style>` block with plain global classes works in a page. Any stylesheet would also do.
- That the camera keeps running while its tab is hidden, because the panel stays in the page. The guards on `ready` and `access` are minimal.

## Website
- Camera preview: the browser asks for camera permission, then the visitor sees the browser's own live camera picture (a video-like feed) stretched to the panel width.
- PDF page: the browser's built-in PDF viewer (as in an embedded frame, possibly with its own toolbar), open at the current page of `/guide.pdf` and filling the panel width.

## Answers
A: It is a named export of `@markless/device`. That package owns `camera()`, `pdf()` and the `Camera`/`Pdf` types, and this element is how those objects are shown, so it fits beside them. It is not a `@markless/ui` part, because the sheet says it has no parts and no behaviour of its own.
B: `<View el={cam} />`. Other spellings I would also find natural: `<Device el={cam} />` and `<device.view el={cam} />`.
