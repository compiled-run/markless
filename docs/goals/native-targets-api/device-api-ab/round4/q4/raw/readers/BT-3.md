1: `button` and `img` are plain HTML. `drawer.root`, `drawer.trigger`, `drawer.backdrop`, `drawer.content`, `drawer.title` and `drawer.close` come from `@markless/ui` (imported as `drawer`). `base.button` also comes from `@markless/ui` (imported as `base`). `<sheet>` is imported from nowhere and is not an HTML element, so it must be built into Markless; I read it as a native modal sheet. `<camera>` is the ambiguous one. It is lowercase, and HTML has no `<camera>` element, but `camera` is imported from `@markless/device` as a function (`camera()` returns `cam`, which goes into `el={cam}`). So it is either a Markless built-in tag for showing a native view, or a tag tied to the `@markless/device` import. I lean towards a Markless built-in fed by the device handle, but that is a guess.

2: I'm guessing on both. The camera tag probably still exists on the website, since the button reads `cam.ready` and nothing on the page is gated by platform. I'd expect a browser camera preview (a `<video>` fed by the browser's camera access), with `cam.ready` staying false if permission is denied or there's no camera. The sheet probably exists too, with a web fallback: something like a `<dialog>` or a bottom panel holding the same heading and filter buttons. The code gives no sign that either is left out of the web build.

3: The camera preview is mostly drawn by the system (the native or browser camera view). The author only sizes and places it through `class="preview"`. The Filters sheet is drawn by the system: it has no class or styling parts, so it would get the platform's standard sheet look. The author supplies only its contents. The Comments drawer is styled by the author: it is built from `@markless/ui` parts with a `class` on `drawer.content`, which looks like an unstyled component the author styles. That last point is an inference from the way it is put together.

4: The sheet is a single built-in tag whose open state belongs to the page. The page opens it with `choosing = true`, and `onChange` reports when it closes, for example when the user swipes it away. It has no trigger, backdrop, title or close parts, and it looks like a native system sheet. The drawer is a component made of parts that manages its own open state. It brings its own trigger button, backdrop, labelled title and close button, the author styles it, and it presumably looks and behaves the same in the apps and on the website.

My reading is that it means "running as the iPhone app", so the note "Photos also save to your library" appears only in the iPhone app. Saving to the photo library is something a native app can do and a web page cannot, which supports that reading. But `platform.ios` could just as easily mean "the operating system is iOS", which would include Safari on an iPhone. The code does not settle it, so I am guessing.
