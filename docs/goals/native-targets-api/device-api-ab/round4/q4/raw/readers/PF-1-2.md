## Ranking
1. IA: It is the easiest to read on all three points. Each platform's tag is named (`ios.`, `android.`, `web.`), the `@else` branch says outright that the website gets `web.camera` and `web.sheet`, and the per-OS tags make it clear the OS draws them. Clarity is the only thing it wins on, though. The sheet code is written out three times.
2. SY: `system.` says the operating system or browser draws it, and that reads correctly on every target, including the website, where the browser is the system. The website's version is still implied rather than shown.
3. NT: `native.` clearly says the page doesn't draw it. On the website, though, "native" is confusing: the word suggests an app-only control, so I'd wonder whether the website gets anything at all.
4. PF: `platform.` shares a name with the `platform.ios` condition. That makes `platform.camera` read as either "the platform's camera view" or a question like "does this platform have a camera?". It gives no hint about the website.
5. BC: `base.camera` and `base.sheet` sit in the same namespace as `base.button`, which the page's author styles. That suggests the page's own components, which is the opposite of what is meant.
6. BT: The bare `<camera>` and `<sheet>` have no import, so they look like HTML or custom elements. There is no sign of where they come from, who draws them, or what the website gets.

B: `system` is the best name. It names who draws the thing, and that stays true on every target: iOS, Android, or the browser on the website. `native` suggests "app only", so it reads badly in the website build. `platform` collides with the `platform.ios` and `platform.android` checks. `base` collides with the author-styled `base.button`. The per-platform names are explicit, but they force branches and copies. A bare tag says nothing.

C: It can be confused. `platform.ios` is a yes/no fact about where the code is running, while `platform.sheet` and `platform.camera` are tags, so one object mixes facts with components. A reader can misread `platform.camera` as a capability check ("does this platform have a camera?") or take `platform.ios` for a component. The two are only told apart by whether they appear as a tag or inside an `@if`.

D: I'd rather write SY. It is one tag, so the heading lives in one place, and the name says the system draws it without making the website look unsupported. IA is the clearest to read but the worst to write, because the sheet body is copied three times and changing the heading means editing three places.
