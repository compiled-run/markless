1: The tag that shows the camera, `<platform.camera>`, comes from `@markless/device`. It is reached through the `platform` export, and `cam` from `camera()` (same package) is bound to it with `el={cam}`. The Filters sheet tag, `<platform.sheet>`, also comes from `@markless/device` through `platform`. The `drawer.*` tags (`root`, `trigger`, `backdrop`, `content`, `title`, `close`) come from `@markless/ui`. `base.button` also comes from `@markless/ui`, and judging by `pressed` and `onChange` it looks like a toggle button. Plain `button` and `img` are HTML elements, as are `main`, `p`, `h2`, `ul` and `li`. Markless itself only provides the `@if` and `@for` blocks and `state()` from `@markless/core`. None of the tags come from Markless itself.

3: The system decides most of the camera preview's look: it draws the live feed, and the author only places and sizes the box via `class="preview"`. The system also decides how the Filters sheet looks and moves (the native iOS/Android sheet chrome: grabber, corners, animation, swipe to dismiss). The author supplies only the content inside it. The page's author decides how the Comments drawer looks. `@markless/ui` parts seem to be behaviour-only (headless), and the author styles them, for example via `class="comments"` on `drawer.content`.

4: The Filters sheet is a single native, platform-specific tag. The page controls it with its own state (`open={choosing}` plus `onChange`), opens it from an ordinary button, and closes it in code (`choosing = false`). The system draws it, so it looks native on each platform. The Comments drawer is built from composed parts of `@markless/ui` (root, trigger, backdrop, content, title, close). It manages its own open state through `drawer.trigger` and `drawer.close`, has an explicit title part that is probably used as its accessible name, and is drawn in the page, so it looks the same on every target and the author styles it.

6: There are three uses. `platform.camera` means "the native camera view on this target" and is a component. `platform.sheet` means "the native sheet on this target" and is also a component. `platform.ios` is a boolean that is true when running on iOS. So `platform` serves both as a namespace for native-backed components and as the place you ask "which platform am I on?". My guess is that only someone in the iPhone app sees the note. Saving to the photo library is an app capability that a website can't do silently, which suggests `platform.ios` means "the iOS app build". But if `platform.ios` means the device's operating system, a Safari-on-iPhone visitor would see it too, and the note would then be false for them.
