1: `<system.camera>` (the tag that shows the camera) comes from the `@markless/ui` package, through its `system` namespace. It is fed by `camera()` from `@markless/device`, which supplies `ready`, `facing`, `flip()` and `takePhoto()`. `<system.sheet>` (the Filters sheet) is also from `@markless/ui` under `system`. The `drawer.*` tags (`root`, `trigger`, `backdrop`, `content`, `title`, `close`) are from `@markless/ui`, the `drawer` component family. `<base.button>` is from `@markless/ui` (`base` namespace); since it takes `pressed` and `onChange`, I am guessing it is a toggle button. `<button>`, `<img>`, `<main>`, `<p>`, `<h2>`, `<ul>` and `<li>` are plain HTML. The only things that come from Markless itself are the `@if` / `@for` blocks and `state`, which is from `@markless/core`. None of the tags do.

2: Nothing in the code limits either tag to a platform: neither sits inside an `@if (platform...)`. So I take both to exist in the website build, though that is an inference, not something the code states. My guess for what a visitor gets: for `system.camera`, a browser camera preview (the browser asks for camera permission). `cam.ready` stays false until access is granted or if there is no camera, so "Take photo" stays disabled. For `system.sheet`, a web stand-in for the native bottom sheet, probably an HTML dialog or bottom-sheet panel that closes on dismiss. Exactly what the web fallback looks like is a guess.

3: The camera preview: the system draws the camera feed, and the author only sizes or places it with `class="preview"`. The Filters sheet: the system. The `system.` prefix suggests the phone's own native sheet, and the author only supplies what goes inside it. The Comments drawer: the page's author. It is a headless component built from parts, and it is styled through classes such as `class="comments"`.

4: The Filters sheet is one system-provided element. It is controlled by the page: `open={choosing}` plus `onChange`, with the page's own button opening it and the filter buttons closing it. It probably renders as the native iOS/Android sheet, so it looks and behaves like the platform's. The Comments drawer is a Markless UI component assembled from parts. It manages its own open state through `drawer.trigger` and `drawer.close`, the author renders and styles its backdrop, content and title, and it has an explicit title part. So it looks the same on every platform.

5: One place: the `<h2>Choose a filter</h2>` text on line 32. There is no separate title prop to update. Contrast the drawer, whose heading lives in `drawer.title`. A guess: the native sheet may pick up that `h2` as its title, but either way it is still one edit.

6: `platform` is imported from `@markless/device` and used once, in `@if (platform.ios)`, to show the "Photos also save to your library" note only on iOS. My reading is that it means "running as the iPhone app build", since the note is about saving to the photo library, which the website cannot do. So only someone in the iPhone app sees it, not a Safari visitor on an iPhone. This is a guess: `platform.ios` could just as well mean "the device runs iOS", and then both would see it.

7: For question 2 I am about 2 out of 5 sure, and for question 6 about 2 out of 5. To be sure I would need the documentation for `system.camera` and `system.sheet` on the website build (whether they render a fallback, nothing, or fail to build). I would also need the definition of `platform.ios`: whether it means the native app target or the device's operating system, and whether a separate flag such as `platform.web` exists.
