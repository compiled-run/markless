## Ranking
1. SY: "system" names whoever draws the UI, not one kind of device. "System sheet" and "system camera" fit the phone's operating system and, with a small stretch, the browser on the website. Its weakness is that "system" can be heard as "design system".
2. NT: "native" is the usual word for "the platform's own control", so the meaning comes through. But in cross-platform work it usually means "the phone app, as opposed to the web version", which pulls the reader away from the website.
3. OS: "os" says "operating system" clearly, but a browser isn't usually called an OS, so it reads as phone-only. As a short, lowercase namespace beside `base` and `drawer`, it could also pass for a library name.

B: SY yes, mostly: a browser can count as "the system", and nothing in the name rules the web out. NT can't tell, leaning no: "native" often means "not the web", though "native HTML element" is also a common phrase. OS can't tell, leaning no: it points to iOS or Android, and a website visitor's OS doesn't draw page elements.

C: SY somewhat: "design system" and "UI system" are common phrases, and `system` sits beside `base` in `@markless/ui`. NT no: "native" describes where something comes from, not a styled library, though it echoes "React Native". OS somewhat: it is a short, opaque namespace that could be a brand name. It reads mainly as "operating system".

D: Both, but mainly the phone's own UI. In a codebase that builds iPhone, Android and web from one source, "native" first suggests the app builds. Only after a second thought does it also cover the browser's built-in elements, like `<dialog>` or the built-in PDF viewer, on the website.
