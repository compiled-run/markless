## Ranking
1. SY (`system`): "System" covers both the operating system and the browser, so it reads naturally as "whatever the host platform draws" on all three targets. It can be confused with "design system".
2. NT (`native`): It says clearly "not drawn by the page", but it leans hard toward the phone's own controls, as in "native app". That makes it unclear what happens on the website.
3. OS (`os`): It clearly means the operating system's UI on phones. On the website the browser is not the OS, so `os.pdf` or `os.sheet` reads as phone-only, or as something the website cannot do.

B:
- SY: yes. "System" stretches to cover the browser.
- NT: can't tell. A browser's own controls count as "native" too, but many readers take "native" to mean "not the web".
- OS: no, or at best can't tell. It implies the phone's operating system, so I would expect it to be missing or to fall back on the website.

C:
- SY: somewhat. "Design system" is a common term, though `camera` and `pdf` steer away from it.
- NT: no. Nobody would name a component library "native", except maybe through a React Native association.
- OS: no.

D: Both, but mainly the phone's own UI. On the website I would only read it as the browser's built-in element after thinking it through. Without that step, "native" sounds like "the iPhone or Android control", so it is less clear than `system` for the website build.

Tools used: none
