## Ranking
1. NT — "native" is the most common word for "the platform draws this control, not your code" (native controls, native UI). It sets these apart from `drawer`, which the author builds. It is a little biased toward the phone apps, but web developers also say "native `<dialog>`" and "native PDF viewer", so the meaning still holds on the website.
2. SY — "system" fits the idea (system sheet, system camera UI) and covers the browser as naturally as the phones. But next to `base` and `drawer` inside `@markless/ui`, it is easily confused with "design system", so the meaning is less immediate.
3. OS — it clearly means the phone's own UI on iOS and Android. But a browser is not an operating system, so on the website it reads oddly, and it implies the element might be missing there or fall back to something else. It is also terse and can look like a variable name rather than a namespace.

B: SY — can't tell, leaning yes (a browser plausibly counts as "the system"); NT — can't tell (it hints at the phone apps, but "native HTML element" is a familiar phrase on the web); OS — leaning no (it suggests the phone's operating system, which a website visitor doesn't have, so I'd guess it is missing or a fallback).

C: SY — yes (the "design system" reading is real, especially since it is imported from a UI package beside other components); NT — no (it says where a control comes from, not which library it belongs to); OS — no.

D: Both, leaning toward the phone's own UI. Because the page builds as iPhone and Android apps, "native" first calls up the phone's controls. Since the same page also builds as a website, I'd then read it as the browser's built-in element there. The name doesn't settle the website case; the cross-platform setup does.
