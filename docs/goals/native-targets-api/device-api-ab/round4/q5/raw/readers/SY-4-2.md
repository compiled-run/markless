## Ranking
1. SY (system): it reads as "the system draws this", and that works on any host. On the website the browser counts as the system, so the name holds in all three builds without suggesting phone-only.
2. NT (native): it strongly says "the platform draws it, not the page". But in cross-platform work "native" usually means the iOS/Android app as opposed to web, so a reader may assume it doesn't apply on the website.
3. OS (os): it points at the operating system. On the website the PDF viewer, dialog and camera preview come from the browser, not the OS, so the name only fits there loosely. It is also short and easy to misread as an abbreviation for something else.

B: SY: yes, mostly. The browser is a believable "system" and nothing hints at phone-only. NT: can't tell. "Native" pulls toward the apps, and only the missing platform guard suggests it renders on the web. OS: can't tell, leaning no. An operating-system control sounds like something a web page doesn't get, although a browser does draw some things through the OS (camera permission, file pickers).

C: SY: somewhat. "System" is common in design-system naming, and importing it from @markless/ui next to base and drawer makes that reading possible. NT: somewhat. "Native" calls to mind React Native or other "native component" libraries, but less as a styled design system. OS: no. Nobody names a design system "os" in a way that would fit here.

D: Mainly as the phone's own UI. In a codebase that builds an iPhone app, an Android app and a website, "native" is the usual word for "not web". Calling a browser's built-in element "native" is also valid usage (a native <dialog>, native form controls), so on reflection it means both. But my first reading was the phone, and I'd only arrive at "both" because the page has no platform guard.
