## Phone
1. Filters: bottom sheet
2. Delete: centered box
3. Deliver to / Change: bottom sheet

## Website
1. Filters: centered box
2. Delete: centered box
3. Deliver to / Change: centered box

## Guesses
- The opt-in spelling: a boolean `adaptive` prop on `modal.root`. The sheet does not list it.
- That `modal.close` runs its `onClick` and then closes, so the Delete button can record the deletion and close in one step.
- That setting the controlled `open` state to `false` closes the modal. I rely on this when an address is picked.
- That a plain `onChange` handler with `event.currentTarget.checked` works on a native checkbox.
- That `<modal.trigger>` with no `onClick` opens the modal through `onChange(true)`.

## Answers
A: I used `adaptive` (`<modal.root adaptive>`). Two other spellings I would find natural are `sheet="adaptive"` and `presentation="auto"` (or `adapt`).

B: I used it on the Filters panel and on the saved-address picker. Both are short pick-something panels started by a thumb tap, which is where a bottom sheet is normal on a phone, and a centered box suits a laptop. I left it off the Delete confirmation. That is an alert dialog, and a destructive yes/no question should stay a centered box on every platform, matching how iPhone and Android show system alerts.
