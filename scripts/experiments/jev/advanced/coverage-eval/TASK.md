Scope: scripts/experiments/jev/advanced/coverage-eval/**; reusable exports/entry guard in advanced/journeys.mjs; single-schedule entry, shared schedule definitions and effective gate in advanced/production-navigation.mjs and advanced/production-patterns.mjs; /tmp/jev-coverage/** and existing experiment servers' /tmp/jev-advanced outputs. Implement explicit failure/reset feedback, persistent route/action/failure coverage, exclusion of no-op actions, repeated-failure suppression, and a deterministic escape from repeated choices without new coverage. Record the original and restricted menus, selection source and interventions. Do not hide product failures or count recovery as passing SPA navigation. Separate mandatory route starts and scheduler-required choices from model-selected coverage. Test these behavioral contracts before implementation.

Evaluation: random, least-visited and Jev receive identical observations, legal actions, oracles and restrictions. Three repeated runs per policy, each with fresh sessions starting at home, workspace, Todos and slow report; 12 decisions/session. Rotate ordering fairly; seeded randomness belongs to local selection/menu ordering, not a claim of Jev model seeding. Shared coverage memory spans the four sessions within each run. At most 144 primary Jev journey decisions. Use current-spelling Todo fixture. Production: six actual schedules per policy, with prior errors, achieved conditions and unseen schedules fed back; remove a schedule after one attempt, and separately track forced completion. At most six additional primary Jev calls. Replays are offline. A fresh $1 conservative admission ledger applies to this evaluation, retaining the earlier experiment's cap and ledger unchanged. No automatic retries.

Decision criteria: Does the repaired harness escape the former add/edit/reset loop? Which routes, transitions, distinct actions and state/action combinations are exercised, attempted successfully or blocked by product behavior? Does Jev contribute additional diversity, valid failures or shorter failure discovery beyond the same harness with simple policies? Forced coverage alone cannot justify Jev. Treat this as a small local comparison, not statistical superiority. Repeat/minimize any newly observed failure before counting it as a discovery. Preserve incomplete or invalid attempts.

Verify: focused offline harness tests (red then green), unchanged client tests, pnpm run typecheck, both fixture authoring checks, a no-API browser preflight, complete primary runs, representative no-API replay, production condition checks, metrics recomputed from traces, code syntax/whitespace and credential exclusion. Exploratory failures are evidence, not a claim of a green product suite. Stop owned servers and archive source hashes, traces, API costs and a final recommendation. A PM completion audit maps this evidence to the original outcome. No commit, push, merge or framework fix is part of this task.

Final source packaging: rename the owned coverage directory to coverage-eval because the existing repository coverage/ ignore rule hides source as generated coverage output. No ignore configuration changes. Preserve the original command paths in historical logs; relative imports and executable behavior are unchanged.
