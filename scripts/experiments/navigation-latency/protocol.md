# Current-tree cold-navigation measurement

Workflow guidance: .ruler/skills/markless-implementation/implementation.md, .ruler/skills/markless-implementation/performance.md, .ruler/skills/markless-implementation/compiler.md, .ruler/skills/markless-implementation/bundler.md.

This measurement package is under admission development. Its partial script is not a completed performance benchmark. Historical before/linked files remain unchanged. Results belong to the current dirty candidate; they do not establish a clean-HEAD predecessor comparison.

## Frozen intended protocol

Pairs: Select → Accordion, Accordion → Select, Select → accordion-examples TSRX gallery. Destination content and a working interaction must both pass. A URL change alone does not pass.

Fresh dev uses a new process and unique experiment cache per sample. Warm dev explicitly loads the destination in a discarded context, then uses another context. Each condition requires ten independently cold browser visits. Service workers are blocked; no persistent browser profile or destination hover/focus prefetch is allowed. Source readiness is DOMContentLoaded, expected content, then 500 ms without script requests; failure is bounded at 30 seconds. Naturally shared source dependencies are inventoried.

Native production preserves visible-Link preload behavior and is labeled preloaded if destination-exclusive code arrives before click. Controlled production may use only the approved real embedded road-trip source with a late-created marked anchor, provided destination-exclusive code is absent at startup. Do not disable preload, rewrite responses or abort requests. Constrained production uses 150 ms network latency, 5 Mbit/s download, 1 Mbit/s upload and 4× CPU throttling.

Measure browser click, destination content readiness, interaction input and observed result, and navigation settlement independently. Preserve document nonce, original document reference and document network requests. Source-range execution coverage and CPU/server profiles belong in separate untimed diagnostic runs. A frame callback is not compositor paint proof.

Report median, nearest-rank p95, min/max and MAD; retain failed attempts separately and never remove outliers. With ten samples, p95 is the maximum. Engineering gates are median ≤100 ms/p95 ≤150 ms for ready-server cold visits and median ≤150 ms/p95 ≤250 ms for fresh dev. These apply to content and usable interaction, with automation input gaps exposed. A later improvement must exceed max(10 ms, 10% of baseline median, twice the larger MAD), with no p95, correctness or initial-JS regression. No speculation/startup tradeoff is authorized.

The initial production implementation used canonical website Vite Plus build/preview with experiment-owned Nitro outputs and a source-fingerprint-keyed build cache. The exact-build repair below retains canonical builds and replaces Vite preview with the selected generated Nitro entry. The production manifest constant comes from its owning router module. The native Select sidebar preloads its Accordion destination and is recorded as preloaded, not cold.

The approved controlled source is `/markless/examples/accordion/road-trip?embed=1`. Its late-created marked anchor must be inside the actual source link bridge's `[data-async-container]`; appending it to `body` bypasses that container-scoped listener and produces an invalid full-document harness sample. Cold admission checks the complete request inventory both at source readiness and immediately before click. It does not suppress native requests. Production coverage and profiles run separately from timing samples.

The fixed local preview transport is HTTP/1.1 with no observed content compression. In the constrained condition its request concurrency and hundreds of small chunks materially affect elapsed time; those results are not deployed HTTP/2 estimates. Startup encoded/decoded body sizes, CDP encoded transfer totals, and executed source ranges are distinct measurements. Modulepreload requests are transfers and do not establish execution.

The built router demand Witness is a separate instrumented fixture. It marks destination container runtime demand through a test-only transform, checks no marker through the navigation mount, then checks the marker and rendered counter updates on genuine interaction. The existing global execution observer cannot attribute an outgoing Link handler's runtime to the destination. This fixture preserves native preloads and does not replace cold website measurements. The old scope's Select/gallery oracles and route title correctness remain unresolved.

## Canonical server CPU diagnostics

`--server-profile` is restricted to dev `--diagnostic` runs. The canonical CLI child receives a scoped Node preload that attaches an inspector session in each participating Node isolate. Identity files record PID, worker thread ID, argv, cwd and time origin. The measured runs include pnpm, the vp wrapper, the actual Vite CLI main isolate and its env-runner worker. Native background threads and any subprocess/isolate that does not inherit the preload remain outside this coverage.

After source readiness, the probe writes a profile start command and waits for participating isolates to acknowledge before clicking. It stops capture after content, successful interaction and navigation settlement. Browser time origin/marks, host command times and actual isolate acknowledgement times are retained. The 25 ms command polling and inspector start/stop overhead mean the capture envelope is wider than the navigation itself. Classify profiler and polling frames separately; do not describe their startup overhead as compiler cost. `process.cpuUsage()` is process-wide metadata and must never be summed across threads sharing a PID. Profile self/inclusive sample durations are separate from overlapping transform-hook wall durations. Inclusive categories can overlap and must not be added together.

The restored twenty-sample dev measurements do not enable server profiling. They establish the current restored state rather than proving causation for the earlier candidate's measurements across an interruption. Production diagnostic admission remains one smoke/profile run, not a replacement distribution. Precise browser coverage reports V8 source-offset ranges; these are neither transfer bytes nor CPU time.

## Exact production-build selection and sample validity

Production launches the selected build's generated `site/server/index.mjs` with website cwd and only explicit `NITRO_HOST=127.0.0.1` and `NITRO_PORT` overrides. Normal builds still use canonical website Vite Plus build. `--build-dir <directory>` reuses an existing build read-only: no build, configuration write, or launch receipt is placed in that directory. Fresh launch and sample receipts belong to the requested output. Dev retains canonical Vite Plus dev and its existing flags.

Vite's Nitro preview resolves a shared `website/node_modules/.nitro/last-build.json` pointer. Separate Vite output configuration does not isolate that lookup. Consequently, historical multi-build comparisons without served-body identity are unverified for build selection; this does not invalidate captures whose bodies were explicitly verified. The reusable production launcher bypasses that pointer and records absolute build, generated-entry, public and inventory paths; executable/arguments; environment overrides; owned child PID; and a content digest covering the inventory and generated site files. Archived build identity is recorded separately from the current package/website source fingerprint.

Readiness requires a successful served-asset hash check, followed by per-sample verification. The response collector includes application JavaScript prefetches reported as Other, preserves repeated responses, and checks each response body against the selected public asset inventory. Unexpected JavaScript, missing files or bodies, failed loads, mismatched hashes, unmatched resource entries or ResourceTiming overflow invalidate the sample and yield a nonzero result. The resource buffer is configured before document startup. Endpoint marks are captured before the bounded evidence drain; resource snapshots follow completed body collection. Encoded body bytes, decoded body bytes, transfer sizes and precise execution ranges remain separate. Invalid captures supply failure evidence, not accepted totals.

`--native` preserves ordinary prefetching and labels observed destination preloading explicitly. It does not claim an unloaded destination. Controlled production admission supports only the existing embedded-source Accordion case; other controlled destinations are rejected rather than checked against Accordion's manifest. Neither mode suppresses requests. Navigation and destination interaction currently use `HTMLElement.click()` through Playwright `locator.evaluate`, not trusted mouse input. Existing content, interaction and settlement boundaries and destination-oracle limitations remain in force.

Precise execution coverage and CPU profiles require `--diagnostic`; these instrumented smoke runs establish no latency distribution or speed claim. The executable isolation test reuses distinct archived builds in before→after→before order, verifies a known differing asset and captured application bodies, checks SSR/preloads and one-document Accordion interaction, and includes missing-identity/body, mismatch, overflow, occupied-port, bounded-readiness and pending-launch cleanup controls. Only owned children are terminated.
