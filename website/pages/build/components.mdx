# Props pass values down, and callbacks talk back

<PageMeta time="5 min" assumes="state, events" />

<ThemeToggle />

Your page works, and the file keeps growing. One piece of it wants to be its own component. Now two
components need to share a number.

They share it through props. A component's parameter is its props, like the parameter of any other
function.

Here is the part that surprised me. **A prop is a live read of the parent's value, not a copy.**
When the parent's `count` changes, the text inside the child changes too. The child does not run
again.

Click **Add one** a few times.

<Code note="Add a second Badge with value={count * 2}, then click Add one. Both bold numbers follow count, and each Badge keeps the number it drew.">
```tsrx title="badge-counter.tsrx"
import { state } from '@markless/core';

function Badge({ value }: { value: number }) @{
	const drawn =
		Math.floor(Math.random() * 900) + 100;

	<p>
		<strong>{value}</strong> clicks so far. Badge
		drew {drawn} when it ran.
	</p>
}

export default function BadgeCounter() @{
	let count = state(0);

	<section>
		<Badge value={count} />
		<button onClick={() => count++}>
			Add one
		</button>
	</section>
}
```
</Code>

The count goes up. The number Badge drew stays the same. Badge drew it once, when it ran, and it
never ran again.

`Badge` takes `{ value }`, and the parent writes `value={count}`. That is the whole connection. A
click changes `count`, and Markless updates the text inside `<strong>`. Nothing else on the page
moves.

## Talk back with a callback

The child can't change the parent's `count` itself. Instead, the parent hands the child a function,
and the child calls it.

Pick a name.

<NamePickerDemo />

Each `Picker` gets its own `name` and the same `onPick`. The click runs `onPick(name)` in the child.
The parent's function sets `picked`, and the paragraph changes.

## Put children where you want them

Elements between a component's tags arrive as the `children` prop. Write `{children}` where it goes.
Its type is `Children` from `@markless/core`.

```tsrx
import type { Children } from '@markless/core';

export default function Card({ title, children }: { title: string; children?: Children }) @{
	<section class="card">
		<h2>{title}</h2>
		{children}
	</section>
}
```

And this is how a page uses it:

```tsrx
import Card from './card.tsrx';

export default function Welcome() @{
	<Card title="Welcome">
		<p>Anything between the tags lands where Card puts children.</p>
	</Card>
}
```

<Callout
	sprite="cross"
	title="Why can't I map over children?"
	text="You can place children, wrap it in more elements, or pass it to another component. You can't look inside it. Mapping, counting or indexing children stops the build with MARKLESS_CHILDREN_OPAQUE."
/>

## Defaults for props

A default like `{ text = 'none' }` looks natural, but Markless refuses it when your elements show the
prop. The build stops with `MARKLESS_STATE_DESTRUCTURE_DEFAULT_UNSUPPORTED`. Work out the fallback
in a computed value instead:

```tsrx
import { computed } from '@markless/core';

export default function Label({ text }: { text?: string }) @{
	const shown = computed(() => text ?? 'none');

	<p>{shown}</p>
}
```
