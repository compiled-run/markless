# Reach a real element with `element()`

<PageMeta time="4 min" assumes="state, events" />

<ThemeToggle />

<Subtitle text="A handle is a name for one real element. A handler can use it once that element is on the page." />

Type a name, then press **Add guest**.

<Code steps={[{ label: 'Press Add guest. The count goes up, and the cursor lands back in the field.', shows: 'Guests added: 1' }, { label: "Empty the field on each press: above `field?.focus()`, add `if (field) field.value = '';`.", source: "field.value = ''" }]}>
```tsrx title="guest-form.tsrx"
import { element, state } from '@markless/core';

export default function GuestForm() @{
	let added = state(0);
	const field = element<HTMLInputElement>();

	<section>
		<label for={field}>Guest name</label>
		<input el={field} />
		<button
			onClick={() => {
				added++;
				field?.focus();
			}}
		>
			Add guest
		</button>
		<p>Guests added: {added}</p>
	</section>
}
```
</Code>

`el={field}` binds the handle to the `<input>`. Inside a handler, `field` is that element, or `undefined` if it isn't on the page. That is why the code writes `field?.focus()`.

Your component runs once, before the `<input>` exists, so an element can't be state. A handle is how you reach it later.

## Point a label at a field without an id

Press the words **Guest name**. The cursor goes to the field, because `for={field}` points the label at it. Markless makes one id and writes it on both elements.

A handle works this way in five attributes:

| Attribute | What it points at |
| --- | --- |
| `for` | the field a label belongs to |
| `aria-labelledby` | the element that names this one |
| `aria-describedby` | the element that describes this one |
| `aria-controls` | the element this one opens or changes |
| `popovertarget` | the popover this button opens |

## Reach every row with an array handle

Give `element()` an array type, and the handle collects every element you bind it to, in page order. It is never `undefined`, just empty before anything is on the page.

<Code steps={[{ label: 'Press Count rows.', shows: 'Rows on the page: 3' }, { label: "Add `'Linus'` to the list in `state()`, and press again.", shows: 'Rows on the page: 4' }]}>
```tsrx title="guest-list.tsrx"
import { element, state } from '@markless/core';

export default function GuestList() @{
	let guests = state(['Ada', 'Grace', 'Kim']);
	const rows = element<HTMLLIElement[]>();
	let count = state(0);

	<section>
		<ul>
			@for (const guest of guests; key guest) {
				<li el={rows}>{guest}</li>
			}
		</ul>
		<button onClick={() => (count = rows.length)}>
			Count rows
		</button>
		<p>Rows on the page: {count}</p>
	</section>
}
```
</Code>

## Run setup code with `attach`

Some code needs the element itself, like an observer or a library from outside. `attach` hands the element to your function. If the function returns another function, Markless calls that one when the element leaves the page.

```tsrx title="note-box.tsrx"
import { state } from '@markless/core';

export default function NoteBox() @{
	let edits = state(0);

	<section>
		<textarea
			attach={(box) => {
				const observer = new ResizeObserver(() => {});
				observer.observe(box);
				return () => observer.disconnect();
			}}
			onInput={() => edits++}
		/>
		<p>Edits: {edits}</p>
	</section>
}
```

On a page the server renders, `attach` waits, like every other piece of code. It starts at the first of these:

| What is on the element | When `attach` starts |
| --- | --- |
| a handler like `onInput`, on the element or inside it | just before that handler first runs |
| `onVisible` | when the element scrolls into view |
| `onIdle` | once the page has loaded and the browser is idle |

So the observer above starts on the first keystroke. To start it as soon as the element is on screen, add `onVisible={() => {}}` to it. An element the browser creates, like the inside of an `@if` that opens, runs `attach` straight away.

Not yet:

- `attach` goes on page elements like `<textarea>`, not on components (`MARKLESS_ATTACH_HOST_ELEMENT_REQUIRED`).
- An `attach` with none of the three starters stops the build with [`MARKLESS_ATTACH_NO_START_TRIGGER`](/errors/MARKLESS_ATTACH_NO_START_TRIGGER), because it would never run.
- A handle can't be shown in the elements. `{field.value}` stops the build with `MARKLESS_ELEMENT_HANDLE_RENDER_READ`; keep that text in `state()`.
- A single handle binds one element. A second `el={field}` stops the build with `MARKLESS_ELEMENT_HANDLE_DUPLICATE`, so make a second handle or use an array one.

Some values should outlive a reload. [Keep them with `storage()`](/build/storage).
