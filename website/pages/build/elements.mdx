# Reach a real element with `element()`

<PageMeta level="Building" time="4 min" assumes="state, events" sprite="bolt" />

<ThemeToggle />

A click handler can change `count`. Sometimes it also needs the real `<input>`, to put the cursor in
it or to measure it.

An element is not state. Your component runs once to set up the page, and at that moment the
`<input>` does not exist yet. So Markless gives you a handle: a name that points at one element once
that element is on the page.

Click **Add one and focus**.

<Code note="Add a Select button whose click runs field?.select(). Click it, and the number in the field is selected. Then add a second input with its own handle, and a button that focuses it.">
```tsrx title="focus-counter.tsrx"
import { element, state } from '@markless/core';

export default function FocusCounter() @{
	let count = state(0);
	const field = element<HTMLInputElement>();

	<section>
		<label for={field}>Count</label>
		<input el={field} value={count} />
		<button onClick={() => { count++; field?.focus(); }}>Add one and focus</button>
	</section>
}
```
</Code>

The number goes up, and the cursor lands in the field. Click the word **Count** too. The cursor goes
to the field, because the label points at it. Nobody wrote an id.

`el={field}` links the handle to the `<input>`. Inside a handler, `field` is the element itself. If
the element is not on the page, `field` is `undefined`. That is why the code writes `field?.focus()`.

## Links without ids

Look at `for={field}` again. You pass the handle, and Markless makes one id and puts it on both
elements. A handle works this way in five attributes:

| Attribute | What it points at |
| --- | --- |
| `for` | the field a label belongs to |
| `aria-labelledby` | the element that names this one |
| `aria-describedby` | the element that describes this one |
| `aria-controls` | the element this one opens or changes |
| `popovertarget` | the popover this button opens |

## Run setup code with `attach`

Some code needs the element as soon as it exists, like an observer or a library from outside.
`attach` hands the element to your function. If your function returns a cleanup function, Markless
calls it when the element leaves the page.

```tsrx
import { state } from '@markless/core';

export default function Watched() @{
	let count = state(0);

	<button
		attach={(button) => {
			const observer = new ResizeObserver(() => {});
			observer.observe(button);
			return () => observer.disconnect();
		}}
		onClick={() => count++}
	>
		{count}
	</button>
}
```

`attach` goes on page elements like `<button>`, not on components. On a component, the build stops
with `MARKLESS_ATTACH_HOST_ELEMENT_REQUIRED`.
