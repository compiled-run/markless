# Shared state

<PageMeta time="5 min" assumes="state, components" />

<Subtitle text="shared() is state with a name: every component that calls the name gets the same copy." terms="shared state" />

```tsrx title="player.tsrx"
import { shared, state } from '@markless/core';

export const player = shared(() => {
	const box = state({ track: 'Harbour Lights' });
	return { ...box };
});
```

**`shared()`** takes a function that makes the state, and names it `player`. Every component that calls **`player()`** gets the same `track`, with no props in between.

## Two components read one copy

A *shared definition* is the function you pass to `shared()`. Call it from any component, and:

- every caller reads the same values
- a change in one caller shows in all of them
- no prop has to carry it

Press play on either player, then turn one volume knob.

```tsrx title="player.tsrx"
import { shared, state } from '@markless/core';

export const player = shared(
	() => {
		const box = state({
			track: 'Harbour Lights',
			playing: false,
		});
		return {
			...box,
			toggle() {
				box.playing = !box.playing;
			},
		};
	},
	{ scope: 'app' },
);

function MiniPlayer() @{
	const p = player();

	<p>
		{p.playing ? 'Playing' : 'Paused'}: {p.track}
	</p>
}

export default function NowPlaying() @{
	const p = player();

	<section>
		<MiniPlayer />
		<h2>{p.track}</h2>
		<button onClick={() => p.toggle()}>
			{p.playing ? 'Pause' : 'Play'}
		</button>
	</section>
}
```

## One signed-in user for the whole app

A real app shows the same data in places far apart. Here the header shows who is signed in, and a settings form elsewhere edits the name. Neither passes the user to the other: both call **`viewer()`**, so there is one user.

<Code steps={[{ label: "Type Grace in the form. The header changes as you type.", shows: 'Signed in as Grace' }, { label: "Change `'Ada'` to `'Linus'`. Both places start with the new name.", source: "name: 'Linus'" }]}>
```tsrx title="account.tsrx"
import { shared, state } from '@markless/core';

export const viewer = shared(
	() => {
		const box = state({ name: 'Ada' });
		return {
			...box,
			rename(name: string) {
				box.name = name;
			},
		};
	},
	{ scope: 'app' },
);

function Header() @{
	const v = viewer();

	<header>Signed in as {v.name}</header>
}

function Settings() @{
	const v = viewer();

	<label>
		Name
		<input
			value={v.name}
			onInput={(event) =>
				v.rename(event.currentTarget.value)
			}
		/>
	</label>
}

export default function Account() @{
	<section>
		<Header />
		<Settings />
	</section>
}
```

## Who shares one copy

The second argument, the *scope*, says who shares one copy. You never write down where the sharing starts: the compiler finds it when it builds your app.

## One copy per tab group

A tab group is several components that work as one: a root, a list, triggers and panels. Each tab group needs its own copy, shared by its parts. A *subtree* is a component plus everything rendered inside it, and with one copy per subtree:

- the outermost component that calls the definition gets a new copy
- everything rendered inside it shares that copy
- place the tab group twice, and you get two copies

Below, `Tabs`, `Tab` and `Panel` all call **`tabs()`**. `Tabs` is the outermost, so each recipe card keeps its own open tab.

<Code entry="recipes.tsrx" steps={[{ label: 'Press Cook on Pancakes. Soup stays on Prep.', shows: 'Fry.' }, { label: 'Add a third `<Tabs open="Cook">` card. It starts with its own copy.', source: 'open="Cook"' }]}>
```tsrx title="tabs.tsrx"
import type { Children } from '@markless/core';
import {
	computed,
	shared,
	state,
} from '@markless/core';

export const tabs = shared(
	() => {
		const box = state({ open: '' });
		return {
			...box,
			show(name: string) {
				box.open = name;
			},
		};
	},
	{ scope: 'subtree' },
);

type Props = {
	name: string;
	children?: Children;
};

export function Tabs({
	open,
	children,
}: {
	open: string;
	children?: Children;
}) @{
	const t = tabs();
	t.open = open;

	<div>{children}</div>
}

export function TabList({
	children,
}: {
	children?: Children;
}) @{
	<div role="tablist">{children}</div>
}

export function Tab({ name }: Props) @{
	const t = tabs();
	const on = computed(() => t.open === name);

	<button
		role="tab"
		aria-selected={on ? 'true' : 'false'}
		onClick={() => t.show(name)}
	>
		<style>
			[aria-selected='true'] {
				font-weight: bold;
			}
		</style>
		{name}
	</button>
}

export function Panel(props: Props) @{
	const t = tabs();

	@if (t.open === props.name) {
		<p role="tabpanel">{props.children}</p>
	}
}
```

```tsrx title="recipes.tsrx"
import {
	Panel,
	Tab,
	TabList,
	Tabs,
} from './tabs.tsrx';

export default function Recipes() @{
	<section>
		<Tabs open="Prep">
			<h3>Pancakes</h3>
			<TabList>
				<Tab name="Prep" />
				<Tab name="Cook" />
			</TabList>
			<Panel name="Prep">Flour, eggs.</Panel>
			<Panel name="Cook">Fry.</Panel>
		</Tabs>
		<Tabs open="Prep">
			<h3>Soup</h3>
			<TabList>
				<Tab name="Prep" />
				<Tab name="Cook" />
			</TabList>
			<Panel name="Prep">Leeks.</Panel>
			<Panel name="Cook">Simmer.</Panel>
		</Tabs>
	</section>
}
```

The [UI components](/ui) work the same way, so two menus on one page open and close on their own.

A tab group inside another tab group gets its own copy too. Put a `Tabs` inside another one's `Panel`, and the inner `Tabs` starts a new copy, so its tabs never move the outer ones:

```tsrx title="week.tsrx"
import {
	Panel,
	Tab,
	TabList,
	Tabs,
} from './tabs.tsrx';

export default function Week() @{
	<Tabs open="Plan">
		<Panel name="Plan">
			<Tabs open="Monday">
				<TabList>
					<Tab name="Monday" />
					<Tab name="Tuesday" />
				</TabList>
			</Tabs>
		</Panel>
	</Tabs>
}
```

## A copy lasts until a reload

- On the server, every request starts from the starting values.
- In the browser, one copy lives as long as the document, through links, Back and Forward.
- A reload starts again from the starting values.

## Two apps on one page share by name

Two separately built apps on one page that call the same definition read and write one copy. This happens with *micro-frontends*: parts of one page that different teams build and ship on their own. The name is the file plus its export, like `lib/player.tsrx#player`, so both must import it from the same place.

Both apps must also give the value the same shape: the same field names and types. To give each app its own copy instead, use `{ scope: 'container' }`.

<Collapsible sprite="star-badge" summary="Coming from React context?">

A subtree definition is context with no `Provider` to write. The outermost component that calls it is the provider, and the compiler sees which one that is at build time. Some component is always the outermost caller, so there is no missing-provider error to guard against.

An app definition is one copy per user. On the server each request gets its own, so two requests rendering at once never share it. In the browser it is kept until a reload, across in-place navigation, and it starts from the values the server rendered.
