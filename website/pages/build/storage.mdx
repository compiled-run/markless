# Keep a value across reloads with `storage()`

<PageMeta time="3 min" assumes="state" />

<Subtitle text="storage() is a string variable the browser keeps for the reader. Reload the page, and it still holds their choice." />

Pick a drink, then reload this page.

<DrinkDemo />

- Your pick is still there after the reload, marked before the page shows.
- One write saved it in three places: a cookie, `localStorage`, and the `data-docs-drink` attribute on `<html>`.
- The mark is plain CSS that reads that attribute.

## Save it under a key

```tsrx title="theme-switch.tsrx"
import { storage } from '@markless/core';

let theme = storage('theme', 'light');

export default function ThemeSwitch() @{
	<button
		onClick={() => {
			theme = theme === 'light' ? 'dark' : 'light';
		}}
	>
		Theme: {theme}
	</button>
}
```

The first argument is the key the browser saves it under. The second is the starting value, for a reader who hasn't picked yet. You can call `storage()` at the top of a file, as here, or inside a component.

Each write saves the value in three places:

- a cookie named `markless-theme`, so the server renders the saved value in the very first byte
- `localStorage`, under the key `theme`
- the attribute `data-theme` on `<html>`, for your CSS

A page that shows a `storage()` value answers with `Cache-Control: private` and `Vary: cookie`. So a shared cache never hands one reader's page to another.

## Style from the attribute

```css title="style.css"
html[data-theme='dark'] body {
	background: #222;
	color: #eee;
}
```

A prerendered page has no cookie to read, so a small script runs before the page content. It reads the saved value and sets the `<html>` attribute first, so this CSS is right from the first paint. It covers `storage()` in the page file and, on an `.mdx` page, in the components the page imports directly.

## One argument or two

| Call | Saved under | Attribute on `<html>` |
| --- | --- | --- |
| `let theme = storage('theme', 'light')` | `theme` | `data-theme` |
| `let theme = storage('light')` | `markless:theme` | `data-markless-theme` |

With one argument, that argument is the starting value, and Markless builds the key from the variable name. Rename `theme` to `mode`, and every reader's saved choice is left behind under the old key. For anything you ship, pass the key yourself.

Not yet:

- The key and the starting value must be plain strings, like `'theme'`. Anything built from other values stops the build with `MARKLESS_STORAGE_KEY_STATIC`.
- The value is always a string. To keep a number, save its text and convert it when you read it.
- A `const` storage value is read-only. Assigning to it stops the build with `MARKLESS_STATE_CONST_REASSIGNMENT`.

When several components need one value, [share it with `shared()`](/build/shared).
