# Waiting is a block, not a flag

<PageMeta level="Building" time="5 min" assumes="state, computed, conditionals" sprite="arrow-loop" />

<ThemeToggle />

Count the variables a loading spinner usually needs. The data. A flag for "still loading". An error,
in case the data never comes. Then a rule in your head about which one wins when two are set.

Only the data is what the page is about. You can drop the other three.

**Give `computed()` an `async` recipe. Then write three blocks: one for the answer, one for the
wait, and one for a failure.**

Each pick runs the recipe again. The old answer stays on the page until the new one is ready, then
swaps. The cracked mug fails, and the `@catch` block takes its place. Pick another mug and the page
recovers.

```tsrx
import { computed, state } from '@markless/core';
import { loadMugFact } from './mug-facts.ts';

export default function MugFacts() @{
	let mug = state('');
	const fact = computed(async () => {
		const which = mug;
		return { text: await loadMugFact(which) };
	});

	<section>
		<button onClick={() => (mug = 'tall')}>Tall mug</button>
		<button onClick={() => (mug = 'small')}>Small mug</button>
		<button onClick={() => (mug = 'cracked')}>Cracked mug</button>
		@try {
			<p>{fact.text}</p>
		} @pending {
			<p>Looking it up...</p>
		} @catch {
			<p>That mug is not on the shelf.</p>
		}
	</section>
}
```

`loadMugFact` stands in for a `fetch`. It answers "Pick a mug." straight away, waits before it
answers anything else, and fails for a mug it does not know:

```ts
const facts: Record<string, string> = {
	tall: 'The tall mug holds a big coffee.',
	small: 'The small mug holds one espresso.',
};

export function loadMugFact(mug: string): Promise<string> {
	if (mug === '') return Promise.resolve('Pick a mug.');
	return new Promise((resolve, reject) => {
		setTimeout(() => {
			const fact = facts[mug];
			if (fact) resolve(fact);
			else reject(new Error(`No mug called ${mug}`));
		}, 1500);
	});
}
```

## The three blocks

`@try` holds what you show once the value is ready. Inside it, read the value directly, as in
`fact.text`. There is no `.data` to reach through and no status to check.

`@catch` holds what you show when the recipe throws or its promise rejects.

`@pending` holds what you show while there is no answer yet, such as the first render of a
browser-only app. This page arrived with its first answer, "Pick a mug.", already in place. Later
picks keep the old answer on screen. So on this page, `@pending` has nothing to cover.

## Read state before the first await

The recipe copies `mug` into `which` before it awaits anything. That is on purpose. The reads before
the first `await` tell Markless when to run the recipe again. A state read after an `await` stops the
build with `MARKLESS_ASYNC_POST_AWAIT_READ`.

## Try this

Delete the `@catch` block and pick the cracked mug. The answer disappears, and nothing on the page
says why. Put the block back. It is the only place your page says what failure looks like.

Then move `const which = mug;` below the `await` line and build. Read the error, and move the line
back.
