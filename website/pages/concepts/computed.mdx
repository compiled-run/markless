# A value you work out is never out of date

<PageMeta time="2 min" assumes="state" />

<Subtitle text="If you can work a value out from other values, don't store it. Write the recipe once with computed()." />

```tsrx
const total = computed(() => cart * 14);
```

The function you pass is the *recipe*. Markless finds `cart` in it, so you never list what it reads.

## Follow the recipe

The card on the desk is the recipe for `total`. Press **Add to cart**.

## Change the recipe

<Code steps={[{ label: 'Press Add a coaster twice. The total reads 18.', shows: 'Total: 18' }, { label: 'Change `12` to `15`. Each mug now adds 15.', source: 'mugs * 15' }, { label: 'Add `total = 0` to the end of a click handler, and read the build error.', source: 'total = 0' }]}>
```tsrx title="mug-order.tsrx"
import { computed, state } from '@markless/core';

export default function MugOrder() @{
	let mugs = state(1);
	let coasters = state(0);
	const total = computed(
		() => mugs * 12 + coasters * 3,
	);

	<section>
		<p>Mugs at 12 each: {mugs}</p>
		<p>Coasters at 3 each: {coasters}</p>
		<p>Total: {total}</p>
		<button onClick={() => mugs++}>
			Add a mug
		</button>
		<button onClick={() => coasters++}>
			Add a coaster
		</button>
	</section>
}
```
</Code>

## What a recipe can read

- State, props, imports, other computed values, and `const` values built from those.
- Functions you declared with `function` or `const`.
- Not a plain `let` in the component body: `MARKLESS_COMPUTED_READS_RENDER_LOCAL`.

## A computed is read-only

- `total = 0` stops the build with `MARKLESS_STATE_READ_ONLY_WRITE`. Change its inputs instead.
- A recipe can't change state: `MARKLESS_STATE_WRITE_IN_COMPUTED`. Saving or logging goes in the handler.

<Collapsible sprite="star-badge" summary="How do existing tools handle this?">

Many tools ask you to list a derived value's inputs in a dependency array, and to run side work in an effect hook. Markless finds the inputs before your app runs, and side work stays in the handler.
