# Computed values

<PageMeta time="4 min" assumes="state, events" />

<Subtitle text="A computed is one of your values, worked out from other values and kept up to date." terms="computed values" />

```tsrx title="pace.tsrx"
import { computed, state } from '@markless/core';

export default function Pace() @{
	let km = state(5);
	let minutes = state(25);
	const pace = computed(() => minutes / km);

	<section>
		<p>{km} km in {minutes} min</p>
		<p>Pace: {pace} min/km</p>
		<button onClick={() => (minutes -= 1)}>
			Run faster
		</button>
	</section>
}
```

**`state()`** holds `km` and `minutes`. **`computed()`** works out `pace` from them, and works it out again whenever either one changes.

## A computed follows what it reads

The function you pass is the *recipe*. Markless reads it and finds `minutes` and `km`, so you never list them.

- Change `minutes` or `km`, and `pace` follows.
- Nothing else has to remember to update it.
- You can't set `pace` yourself.

## A computed can read other computeds

`advice` reads `fahrenheit`, which reads `celsius`. Change `celsius`, and both follow. The advice only flips when the temperature crosses 50°F.

<ThermometerAnatomy />

<Code steps={[{ label: 'Press Warmer until the advice changes.', shows: 'No coat' }, { label: "Add a third computed that reads `advice`, like `computed(() => advice + '!')`, and show it.", source: 'advice +' }]}>
```tsrx title="weather.tsrx"
import { computed, state } from '@markless/core';

export default function Weather() @{
	let celsius = state(5);
	const fahrenheit = computed(
		() => celsius * 1.8 + 32,
	);
	const advice = computed(() =>
		fahrenheit < 50 ? 'Bring a coat' : 'No coat',
	);

	<section>
		<p>{celsius}°C is {fahrenheit}°F.</p>
		<p>{advice}</p>
		<button onClick={() => (celsius += 5)}>
			Warmer
		</button>
	</section>
}
```
</Code>

## Give a long expression a name

Short expressions like `{minutes * 60}` or `{done ? 'yes' : 'no'}` work right in the markup. One with an arrow function or a spread, like `[...tags].join(', ')`, can't stay up to date there. Give it a name with `computed`.

<Code steps={[{ label: 'Press Add swing.', shows: 'jazz, bebop, swing' }, { label: "Try breaking it: replace `{line}` with `{[...tags].join(', ')}`. The build stops, because the page can't keep that expression up to date.", fails: 'MARKLESS_TEMPLATE_EXPRESSION_UNSUPPORTED' }]}>
```tsrx title="tag-line.tsrx"
import { computed, state } from '@markless/core';

export default function TagLine() @{
	let tags = state(new Set(['jazz', 'bebop']));
	const line = computed(() =>
		[...tags].join(', '),
	);

	<section>
		<p>{line}</p>
		<button onClick={() => tags.add('swing')}>
			Add swing
		</button>
	</section>
}
```
</Code>

## Filter and sort a list with a computed

A computed can return a new array, like the songs that match a search:

```tsrx
const shown = computed(() =>
	songs.filter((song) => song.title.includes(query)),
);
```

[Lists](/concepts/lists) shows each one on the page.

## A computed only reads

A computed works out a value. It never changes state. Saving or logging goes in the handler that made the change, where you already know what happened.

## A computed can wait for data

`computed(async () => ...)` waits for a fetch or any other promise. Its type is the value the promise resolves to, not a promise: `computed(async () => ({ text: '' }))` is typed `{ text: string }`. [Async values](/concepts/async) shows how the page looks while it waits.

Many tools ask you to list a derived value's inputs in a dependency array, and to run side work in an effect hook. Markless finds the inputs before your app runs, and side work stays in the handler.
