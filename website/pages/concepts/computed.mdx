# A value you work out is never out of date

<PageMeta level="Start here" time="3 min" assumes="state" sprite="spiral" />

<ThemeToggle />

You have seen this bug in a shop. The basket says three items. The total says the price of two.

Somebody stored the total in its own variable. Then somebody else added a button that changed the
items and forgot the total. Two copies of one fact drifted apart.

**If you can work a value out from other values, do not store it. Write the recipe once with
`computed()`.**

```tsrx
const total = computed(() => mugs * 12 + coasters * 3);
```

You read `total` like any other variable. You never call it, and you never list what it depends on.
Markless reads the recipe and sees `mugs` and `coasters` in it.

## Fill the basket

<ComputedSketch />

In the code below, press **Add a mug**. Then press **Add a coaster** twice. Watch the total.

<Code note="Add a third item with its own state() and price, put it in the recipe and give it a button. Then write total = 0 in a click handler and read the build error.">
```tsrx title="mug-order.tsrx"
import { computed, state } from '@markless/core';

export default function MugOrder() @{
	let mugs = state(1);
	let coasters = state(0);
	const total = computed(() => mugs * 12 + coasters * 3);

	<section>
		<p>Mugs at 12 each: {mugs}</p>
		<p>Coasters at 3 each: {coasters}</p>
		<p>Total: {total}</p>
		<button onClick={() => mugs++}>Add a mug</button>
		<button onClick={() => coasters++}>Add a coaster</button>
	</section>
}
```
</Code>

Now look in the file for the line that updates the total. There is no such line. Each button
changes one count and stops. When a count changes, Markless runs the recipe again and updates the
text that shows `total`.

## What a recipe can read

A recipe can read state, props, imports, and `const` values built from those. It cannot read other
variables from the component body. Those exist only while the component sets up the page, and the
recipe runs again long after that. The build stops with `MARKLESS_COMPUTED_READS_RENDER_LOCAL` and
names the variable.

## A computed is read-only

Assign to a computed, as in `total = 0`, and the build stops with `MARKLESS_STATE_READ_ONLY_WRITE`.
Change its inputs instead. A recipe cannot change state either. A state change inside
one gives `MARKLESS_STATE_WRITE_IN_COMPUTED`.

## Where does side work go?

Saving, logging, and sending a message are not values. They do not belong in a recipe. Put them in
the event handler that causes them. `@markless/core` has no effect function to run code when a value
changes. Each change starts in a handler, so the handler is the place for its side work.
