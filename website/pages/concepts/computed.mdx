# A value you work out is never out of date

<PageMeta time="3 min" assumes="state" />

<Subtitle text="If you can work a value out from other values, don't store it. Write the recipe once with computed()." />

You have seen this bug in a shop: the basket says three items, and the total says the price of two.
Someone stored the total in its own variable, and a new button forgot to update it.

```tsrx
const total = computed(() => mugs * 12 + coasters * 3);
```

A *recipe* is the function you give `computed()`. You read `total` like any other variable. You
never call it, and you never list what it depends on: Markless reads the recipe and finds `mugs`
and `coasters` in it.

## Press a button, watch the total follow

Press **Add a mug**, then **Add a coaster**, and watch the total.

<BasketDemo />

- Each button changes one count, and the total follows.
- The recipe runs again only when `mugs` or `coasters` changes.
- No handler mentions `total`, so there is nothing to forget.

## Change the recipe

<Code steps={[{ label: 'Press Add a coaster twice. The total reads 18.', shows: 'Total: 18' }, { label: 'Change `12` to `15`. Each mug now adds 15.', source: 'mugs * 15' }, { label: 'Add `total = 0` to the end of a click handler, and read the build error.', source: 'total = 0' }]}>
```tsrx title="mug-order.tsrx"
import { computed, state } from '@markless/core';

export default function MugOrder() @{
	let mugs = state(1);
	let coasters = state(0);
	const total = computed(
		() => mugs * 12 + coasters * 3,
	);

	<section>
		<p>Mugs at 12 each: {mugs}</p>
		<p>Coasters at 3 each: {coasters}</p>
		<p>Total: {total}</p>
		<button onClick={() => mugs++}>
			Add a mug
		</button>
		<button onClick={() => coasters++}>
			Add a coaster
		</button>
	</section>
}
```
</Code>

## What a recipe can read

- State, props, imports, other computed values, and `const` values built from those.
- A function you declared with `function` or `const`, in the file or in the component body. The
  same holds in the markup: `{label(count)}` updates when `count` changes.
- Not a plain `let` from the component body. It exists only while the component sets up the
  page, and the recipe runs long after that. The build stops with
  `MARKLESS_COMPUTED_READS_RENDER_LOCAL` and names the variable.

## A computed is read-only

- Assigning to one, as in `total = 0`, stops the build with `MARKLESS_STATE_READ_ONLY_WRITE`.
  Change its inputs instead.
- A recipe can't change state. A write inside one stops the build with
  `MARKLESS_STATE_WRITE_IN_COMPUTED`.
- Side work, like saving or logging, goes in the event handler that causes the change. There is
  no effect function that runs when a value changes.

<Collapsible sprite="star-badge" summary="How do existing tools handle this?">

Many tools ask you to list a derived value's inputs in a dependency array, and to run side work
in an effect hook when a value changes. Markless reads the recipe and finds its inputs before
your app runs, and side work stays in the handler where the change starts.

</Collapsible>
