# Conditionals

<PageMeta time="4 min" assumes="state, events" />

<Subtitle text="@if shows its elements while a condition is true, and removes them when it isn't." terms="elements" />

```tsrx title="video.tsrx"
import { state } from '@markless/core';

export default function Video() @{
	let playing = state(false);

	<section>
		@if (playing) {
			<p>Now playing</p>
		} @else {
			<p>Paused</p>
		}
		<button onClick={() => (playing = !playing)}>
			Play or pause
		</button>
	</section>
}
```

**`@if (playing)`** builds `<p>Now playing</p>` while `playing` is true. **`@else`** holds what goes there instead. One of the two is on the page; the other isn't there at all.

## A closed `@if` is gone, not covered

A *condition* is the true-or-false value in `@if ( )`. When it turns false, the elements inside aren't hidden with CSS. They're removed, and built new the next time it's true.

- Exactly one side is on the page at a time.
- Closing removes the elements and what you typed in them.
- Opening builds new, empty ones.

Type a note under the paused video, then press play. Pause again.

## A side holds one element

Each side of an `@if` holds one element. For more, wrap them in `<>` and `</>`:

```tsrx
@if (playing) {
	<>
		<p>Now playing</p>
		<button>Pause</button>
	</>
}
```

Two elements side by side stop the build with [`MARKLESS_BLOCK_SIBLING_NODES`](/errors/MARKLESS_BLOCK_SIBLING_NODES). The same goes for every `@` block: `@for`, `@switch` cases, `@try`, `@pending` and `@catch`.

## `@else if` asks the next condition

Conditions are asked top to bottom. The first true one wins, and `@else` catches the rest.

<Code steps={[{ label: 'Press Louder until it reads Loud.', shows: 'Loud' }, { label: 'Press Mute.', shows: 'Muted' }, { label: "Add `@else if (volume > 80) { <p>Very loud</p> }` above the `@else`, and press Louder until it shows.", source: 'volume > 80' }]}>
```tsrx title="volume.tsrx"
import { state } from '@markless/core';

export default function Volume() @{
	let volume = state(40);

	<section>
		@if (volume === 0) {
			<p>Muted</p>
		} @else if (volume < 50) {
			<p>Quiet</p>
		} @else {
			<p>Loud</p>
		}
		<button
			onClick={() =>
				(volume = Math.min(volume + 20, 100))
			}
		>
			Louder
		</button>
		<button onClick={() => (volume = 0)}>
			Mute
		</button>
	</section>
}
```
</Code>

## `@switch` picks one case

When one value can be one of several things, `@switch` compares it with each `@case` in order and shows the first that matches. `@default` shows when none does.

Press play, then drag the knob to the end of the timeline. Hover the card to see which case it came from.

<StatusAnatomy />

<Code steps={[{ label: 'Press Play.', shows: 'Now playing' }, { label: "Add `@case 'ended': { <p>Replay?</p> }` above `@default`, and a button that sets `status = 'ended'`.", source: "'ended'" }]}>
```tsrx title="status.tsrx"
import { state } from '@markless/core';

export default function Status() @{
	let status = state('loading');

	<section>
		@switch (status) {
			@case 'loading': {
				<p>Loading the video</p>
			}
			@case 'playing': {
				<p>Now playing</p>
			}
			@default: {
				<p>Paused</p>
			}
		}
		<button onClick={() => (status = 'playing')}>
			Play
		</button>
		<button onClick={() => (status = 'paused')}>
			Pause
		</button>
	</section>
}
```
</Code>

## `@switch (true)` picks the first condition that holds

Write `true` as the value, and each `@case` becomes a condition. It reads like the `@else if` chain above, one case per line:

```tsrx
@switch (true) {
	@case volume === 0: {
		<p>Muted</p>
	}
	@case volume < 50: {
		<p>Quiet</p>
	}
	@default: {
		<p>Loud</p>
	}
}
```

## Keep a value by declaring it above

Where you declare a value decides how long it lives. The field under the paused video had nothing behind it, so its text went with it. Declared above the `@if`, `note` lasts as long as the component, and the field comes back with the note still in it. A `state()` written inside a side belongs to that side, and starts over each time the side opens.

<Code steps={[{ label: 'Type `Great shot`, then press Play or pause. The field goes; the line stays.', shows: 'Great shot' }, { label: 'Add `<p>{note.length} letters</p>` under the line.', source: '{note.length}' }]}>
```tsrx title="note-kept.tsrx"
import { state } from '@markless/core';

export default function NoteKept() @{
	let playing = state(false);
	let note = state('');

	<section>
		<button onClick={() => (playing = !playing)}>
			Play or pause
		</button>
		@if (!playing) {
			<input
				placeholder="Add a note"
				value={note}
				onInput={(event) =>
					(note = event.currentTarget.value)
				}
			/>
		}
		<p>{note}</p>
	</section>
}
```
</Code>

## Show or hide without removing

When an element should stay on the page, with its scroll position and its typed text, toggle an attribute instead of wrapping it in `@if`:

```tsrx
<input hidden={playing} placeholder="Add a note" />
<button aria-pressed={playing} onClick={() => (playing = !playing)}>
	Play
</button>
```

## An attribute that comes and goes

For one attribute, you don't need an `@if`. Give it a value that can be missing:

| Value | What the element gets |
| --- | --- |
| `undefined`, `null` | no attribute |
| `false` | no attribute, except the names listed below, which get `"false"` |
| `true` | the bare attribute, as in `disabled=""`; `aria-*`, `data-*`, `draggable`, `contenteditable` and `spellcheck` get `"true"` |
| a string or number | that text |

`aria-pressed={false}` writes `aria-pressed="false"`, because for these states "false" and missing mean different things to a screen reader: `aria-atomic`, `aria-busy`, `aria-checked`, `aria-current`, `aria-disabled`, `aria-expanded`, `aria-grabbed`, `aria-haspopup`, `aria-invalid`, `aria-modal`, `aria-multiline`, `aria-multiselectable`, `aria-pressed`, `aria-readonly`, `aria-required` and `aria-selected`. `draggable`, `contenteditable` and `spellcheck` write `"false"` too. Every other attribute, `aria-hidden` included, is removed by `false`. To drop one of those states, pass `undefined`: `aria-busy={saving ? true : undefined}`.

You rarely write `aria-busy` yourself. While an async value loads again, Markless marks the elements that show it. See [Async values](/concepts/async#the-old-answer-stays-until-the-new-one-is-ready).
