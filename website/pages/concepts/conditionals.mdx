# A hidden branch is not hidden, it is gone

<PageMeta time="3 min" assumes="state, computed, events" sprite="corner-bracket" />

<ThemeToggle />

You type half a note into a panel. You close the panel by accident. You open it again, and the note
is gone.

That bug comes from a reasonable idea: keep the note next to the field that edits it. In Markless,
the build will not let you write it that way. Once you see why, the fix is one line.

**`@if` puts real elements on the page and takes them off again. A value only outlives the branch if
you declare it above the branch.**

## Close it, open it again

In the preview, press **Show or hide**, type a note, and close the field. Then open it again.

<ConditionalsSketch />

In the code below, press **Show or hide the note**. Type a note longer than twenty characters. Close
the panel, then open it again.

<Code note="Move let note = state('') inside the @if and read the build error. Put it back. Then change 20 to 5 and type six characters.">
```tsrx title="note-panel.tsrx"
import { computed, state } from '@markless/core';

export default function NotePanel() @{
	let open = state(false);
	let note = state('');
	const long = computed(() => note.length > 20);

	<section>
		<button onClick={() => (open = !open)}>
			Show or hide the note
		</button>
		@if (open) {
			<label>
				Note
				<input
					value={note}
					onInput={(event) =>
						(note = event.currentTarget.value)
					}
				/>
			</label>
		}
		@if (long) {
			<p>That is a long note.</p>
		} @else {
			<p>Short and sweet.</p>
		}
	</section>
}
```
</Code>

The field left the page when you closed the panel. Your note did not. It lives in `note`, which sits
in the component body above the `@if`. The line under the field kept working the whole time, because
it reads `note` too.

## Why state cannot live inside the branch

Move `let note = state('');` inside the `@if`, and the build stops with
`MARKLESS_STATE_CREATION_SITE_UNSTABLE`. The message reads: state() creates "note" inside a branch.

<MugSpot mood="sad">

Picture that note if the build let it through. It leaves the page with the branch. Opening the
panel again creates a new, empty note. Markless stops the build instead of shipping that bug. The same
run can list other errors on the same lines. They go away with the first one.

</MugSpot>

**Where you declare a value decides how long it lives.** The component body lasts as long as the
component. A branch lasts as long as its test is true.

## The shapes

`@else` covers the other side of the same test. Write it with the `@`. A plain `else` stops the
build with `MARKLESS_BRANCH_ELSE_SPELLING`.

For three or more cases, use `@switch`. It shows the one `@case` that matches, and `@default`
catches the rest:

```tsrx
import { state } from '@markless/core';

export default function Light() @{
	let color = state('red');

	<section>
		<button onClick={() => (color = color === 'red' ? 'green' : 'red')}>Switch</button>
		@switch (color) {
			@case 'red': {
				<p>Stop.</p>
			}
			@case 'green': {
				<p>Go.</p>
			}
			@default: {
				<p>Wait.</p>
			}
		}
	</section>
}
```

## Give the test a name

The demo tests `long`, not `note.length > 20`. The recipe in `computed()` gives the test a name, and
the `@if` reads that name. If the build warns `MARKLESS_TEMPLATE_EXPRESSION_STATIC` about a test,
this is the fix.
