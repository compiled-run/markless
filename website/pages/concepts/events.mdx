# Events

<PageMeta time="5 min" assumes="state" />

<Subtitle text="An event prop runs your handler when the browser fires one of its events, and hands it the real event object." terms="events" />

```tsrx title="composer.tsrx"
import { state } from '@markless/core';

export default function Composer() @{
	let draft = state('');

	<label>
		Message
		<input
			value={draft}
			onInput={(event) =>
				(draft = event.currentTarget.value)
			}
		/>
		<p>{draft.length} characters</p>
	</label>
}
```

**`onInput`** is `on` plus the browser's `input` event. The **`event`** your handler gets is the real one, so `event.currentTarget.value` is what was typed.

## A handler gets the browser's own event

An *event* is something a person does: a key press, a click, a tap. Your handler runs once for each one, and never before.

- Name the prop `on` plus the event name, with a capital letter: `onClick`, `onKeyDown`.
- The browser makes the event, with every field it always has.
- Your handler gets that same object: `event.key`, `event.target`, `event.preventDefault()`.

Press a key on the drawing, or type on your own keyboard.

## Pass your own values to a handler

Wrap the call in an arrow function, `onClick={() => pick('red')}`, to pass a value. A function from the component body works as a handler too.

<Code steps={[{ label: 'Press Blue.', shows: 'Picked: blue' }, { label: "Add a Green button that calls `pick('green')`.", source: "pick('green')" }]}>
```tsrx title="colours.tsrx"
import { state } from '@markless/core';

export default function Colours() @{
	let picked = state('none');
	function pick(colour: string) {
		picked = colour;
	}

	<section>
		<button onClick={() => pick('red')}>
			Red
		</button>
		<button onClick={() => pick('blue')}>
			Blue
		</button>
		<p>Picked: {picked}</p>
	</section>
}
```
</Code>

## Read the key with event.key

`event.key` is the key's name: `'Enter'`, `'Escape'`, `'a'`. `event.shiftKey` is true while Shift is held. Here Enter sends the message, and Escape empties the box.

<Code steps={[{ label: 'Type hello and press Enter.', shows: 'Sent: hello' }, { label: "Add a Clear button that runs `sent = ''`.", source: "sent = ''" }, { label: "Make Shift+Enter not send: `event.key === 'Enter' && !event.shiftKey`.", source: '!event.shiftKey' }]}>
```tsrx title="shortcuts.tsrx"
import { state } from '@markless/core';

export default function Shortcuts() @{
	let draft = state('');
	let sent = state('nothing yet');

	<section>
		<input
			value={draft}
			onInput={(event) =>
				(draft = event.currentTarget.value)
			}
			onKeyDown={(event) => {
				if (event.key === 'Enter') sent = draft;
				if (event.key === 'Escape') draft = '';
			}}
		/>
		<p>Sent: {sent}</p>
	</section>
}
```
</Code>

## Stop a form reloading the page

A form's submit reloads the page, which throws away what was typed. Call `event.preventDefault()` in `onSubmit` to keep the page. `new FormData(event.currentTarget)` reads the fields by their `name`.

<FormAnatomy />

<Code steps={[{ label: 'Type ada@example.com and press Join.', shows: 'ada@example.com' }, { label: 'Add `required` to the input, and press Join with the box empty. The browser stops the submit before your handler runs.', source: 'required' }]}>
```tsrx title="signup.tsrx"
import { state } from '@markless/core';

export default function Signup() @{
	let joined = state('');

	<form
		onSubmit={(event) => {
			event.preventDefault();
			const form = event.currentTarget;
			const data = new FormData(form);
			joined = String(data.get('email'));
		}}
	>
		<input name="email" type="email" />
		<button type="submit">Join</button>
		<p>{joined}</p>
	</form>
}
```
</Code>

`preventDefault()` works on the very first submit, because the build puts that call in the page itself.

## Read the right property for each control

There is no shortcut that ties a field to state. Set the value, and write it back in the handler:

- **Text box, text area:** `onInput`, read `.value`.
- **Number, range:** `onInput`, read `.valueAsNumber`.
- **Select:** `onChange`, read `.value`.
- **Checkbox:** `onChange`, read `.checked`.
- **Radio:** `onChange`, and set the value that radio stands for.

<Code steps={[{ label: 'Untick the box.', shows: 'off, Medium, 50' }, { label: 'Add `<option>Large</option>` to the select, and pick it.', source: '<option>Large</option>' }]}>
```tsrx title="controls.tsrx"
import { state } from '@markless/core';

export default function Settings() @{
	let sound = state(true);
	let size = state('Medium');
	let volume = state(50);

	<section>
		<input
			type="checkbox"
			checked={sound}
			onChange={(event) =>
				(sound = event.currentTarget.checked)
			}
		/>
		<select
			value={size}
			onChange={(event) =>
				(size = event.currentTarget.value)
			}
		>
			<option>Small</option>
			<option>Medium</option>
		</select>
		<input
			type="range"
			value={volume}
			onInput={(event) =>
				(volume =
					event.currentTarget.valueAsNumber)
			}
		/>
		<p>
			{sound ? 'on' : 'off'}, {size}, {volume}
		</p>
	</section>
}
```
</Code>

## Every other DOM event works the same way

`onPointerMove`, `onFocus`, `onBlur`, `onWheel`, `onDblClick` and the rest follow the same pattern: `on` plus the event name.

<Code steps={[{ label: 'Move the pointer over the text.', rewrites: 1 }, { label: "Add `onPointerLeave` that writes `x = 0`.", source: 'onPointerLeave' }]}>
```tsrx title="pad.tsrx"
import { state } from '@markless/core';

export default function Pad() @{
	let x = state(0);
	let y = state(0);

	<div
		onPointerMove={(event) => {
			x = event.offsetX;
			y = event.offsetY;
		}}
	>
		Pen at {x}, {y}
	</div>
}
```
</Code>

## Stop a click reaching the parent

A click on a button inside a clickable row reaches the row too. Call `event.stopPropagation()` to keep it on the button:

```tsrx
<li onClick={() => (open = id)}>
	{title}
	<button
		onClick={(event) => {
			event.stopPropagation();
			remove(id);
		}}
	>
		Delete
	</button>
</li>
```

There are no shortcuts like `onClick|once`. You write the call, as in plain JavaScript.

## Run several handlers on one event

Pass an array, and they run in order. If one throws an error, the ones after it don't run.

```tsrx
<button onClick={[send, clearDraft]}>Send</button>
```

## A handler that awaits can fail

A handler can be `async`. If an `await` in it fails inside a `@try` that has a `@catch`, the error shows in the nearest `@catch` around the element, and the content stays. A handler that returns a promise works the same way. See [a failing handler](/concepts/async#a-failing-handler-shows-in-catch).

Anywhere else, the handler stops at that `await`, state it changed before keeps its new value, and the browser reports an uncaught error. To show a message there, wrap the `await` in `try` and `catch`, and keep the message in state:

```tsrx
<button
	onClick={async () => {
		try {
			await saveReport(days);
			note = 'Saved';
		} catch {
			note = 'Could not save';
		}
	}}
>
	Save
</button>
```

## A form shows that it is sending

While an `onSubmit` handler that returns a promise is still running, Markless marks the form for you. The form gets `aria-busy="true"`, and the button that sent it gets `aria-disabled="true"`. If the handler saved something and the page loads its data again because of it, the marks stay until that new data is on screen. Otherwise they go away when the promise finishes, whether it worked or failed. You write no extra state for this, only CSS:

```css
form[aria-busy='true'] {
	opacity: 0.6;
}
form[aria-busy='true'] button {
	cursor: progress;
}
```

`aria-busy` on a form tells assistive tech that its contents are being updated, so many screen readers hold back announcing changes inside it until it clears; most don't announce the busy state itself. `aria-disabled` makes the button report as unavailable. Unlike `disabled`, it keeps keyboard focus on the button, so a keyboard user is not sent back to the top of the page.

`aria-disabled` doesn't stop the button working on its own. Markless stops a press that would send exactly what is already being sent: the same values in every field, from the same button. That press does nothing, with no message. If the person changed a field first, or pressed a different submit button, that is a new submission, and it is sent at once. A press made before Markless has loaded the code that does this, on the very first submit of a page, can still be sent twice. A handler that returns no promise marks nothing.

If you write `aria-disabled` on a submit button yourself, for example `aria-disabled={!ready}` to show the form isn't ready, Markless leaves `aria-disabled` alone on every button of that form and still marks the form busy. Style the sending state from the form's `aria-busy`, as above.

Markless sets the form's `aria-busy`, so the build refuses an `aria-busy` you write on such a form. To mark a form that is busy for another reason, use a class or a `data-` attribute. See [`MARKLESS_ASYNC_ARIA_BUSY_MANAGED`](/errors/MARKLESS_ASYNC_ARIA_BUSY_MANAGED).

## A handler's code waits for its event

Your component runs once, to set up the page. A handler's code isn't part of that: it runs only when its event fires. Two event props run without a person: `onIdle` once the page is idle, and `onVisible` once the element scrolls into view.

[Computed values](/concepts/computed) work a value out from your state, so it can never go stale.
