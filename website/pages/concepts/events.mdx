# Events hand you the browser's own event

<PageMeta time="3 min" assumes="state" />

<ThemeToggle />

You have written this in a plain script, with no framework anywhere near it:

```ts
input.addEventListener('input', (event) => {
	name = event.currentTarget.value;
});
```

Everything in that line still holds here. Same event names, same event object, same properties.

**An event prop is `on` plus the event name. Your handler gets the browser's own event.**

```tsrx
<input onInput={(event) => (name = event.currentTarget.value)} />
```

`event.key`, `event.target` and `event.preventDefault()` are the real ones. The docs you read
when you learned the DOM still apply.

## Print a mug

Type a name into the field. Press Enter. Then press Escape. Each row shows what one handler got from
the browser and what it changed.

<EventsSketch />

<Code note="Add a paragraph under the preview that shows {name.length}, and type a name. Then change onInput to onChange and type again: the preview waits until you leave the field.">
```tsrx title="mug-label.tsrx"
import { state } from '@markless/core';

export default function MugLabel() @{
	let name = state('');
	let printed = state('nothing yet');

	<form
		onSubmit={(event) => {
			event.preventDefault();
			printed = name;
		}}
	>
		<label>
			Name for the mug
			<input
				value={name}
				onInput={(event) =>
					(name = event.currentTarget.value)
				}
				onKeyDown={(event) => {
					if (event.key === 'Escape') name = '';
				}}
			/>
		</label>
		<p>Preview: {name}</p>
		<p>Printed: {printed}</p>
		<button type="submit">Print it</button>
	</form>
}
```
</Code>

The preview follows every key, because `onInput` changes `name`. Enter copies the name to the
printed line, and the page stays put. Escape clears the field.

The submit handler calls `event.preventDefault()`, the same as in a script tag. That is why Enter
does not reload the page.

## The code for a click runs when someone clicks

Your component runs once, to set up the page. A handler is different. Its code runs only when its
event fires. This holds whether the page renders in the browser alone or on a server.

## Code that waits until the page is idle

Some code belongs on the page but should never slow it down: an analytics tag, a chat widget, any
third-party script. No click asks for it.

**`onIdle` runs its handler once, after the page has loaded and the browser has nothing better to
do.** Put it on the element the code belongs to.

```tsrx
export default function Footer() @{
	<footer
		onIdle={async () => {
			const analytics =
				await import('./analytics.ts');
			analytics.start();
		}}
	>
		Made by Example Co.
	</footer>
}
```

Like any handler, its code downloads only when it runs. The `import()` inside it does the same for
the analytics script, so neither one is part of the page load.

It runs once per element. An element inside an `@if` or `@for` runs it after the element appears
and the page is idle again. An element that is gone by then never runs it.

## Naming the prop

Write `on` and then the event name. `click` becomes `onClick`, `input` becomes `onInput`, and
`keydown` becomes `onKeyDown`. The case after `on` does not matter, so `onKeydown` works too.

To run two handlers for one event, pass an array. They run in the order you wrote them.

```tsrx
import { state } from '@markless/core';

export default function SaveButton() @{
	let note = state('nothing saved');
	let saves = state(0);

	const save = () => (note = 'saved');
	const countSave = () => saves++;

	<button onClick={[save, countSave]}>{note}, {saves} times</button>
}
```

## What a handler can read

A handler can read state, props, imports, and `const` values built from those. It can also call a
function you declared in the component body, with `function` or `const`, and pass it arguments:
`onClick={() => add(2)}` runs `add` with the state and props it reads, including other body
functions it calls. A `const` built with `new Map(...)`, `new Set(...)`, `new Date(...)` or another
built-in, or any other body `const`, is built again for each click, so it is read-only there: a
handler that changes it, as in `list.push(3)` or `box.count = 1`, stops the build with
`MARKLESS_HANDLER_WRITES_RENDER_LOCAL`. Keep changing data in `state()`. It cannot read other variables from the component body. Those exist only while the
component sets up the page, and the click comes later. The build stops with
`MARKLESS_HANDLER_READS_RENDER_LOCAL`, or with `MARKLESS_EVENT_HANDLER_EMIT_UNSUPPORTED` for an
instance of your own class, and names the variable.
