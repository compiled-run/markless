# State is a variable the page watches

<PageMeta level="Start here" time="4 min" assumes="reading-tsrx" sprite="burst" />

<ThemeToggle />

You already know how to count in JavaScript.

```ts
let cups = 0;
cups++;
```

Put `cups` on a page, run `cups++`, and the page does not change. Nothing is wrong with the
variable. Nobody told the page to care about it.

**Wrap the starting value in `state()`, and the page cares.**

```tsrx
let cups = state(0);
```

It is still a `let`. You still read it as `cups`, and you still change it with `cups++`. The one
difference: every spot on the page that shows `cups` now changes when `cups` changes.

## Pour a few cups

Press **Pour a cup** in the preview. The table on the right counts the text each click changed.
Then switch on **Button shows cups too** and pour again.

<StateSketch />

In the code below, press **Pour a cup** three times. Then press **Start over**. Keep an eye on the
second line.

<Code note="Add a third paragraph that also shows {cups}, then press Pour a cup. Then change state(0) to a plain 0 and read the build error at the end of the line it names.">
```tsrx title="cups.tsrx"
import { state } from '@markless/core';

export default function Cups() @{
	let cups = state(0);
	const drawn = Math.floor(Math.random() * 90) + 10;

	<section>
		<p>Cups of coffee today: {cups}</p>
		<p>A number drawn once, when the page was set up: {drawn}</p>
		<button onClick={() => cups++}>Pour a cup</button>
		<button onClick={() => (cups = 0)}>Start over</button>
	</section>
}
```
</Code>

The count moves. The second number never does.

That number comes from `Math.random()`. The component drew it once, while it set up the page.
Your component runs once, to set up the page. A click does not run it again. The click runs
`cups++`, and Markless changes the one piece of text that shows `cups`.

## How does Markless know which text to change?

Before your app runs, Markless reads your component the way you do. It sees that `cups` shows up
in the first paragraph. It sees that the clicks change it, and it writes that down. So when `cups`
changes, it already knows the one piece of text to update.

This works the same whether the component renders in the browser alone or on a server.

## Any assignment counts

`cups++`, `cups = 0` and `cups += 2` all change the state. Objects change field by field:

```tsrx
import { state } from '@markless/core';

export default function Visitor() @{
	let user = state({ name: 'Ada', visits: 0 });

	<section>
		<p>{user.name}</p>
		<button onClick={() => user.visits++}>Visits: {user.visits}</button>
	</section>
}
```

A click changes the text that shows `user.visits`. The text that shows `user.name` stays as it is.

## Where state can live

Create state at the top of the component body, next to your other variables. Each of these stops
the build, and each error names the line:

- A `state()` outside the component function gives `MARKLESS_STATE_MODULE_SCOPE`.
- A `state()` inside an `@if`, a handler or a `for` statement gives
  `MARKLESS_STATE_CREATION_SITE_UNSTABLE`. The [conditionals page](/concepts/conditionals) shows why.
- A change inside the markup, such as `{cups++}`, gives `MARKLESS_STATE_WRITE_IN_TEMPLATE`.

`state()` works inside `.tsrx` files. Call it from a plain `.ts` file and it throws
`MARKLESS_FRAMEWORK_API_RUNTIME_CALL` the moment it runs.
