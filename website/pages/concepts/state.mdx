# State is a variable the page watches

<PageMeta time="4 min" assumes="reading-tsrx" />

<ThemeToggle />

Say you work at Beanshop, a coffee brand. Customers press **Add to cart** on your shop page, and
the page needs to keep track of how many bags they have added.

You already know how to count in JavaScript:

```ts
let cart = 0;
cart++;
```

Here is that variable as a jar beside your shop page. Press **Add to cart**.

<StateAnatomy wired={false} />

The jar fills up, but the page still says 0. A plain variable has no wires to the page, so the
page never finds out.

**Wrap the starting value in `state()`, and the page keeps up.**

```tsrx
let cart = state(0);
```

## Follow the wire

It is still a `let`, read as `cart` and changed with `cart++`. Before the page runs, Markless wires
`cart` to every spot that shows it. Press **Add to cart** again.

<StateAnatomy />

<Collapsible sprite="star-badge" summary="How do existing tools handle this?">

Most JavaScript tools ask you to treat the value in a special way, so they can tell when it changes.

Some have you change it through a setter function instead of `cart++`. After each change, they run
your whole component again and compare the new result with the old one to find what is different.

Others keep the value inside a container. You read it through `.value`, or call it like a function,
so the tool can see every read and every write as it happens.

Markless keeps it a plain `let`. Your component runs once and never runs again. The wires are
worked out before the page loads, so a change goes straight to the spots that show it.

</Collapsible>

## Change it with a click

`theme` is one value, and three spots on this settings page show it: the page's colours, the
heading and the picture. Press **Dark**, then **Light**.

<SettingsDemo />

- Every spot that shows `theme` changes together.
- Only the handler you pressed runs. It assigns `theme`, and that is all it does.
- The component function never runs again. It ran once, to set up the page.

Markless reads your component before it runs. It notes every spot that shows `theme`, so a change
goes straight to those spots.

<Code note="Add a paragraph that also shows {theme}, then press Dark. Then change state('light') to a plain 'light' and read the build error at the end of the line it names.">
```tsrx title="settings.tsrx"
import { state } from '@markless/core';

export default function Settings() @{
	let theme = state('light');

	<main class={theme}>
		<h2>Theme: {theme}</h2>
		<p>{theme === 'dark' ? '🌙' : '☀️'}</p>
		<button onClick={() => (theme = 'light')}>
			Light
		</button>
		<button onClick={() => (theme = 'dark')}>
			Dark
		</button>
		<style>
			.dark {
				background: #222;
				color: #eee;
			}
		</style>
	</main>
}
```
</Code>

## Any assignment counts

`theme = 'dark'`, `count++` and `count += 2` all change state. Objects change field by field:

```tsrx
import { state } from '@markless/core';

export default function Visitor() @{
	let user = state({ name: 'Ada', visits: 0 });

	<section>
		<p>{user.name}</p>
		<button onClick={() => user.visits++}>Visits: {user.visits}</button>
	</section>
}
```

A click changes the text that shows `user.visits`. The text that shows `user.name` stays as it is.

## Where state can live

Create state at the top of the component body, next to your other variables. Each of these stops
the build, and each error names the line:

- A `state()` outside the component function gives `MARKLESS_STATE_MODULE_SCOPE`.
- A `state()` inside an `@if`, a handler or a `for` statement gives
  `MARKLESS_STATE_CREATION_SITE_UNSTABLE`. The [conditionals page](/concepts/conditionals) shows why.
- A change inside the elements, such as `{count++}`, gives `MARKLESS_STATE_WRITE_IN_TEMPLATE`.

`state()` works inside `.tsrx` files. Call it from a plain `.ts` file and it throws
`MARKLESS_FRAMEWORK_API_RUNTIME_CALL` the moment it runs.
