# State

<PageMeta time="3 min" assumes="reading-tsrx" />

<Subtitle text="State is one of your values that the page watches: change it, and every spot that shows it updates." terms="values" />

```tsrx title="cart-badge.tsrx"
import { state } from '@markless/core';

export default function CartBadge() @{
	let cart = state(0);

	<button onClick={() => cart++}>In your cart: {cart}</button>
}
```

**`state(0)`** makes `cart` a value the page watches. It's still a plain **`let`**: you read it as `cart` and change it with `cart++`.

## A plain variable isn't watched

A *plain variable* is one without `state()`. Here is `let cart = 0` as a jar beside a shop page. Press **Add to cart**.

<StateAnatomy wired={false} />

The jar fills up, but the page still says 0. Nothing tells the page that `cart` changed.

## Follow the wire

It is still a `let`, read as `cart` and changed with `cart++`. Before the page runs, Markless wires
`cart` to every spot that shows it. Press **Add to cart** again.

## Change it with a click

`theme` is one value, and three spots on this settings page show it: the page's colours, the
heading and the picture. Press **Dark**, then **Light**.

<SettingsDemo />

- Every spot that shows `theme` changes together.
- Only the handler you pressed runs. It assigns `theme`, and that is all it does.
- The component function never runs again. It ran once, to set up the page.

Markless reads your component before it runs. It notes every spot that shows `theme`, so a change
goes straight to those spots.

<Collapsible sprite="star-badge" summary="How do existing tools handle this?">

Most tools make you change a value in a special way: through a setter, then they run your whole
component again and compare, or through a `.value` container they can watch.

Markless keeps `theme` a plain `let`. You write `theme = 'dark'`, your component never runs again,
and the change goes straight to the spots that show it.

</Collapsible>

<Code steps={[{ label: 'Press Dark.', shows: 'Theme: dark' }, { label: 'Add `<p>{theme}</p>` under the heading, and press Light. Both lines follow.', source: '<p>{theme}</p>' }, { label: "Change `state('light')` to a plain `'light'`, and read the build error.", source: "let theme = 'light'" }]}>
```tsrx title="settings.tsrx"
import { state } from '@markless/core';

export default function Settings() @{
	let theme = state('light');

	<main class={theme}>
		<h2>Theme: {theme}</h2>
		<p>{theme === 'dark' ? '🌙' : '☀️'}</p>
		<button onClick={() => (theme = 'light')}>
			Light
		</button>
		<button onClick={() => (theme = 'dark')}>
			Dark
		</button>
		<style>
			.dark {
				background: #222;
				color: #eee;
			}
		</style>
	</main>
}
```

## Any assignment counts

Change state the way you change any variable:

- `theme = 'dark'`, `count++` and `count += 2` all count.
- Objects change field by field. `user.visits++` changes the text that shows `user.visits`, and the
  text that shows `user.name` stays as it is.

```tsrx title="visitor.tsrx"
import { state } from '@markless/core';

export default function Visitor() @{
	let user = state({ name: 'Ada', visits: 0 });

	<section>
		<p>{user.name}</p>
		<button onClick={() => user.visits++}>Visits: {user.visits}</button>
	</section>
}
```

## Make state in the component body

Write `state()` directly in the component body, next to your other variables. Anywhere else, the
build stops and names the line:

- outside the component: `MARKLESS_STATE_MODULE_SCOPE`
- inside an `@if`, an event handler or a `for` loop: `MARKLESS_STATE_CREATION_SITE_UNSTABLE`
- changed inside the markup, as in `{count++}`: `MARKLESS_STATE_WRITE_IN_TEMPLATE`

`state()` only works in `.tsrx` files. In a plain `.ts` file it throws as soon as it runs.

[Computed](/concepts/computed) works out a value from your state, so it can never go stale.
