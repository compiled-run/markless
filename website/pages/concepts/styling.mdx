# Two components can both call it .card

<PageMeta time="3 min" assumes="state" />

<ThemeToggle />

A plain stylesheet is a shared room. You call something `.card`. Someone two folders away also calls
something `.card`. One of you loses, and it is whoever finds out last.

**Put a `<style>` block inside a component, and its rules reach that file's elements and nothing
else.**

## Two cards, one class name

<StylingSketch />

In the card above, switch on Show page classes. Each card carries one more class, and it comes from its own file.

Both cards in the code below use the class `card`. Both files say what `.card` looks like, and they
disagree. Press **Light it up** on the second card.

<Code note="In paper-card.tsrx, change the background to lightblue. Only the paper card turns blue, though chalk-card.tsrx also styles .card. Then press Light it up on the chalk card.">
```tsrx title="two-cards.tsrx"
import PaperCard from './paper-card.tsrx';
import ChalkCard from './chalk-card.tsrx';

export default function TwoCards() @{
	<div>
		<PaperCard />
		<ChalkCard />
	</div>
}
```

```tsrx title="paper-card.tsrx"
export default function PaperCard() @{
	<article class="card">
		<style>
			.card {
				padding: 0.6em 0.9em;
				border: 2px solid currentColor;
				background: lightyellow;
				color: black;
			}
		</style>
		<p>Paper card</p>
	</article>
}
```

```tsrx title="chalk-card.tsrx"
import { state } from '@markless/core';

export default function ChalkCard() @{
	let lit = state(false);

	<article class={lit ? 'card lit' : 'card'}>
		<style>
			.card {
				padding: 0.6em 0.9em;
				border: 2px dashed currentColor;
				background: darkslategray;
				color: white;
			}
			.lit {
				background: plum;
				color: black;
			}
		</style>
		<p>Chalk card</p>
		<button onClick={() => (lit = !lit)}>
			Light it up
		</button>
	</article>
}
```
</Code>

Each card keeps its own look. Neither card file mentions the other, and the order of the imports
does not matter. The button swaps the second card's class, and the scoped `.lit` rule takes over.

## The extra class

When Markless builds your app, it gives each file with a `<style>` block its own class, such as
`mk-1qak359`. The class comes from the file's path. Markless adds it to every selector in the block
and to every element the file renders.

So `.card` in the first file becomes `.card.mk-1qak359` in the stylesheet, and the article goes out
as `class="card mk-1qak359"`. The second file gets a different class. Its `.card` rule cannot match
the first file's article.

Rules inside `@media` get the class too. `@keyframes` names stay as you wrote them.

In a built app, the rules end up in an ordinary stylesheet that the page links to. No script runs to apply them.

## A class is a string

`class` takes a string. Any expression that makes one works, such as a `? :` or a template string.
The second card uses `lit ? 'card lit' : 'card'`, and the page updates the class when `lit` changes.

<Callout
	sprite="cross"
	title="Why does my class say [object Object]?"
	text="An object or an array is not a class string. Write class={{ lit: on }} and the page renders class='[object Object]'. An array such as ['card', on && 'lit'] renders as 'card,false'. Markless warns with MARKLESS_ATTRIBUTE_OBJECT_VALUE either way. If the value reads state, the build stops with MARKLESS_TEMPLATE_EXPRESSION_UNSUPPORTED. Build the string with a ? : instead."
/>

## One file, one class

The class belongs to the file, not to the component. Two components in one `.tsrx` file share one
class and one stylesheet. To give a component its own scope, move it to its own file.

A `<style>` block outside a function's elements never reaches the page. Markless warns with
`MARKLESS_PUBLIC_RENDER_UNSUPPORTED_CONSTRUCT`. For rules that cover the whole site, import an
ordinary stylesheet.
