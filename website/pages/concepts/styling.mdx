# Two components can both call it .card

<PageMeta time="3 min" assumes="state" />

<Subtitle text="Put a style block inside a component, and its rules reach that file's elements and nothing else." terms="elements" />

A plain stylesheet is a shared room. You call something `.card`, someone two folders away does
too, and one of you loses.

```tsrx title="paper-card.tsrx"
export default function PaperCard() @{
	<article class="card">
		<style>
			.card {
				background: lightyellow;
			}
		</style>
		<p>Paper card</p>
	</article>
}
```

The `<style>` block sits inside the component's elements. Its `.card` rule reaches this file's
`<article>`, and no other file's.

## Two cards, one class name

Both cards below write `class="card"`, in two different files. Press **Show classes** to read the
class each one really got.

<CardsDemo />

- Markless gives each file with a `<style>` block its own extra class, starting `mk-`.
- It adds that class to every selector in the block and to every element the file renders.
- So `.card` from one file becomes `.card.mk-…`, and can't match the other file's card.

## Style both cards

<Code steps={[{ label: 'In `paper-card.tsrx`, change the background to `lightblue`. Only the paper card turns blue.', source: 'background: lightblue' }, { label: 'In `chalk-card.tsrx`, change `plum` to `gold`, then press Light it up. Only the chalk card turns gold.', source: 'background: gold' }]}>
```tsrx title="two-cards.tsrx"
import PaperCard from './paper-card.tsrx';
import ChalkCard from './chalk-card.tsrx';

export default function TwoCards() @{
	<div>
		<PaperCard />
		<ChalkCard />
	</div>
}
```

```tsrx title="paper-card.tsrx"
export default function PaperCard() @{
	<article class="card">
		<style>
			.card {
				padding: 0.6em 0.9em;
				border: 2px solid currentColor;
				background: lightyellow;
				color: black;
			}
		</style>
		<p>Paper card</p>
	</article>
}
```

```tsrx title="chalk-card.tsrx"
import { state } from '@markless/core';

export default function ChalkCard() @{
	let lit = state(false);

	<article class={lit ? 'card lit' : 'card'}>
		<style>
			.card {
				padding: 0.6em 0.9em;
				border: 2px dashed currentColor;
				background: darkslategray;
				color: white;
			}
			.lit {
				background: plum;
				color: black;
			}
		</style>
		<p>Chalk card</p>
		<button onClick={() => (lit = !lit)}>
			Light it up
		</button>
	</article>
}
```
</Code>

Neither card file mentions the other, and the order of the imports doesn't matter.

## The rules you can rely on

- The extra class is worked out from the file's path.
- Rules inside `@media` get the class too. `@keyframes` names stay as you wrote them.
- In a built app the rules ship as plain CSS in the page. No script runs to apply them.
- The class belongs to the file, not the component. Two components in one `.tsrx` file share it.
  To give a component its own scope, move it to its own file.
- For rules that cover the whole site, import an ordinary stylesheet.

## A class is a string

`class` takes a string. Any expression that makes one works, like `lit ? 'card lit' : 'card'`, and
the page updates the class when `lit` changes.

Not yet:

- An object or an array, as in `class={{ lit: on }}`, stops the build with
  `MARKLESS_ATTRIBUTE_OBJECT_VALUE`. Build the string with `? :` instead.
- A `<style>` block outside a component's elements never reaches the page, so the build stops
  with `MARKLESS_PUBLIC_RENDER_UNSUPPORTED_CONSTRUCT`.

Scoped styles in single-file components work much the same way. You write the plain class name,
and the build adds one class per file to selectors and elements. In the inspector you see your
own class name next to the added one.
