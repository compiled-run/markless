# CI and the checks you run at home

<PageMeta time="2 min" assumes="nothing" />

<Subtitle text="pnpm ci:local reads .github/workflows/ci.yml each time it runs, so your machine runs the same commands CI does." />

```bash
pnpm ci:local --fast
```

## Check in at home

Press the boarding pass to check in again:

<CheckInFigure />

The four fast jobs run on your machine, and the pre-commit hook runs them too. Everything heavier runs on GitHub, where the pull request's green run is the proof.

## Each step lands in one of three groups

`scripts/ci/local.mjs` sorts every job's steps. Here is the `typecheck` job:

<SortStepsFigure />

- **check**: a `run:` step that tests something. It runs.
- **setup**: `pnpm install`, `corepack enable` and the Playwright installs. They run only with `--install`.
- **skip**: `uses:` actions, lane cache markers, and steps that read GitHub's own context.

A new job with check steps but no entry in the script's mode table makes it stop with an error naming the job.

## Security on GitHub, then the gate

<SecurityGateFigure />

The merge queue is the gate: `main` takes a change only from it.

The required checks are `test`, `typecheck` and `agent-files`. `test` is the gate: it fails unless every lane passed or hit its cache.

| Mode | Jobs |
| --- | --- |
| fast | `agent-files`, `typecheck`, `typecheck-ts7`, `unit` |
| full | `browser`, `completion-matrix`, the `boxes-*` jobs, `website-boxes`, `demo-boxes`, `perf-guards`, `build-scale`, `build-warnings`, `package-manager-matrix`, `test` |
| CI only | `benchmark`, `benchmark-guard` |

## Pick what to run

```bash
pnpm ci:local --list                            # every job and step, and its mode
pnpm ci:local --job browser --job boxes-router  # only these jobs
pnpm ci:local --fast --clean                    # in a throwaway worktree of HEAD
pnpm ci:local --dry-run                         # print the commands, run nothing
```

- `--clean` uses the committed tree, so an untracked file can't make a check pass.
- `--full` runs every job this machine can run. Use it to debug, not as proof.

## Never weaken a check

When a check fails, sort the failure first: environment drift, your regression, an older failure, or a flaky test. Then fix the cause.

- Don't skip, delete or loosen a test to make it pass.
- Don't add retries to Vitest, Playwright or the workflow.
- Move a perf guard's anchor only with `pnpm perf:guard:accept <guard> "<subject>" --reason "<one line>"`.
