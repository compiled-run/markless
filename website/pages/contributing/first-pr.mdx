# Your first pull request

<PageMeta time="2 min" assumes="nothing" />

<ThemeToggle />

<Subtitle text="A pull request is done when its CI run is green and every review finding has an answer." />

```bash
git switch -c fix/counter-text
```

Every change starts on its own branch. Then follow these steps in order.

## 1. Read the rules for your area

Read `AGENTS.md` first. Then read `specs/framework-design.md` and the one spec in `specs/framework/` that covers your change. For a UI component, also read `packages/headless/components/SPEC.md`.

## 2. Write the failing test first

Add or update the closest focused test. Run it, and check that it fails for the reason you expect:

```bash
pnpm exec vp test packages/compiler/test/semantic-graph.test.ts
```

Compiler tests check pass artifacts and diagnostics where they can. Component and browser behavior gets a Vitest browser-mode test.

## 3. Make the smallest change

Change only what the test needs, and run the test again until it passes.

## 4. Run the two checks

```bash
pnpm run typecheck
pnpm ci:local --fast
```

The first reads `.tsrx` files, which plain `tsc` can't. The second runs CI's fast jobs, `agent-files`, `typecheck`, `typecheck-ts7` and `unit`, with the commands from `ci.yml`. If you touched the bundler, router, web, runtime, compiler or demos, run the matching jobs too, like `pnpm ci:local --job browser --job boxes-router`.

## 5. Commit, and let the hook run

The `pre-commit` hook runs `vp lint --deny-warnings`, then the fast jobs with `--bail`. If you staged a file in `.ruler/`, it also checks that the generated agent files match. When lint fails, it prints the fix: `pnpm exec vp lint --fix --fix-suggestions --fix-dangerously`.

## 6. Open the pull request and answer every finding

Push your own branch and open a pull request. In it, say which `ci:local` mode you ran, on which commit, and the result line it printed.

- Read every finding, from people and from the CodeRabbit bot.
- Fix the ones that are right.
- Reply with your reason on the ones that are stale or wrong.

`main` takes changes only through its merge queue, once the required checks `test`, `typecheck` and `agent-files` pass. A merge or a push to a branch other people share needs the owner's go-ahead for that one change set.
