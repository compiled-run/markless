# Your first PR

<PageMeta time="2 min" assumes="nothing" />

<Subtitle text="A pull request is a branch you ask to merge into main, and it is done when its CI run is green and every review finding has an answer." />

```bash title="terminal"
git switch -c fix/chat-timestamps
pnpm run typecheck
pnpm ci:local --fast
git commit -m "Show the time on each chat message"
```

**`git switch -c`** starts your own branch. The two **checks** run before you commit, and the **commit** runs them again through the hook.

## The rules for your area come first

Read `AGENTS.md`, then `specs/framework-design.md` and the one spec in `specs/framework/` for your change. For a UI component, also read `packages/headless/components/SPEC.md`.

## A change starts with a failing test

Add or update the closest focused test, and check that it fails for the reason you expect:

```bash
pnpm exec vp test packages/compiler/test/semantic-graph.test.ts
```

- Compiler tests check pass artifacts and diagnostics where they can.
- Component and browser behavior gets a Vitest browser-mode test.
- Then change only what the test needs.

## Two checks run before you commit

`pnpm run typecheck` reads `.tsrx` files, which plain `tsc` can't. `pnpm ci:local --fast` runs CI's fast jobs with the commands from `ci.yml`.

- Touched the bundler, router, web, runtime, compiler or demos? Run the matching jobs too, like `pnpm ci:local --job browser --job boxes-router`.
- The `pre-commit` hook runs `vp lint --deny-warnings`, then the fast jobs with `--bail`.
- When lint fails, it prints the fix: `pnpm exec vp lint --fix --fix-suggestions --fix-dangerously`.

## Every finding needs an answer

A *finding* is a review comment, from a person or from the CodeRabbit bot. Open the pull request from your own branch, and say which `ci:local` mode you ran, on which commit, and the result line it printed. Press **Merge when ready** before you answer anything:

<ReviewFigure />

- Fix the findings that are right.
- Reply with your reason on the ones that are stale or wrong.
- `main` takes changes only through its merge queue, once `test`, `typecheck` and `agent-files` pass.
- A merge or a push to a shared branch needs the owner's go-ahead for that one change set.
