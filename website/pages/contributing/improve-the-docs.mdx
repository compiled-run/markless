# Improve the docs

<PageMeta time="3 min" assumes="nothing" />

<Subtitle text="This site is a Markless app in website/, so a framework change and the page that explains it land in one pull request." />

```bash title="terminal"
pnpm docs:dev       # dev server
pnpm docs:build     # production build into website/.output/
pnpm docs:preview   # serve the production build
```

**`docs:dev`** serves the site while you edit, and **`docs:build`** builds it the way readers get it. Run them from the repo root.

## A page's path is its address

A *page file* is an `.mdx` file in `website/pages/`. Move `state.mdx` to another folder, or click it to rename it:

<DocsExplorerFigure />

- `pages/concepts/state.mdx` is served at `/concepts/state`.
- A new page also needs its `nav.ts` entry, with a `title`, an `href`, an `icon` and a one-sentence `description`.

## Every page has the same shape

After its imports, each page opens with these, in order:

1. A `#` title in plain words that names the thing.
2. `<PageMeta time assumes />`, with `time` from the formula in `website/README.md`.
3. `<Subtitle text />`: one sentence that says what the thing is.
4. A small, real example, with its parts named in **bold** under it.

Then come `##` headings that state each idea, and limits go last.

## Each idea gets one visual

| The idea | Use |
| --- | --- |
| "Try it and change it" | A `<Code>` block with `steps` |
| "Press this and watch which spots change" | A textbook column |
| The one thing the page must make the reader believe | An ink figure, drawn with the `markless-anatomy` skill |
| A command to run | `<Commands kind>` or `<CommandStrip command>` |
| Facts to look up | A markdown table |
| A trap the reader will hit | One `<Callout>`, at most one per page |

## A Code block runs what the reader types

Wrap titled fences in `<Code>`; the build adds the import.

````txt
<Code steps={[{ label: 'Rename the button to `Captions`.', shows: 'Captions: off' }, { label: 'Start with them on.', source: 'state(true)' }]}>
```tsrx title="subtitles.tsrx"
import { state } from '@markless/core';

export default function Subtitles() @{
	let subtitles = state(false);

	<button onClick={() => (subtitles = !subtitles)}>Subtitles: {subtitles ? 'on' : 'off'}</button>
}
```
</Code>
````

A step ticks on `shows` (an element shows this text), `source` (the code contains it) or `rewrites` (one update rewrites that many places).

## Facts come from the source

Check every API name, flag and command against the Markless source, and leave out what you can't check. Then run:

```bash
pnpm --dir website run typecheck   # the .tsrx-aware checker over pages and components
pnpm run typecheck                 # the rest of the repo
pnpm ci:local --fast               # CI's fast jobs
```
