# Improve the docs

<PageMeta time="3 min" assumes="nothing" />

<Subtitle text="This site is a Markless app in website/, so a framework change and the page that explains it can land in one pull request." />

```bash
pnpm docs:dev       # dev server
pnpm docs:build     # production build into website/.output/
pnpm docs:preview   # serve the production build
```

Run these from the repo root, after `pnpm install`.

## A page's path is its address

<PathUrlFigure />

A new page also needs its `nav.ts` entry, with a `title`, an `href`, an `icon` and a one-sentence `description`. The rest lives here:

- `components/figures/<page>/`: the drawings and live demos.
- `components/docs/`: `Code`, `Callout`, `Collapsible`, `Subtitle` and `PageMeta`.
- `styles/global.css`: the tokens and the type scale.
- `AGENTS.md` and `README.md` in `website/`: the styling rules. Read them first.

## Every page has the same shape

<PageShapeFigure />

`time` comes from the formula in `website/README.md`, and `assumes` lists keys from the `concepts` map in `nav.ts`. Write for a reader who has never used a UI framework: short sentences, "you", and everyday examples.

## Pick one visual per idea

| The idea | Use |
| --- | --- |
| "Try it and change it" | A `<Code>` block with `steps` |
| "Press this and watch which spots change" | A textbook column |
| The one thing the page must make the reader believe | An ink figure, drawn with the `markless-anatomy` skill |
| A command to run | `<Commands kind>` or `<CommandStrip command>` |
| Facts to look up | A markdown table |
| A trap the reader will hit | One `<Callout>`, at most one per page |

## Code the reader can edit

Wrap titled fences in `<Code>`. The page needs no import, because the build adds it.

````txt
<Code steps={[{ label: 'Rename the button to `Done`.', shows: 'Done' }, { label: 'Start at `3` instead of `0`.', source: 'state(3)' }]}>
```tsrx title="tally.tsrx"
import { state } from '@markless/core';

export default function Tally() @{
	let fixed = state(0);

	<button onClick={() => fixed++}>Typos fixed: {fixed}</button>
}
```
</Code>
````

Each step ticks itself on `shows` (an element shows this text), `source` (the code contains it) or `rewrites` (one update rewrites that many places). The starter must build, or the site build stops.

## Check the facts, then the page

Check every API name, flag and command against the Markless source. If you can't check a fact, leave it out. Then run:

```bash
pnpm --dir website run typecheck   # the .tsrx-aware checker over pages and components
pnpm run typecheck                 # the rest of the repo
pnpm ci:local --fast               # CI's fast jobs
```
