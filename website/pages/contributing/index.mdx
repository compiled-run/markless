# A tour of the Markless repo

<PageMeta time="3 min" assumes="nothing" />

<Subtitle text="Most packages form one pipeline: one half reads your .tsrx files before your app runs, and the other half runs the result wherever you pick." />

```txt
Counter.tsrx  →  compiler, bundler  →  web, runtime, serializer  →  a browser, a server, a build step or a test
```

Each list below gives the package, its folder, its job, and the other Markless packages its `src/` imports.

## Compile time

These packages do their work before your app runs.

- **`@markless/compiler`** in `packages/compiler`. Reads `.tsrx` and plans it: semantic graph, state lowering, payload planning, emit. Imports `serializer`.
- **`@markless/bundler`** in `packages/bundler`. Runs the compiler inside Vite or Rolldown. Build-time prerendering lives here too, as a preview. Imports `compiler`, `serializer` and `web`.
- **`@markless/typescript-plugin`** in `packages/typescript-plugin`. Gives editors `.tsrx` support, and holds the repo's `src/tsc.ts` checker. Imports `compiler`.

The compiler doesn't import `web`, but the code it writes does: compiled components import helpers from `@markless/web/fns/*`.

## Render anywhere

These packages run the compiled plan in whichever place you pick.

- **`@markless/web`** in `packages/web`. Renders and resumes for the web: `render` in a browser, `renderToString` and `renderToStream` for HTML. Imports `runtime` and `serializer`.
- **`@markless/runtime`** in `packages/runtime`. The state graph: reads, writes, computed values and the flush journal. Imports `serializer`.
- **`@markless/serializer`** in `packages/serializer`. Value serialization and the payload protocol types. Imports nothing.
- **`@markless/core`** in `packages/core`. The one import for apps: `state`, `computed`, `shared`, `element` and `storage`, plus `render`, `renderToString` and the Vite plugin. Imports `web`, `bundler` and `router`.

A server render and a browser render are two phases of one runtime, and it lives in `web`. That's why there's no `packages/server`. The protocol types live in `serializer`, so there's no `packages/protocol` either.

## Apps with many pages

- **`@markless/router`** in `packages/router`. File routes, navigation in the page and streaming, built on Nitro. Imports `bundler`, `compiler` and `web`.
- **`create-markless`** in `packages/cli`. Creates apps from the `minimal`, `app`, `docs` and `full-stack` starters, which all use the router. Imports nothing.

## Tools around the pipeline

- **`@markless/vitest-browser`** in `packages/vitest-browser`. Renders components inside Vitest browser tests. Imports `core` and `web`.
- **`@markless/analyzer`** in `packages/analyzer`. Checks browser evidence from a running app against its route and action policy. Imports nothing.
- **`@markless/ui`** in `packages/headless/components`. Headless, accessible UI components. Imports `core`, `icons` and `ui-tools`.
- **`@markless/icons`** in `packages/headless/icons`. Icon packs as `<pack.icon />` tags, inlined at build time. Imports nothing.
- **`@markless/ui-tools`** in `packages/headless/tools`. Build tools for the UI packages. Imports `icons`.

No package imports one that depends on it, so `web`, `runtime` and `serializer` never import `core`.

## Everything else

- `specs/` holds the behavior contract. Start at `specs/framework-design.md`.
- `demos/` holds demo apps, such as `todomvc`, `music-player` and `js-framework-benchmark`.
- `poc/fixtures/proofs/` holds proof fixtures, including the native `ios-native-rendering-target` and `macos-native-rendering-target`. They are design evidence, not production code.
- `scripts/` holds `ci/local.mjs`, the release scripts and the benchmark tools.
- `docs/` holds `ci-process.md` and the CI failure history.
- `.ruler/` holds the source of the agent rules and skills.
- `website/` holds this site.

Skip `goals/`, `dist/` and `.witness/` while you read. `CONTRIBUTING.md` lists them as local or generated output.

[Dev setup](/contributing/dev-setup) gets every package building on your machine.
