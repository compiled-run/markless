# Specs and rules

<PageMeta time="2 min" assumes="nothing" />

<Subtitle text="Specs and rules are two folders: specs/ says how Markless behaves, and .ruler/ says how people and AI agents work in the repo." />

```text title="markless/"
specs/framework-design.md
specs/framework/03-state-graph.md
specs/router/
.ruler/AGENTS.md
.ruler/skills/markless-implementation/
```

**`specs/framework-design.md`** is the index of the behavior contract, and each file in **`specs/framework/`** owns one area. **`.ruler/`** holds the rules and skills every agent and contributor follows.

## `specs/` is the behavior contract

A *spec* says what Markless must do, in words a test can check.

- `specs/framework-design.md` is the index. Read it first.
- `specs/framework/00-overview.md` to `14-emission-codegen-migration.md` each own one area, such as `07-diagnostics.md`.
- `specs/framework/08-deferred-decisions.md` lists the topics that stay open on purpose.
- `specs/router/` covers routing, typed routing and the router CLI.
- `specs/framework/archive/` is history, not the current contract.

## A spec edit follows one skill

Follow `.ruler/skills/markless-spec-maintenance/spec.md`:

- Keep accepted decisions, unless your task reopens them.
- Record an open topic as deferred. Don't decide it in passing.
- Write behavior a test can check, not storage shapes or exact compiler output.
- Check TSRX syntax with the TSRX MCP server, or `tsrx.dev/specification`, and record which.
- Run `git diff --check` before you finish.

## `.ruler/` is the one source for the rules

`pnpm rules` runs `ruler apply`, which writes `AGENTS.md`, `CLAUDE.md`, the skill copies and the MCP configuration from `.ruler/`. Add a rule to `.ruler/AGENTS.md`, press **pnpm rules**, then edit `AGENTS.md` by hand:

<ExplorerFigure />

- Never edit the outputs by hand: the `agent-files` CI job fails if they drift from `.ruler/`.
- After you edit `.ruler/`, run `pnpm rules` and commit what it writes.

## A few rules apply everywhere

- Run `pnpm run typecheck` and `pnpm ci:local --fast` before you call a change done.
- Write the test first. Run the narrowest failing test, then make the smallest change.
- Never run components again in the browser over server HTML. No virtual DOM, and no second build stack besides Rolldown and Vite.
- Keep compiler, runtime, serializer and render code free of Node-only APIs.
- Import protocol and config facts from the package that owns them. Don't copy them as literals.
- A merge, or a push to `main` or any shared branch, needs the owner's go-ahead for that one change set.
- A pull request stays open until every review finding, CodeRabbit's too, has an answer.
- Comments are a last resort: one short line, only for a fact the code can't show.
