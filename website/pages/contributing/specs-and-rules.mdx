# Specs and rules

<PageMeta time="2 min" assumes="nothing" />

<Subtitle text="Two folders steer the repo: specs/ says how Markless behaves, and .ruler/ is the source of every agent's instructions." />

```text title="markless/"
specs/framework-design.md
specs/framework/03-state-graph.md
.ruler/AGENTS.md
AGENTS.md
CLAUDE.md
```

**`specs/`** holds the behavior contract, one file per area. **`.ruler/AGENTS.md`** is the source; **`AGENTS.md`** and **`CLAUDE.md`** are written from it.

## Two folders, two plain rules

Step through them:

<ExplorerFigure />

- Change how Markless behaves, and change its spec in the same pull request. Start at `specs/framework-design.md`, the index.
- `specs/framework/08-deferred-decisions.md` lists the topics left open on purpose, and `specs/framework/archive/` is history, not the contract.
- Never edit `AGENTS.md` or `CLAUDE.md`. Edit `.ruler/`, run `pnpm rules`, and commit what it writes. The pre-commit hook checks this too when you stage a `.ruler/` file.

<Callout
	sprite="cross"
	title="Specs are not proof"
	text="A spec can drift from the code. When they disagree, the code and its tests show what Markless does today."
/>

## A spec edit follows one skill

Follow `.ruler/skills/markless-spec-maintenance/spec.md`. In short: keep accepted decisions, record open topics as deferred, and write behavior a test can check.

## A few rules apply everywhere

- Run `pnpm run typecheck` and `pnpm ci:local --fast` before you call a change done.
- Write the test first, then make the smallest change.
- Keep compiler, runtime, serializer and render code free of Node-only APIs.
- A pull request stays open until every review finding, Macroscope's too, has an answer.
