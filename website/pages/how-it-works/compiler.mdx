# What the compiler writes for the cart

<PageMeta time="3 min" assumes="state, events" />

<Subtitle text="The compiler turns one .tsrx file into small separate pieces: one function per event and per update, a record that ties them to elements, and two render modules." />

```tsrx title="cart.tsrx"
import { state } from '@markless/core';

export default function Cart() @{
	let bags = state(0);

	<section>
		<p>In your cart: {bags} bags</p>
		<button onClick={() => bags++}>Add to cart</button>
	</section>
}
```

Every excerpt on this page is the real output of `compileTsrxModule()` from `@markless/compiler` for this file. Each excerpt is a slice of one output, and only the line breaks in the JSON were added.

## A chain of passes

A *pass* is one small step with named inputs and named outputs. Each pass reads what earlier passes wrote and adds its own. Before any pass runs, the compiler checks the chain: a missing input, two passes writing the same output, or a cycle stops the compile with `MARKLESS_COMPILER_PASS_GRAPH_INVALID`.

The first pass parses the file and runs the analyzer over it, then writes the *semantic graph*: every piece of state, element, read and write in the file, with what each one means. The chain, in the order it runs:

Each file compiles on its own. The bundler then links the files: it joins each import to the component it renders and works out which code each page's first interactions need.

## The click became a symbol

A *symbol* is one function with a stable ID, in a module of its own. The click became `symbol:0`, and `bags++` became an update to the graph node `state:bags`:

```js title="symbol:0"
import { marklessWriteScalar } from "@markless/web/fns/write-scalar";
/* scalar leaf marker: context.graph.update({ */
export function symbol_0(context) {
  return marklessWriteScalar(context, { graphNodeId: "state:bags", returnValue: "next", update(value) {
    return Number(value) + 1;
  } });
}
```

The text became `symbol:1`. It returns one instruction, set the text of one element:

```js title="symbol:1"
export function symbol_1(context) {
  return { type: "setText", locator: context.domUpdate?.hostNodeId ?? "h1", value: "In your cart: " + (context.value == null ? "" : String(context.value)) + " bags" };
}
```

`h1` is a *host node ID*, the compiler's name for the paragraph. A *locator* is the record that finds that element again in a real page.

## The view record ties them together

A click on `h2`, the button, runs `symbol:0`. A change to `state:bags` runs `symbol:1` against `h1`. The `section` gets no locator, because nothing on it changes or listens.

```json title="view record"
{
  "version": 1,
  "locators": [
    { "hostNodeId": "h1", "strategy": "dom-order", "index": 1, "tagName": "p" },
    { "hostNodeId": "h2", "strategy": "dom-order", "index": 2, "tagName": "button" }
  ],
  "events": [{ "hostNodeId": "h2", "eventName": "click", "symbolIds": ["symbol:0"] }],
  "domUpdates": [
    {
      "hostNodeId": "h1",
      "source": "bags",
      "graphNodeId": "state:bags",
      "path": [],
      "target": { "kind": "text", "prefix": "In your cart: ", "suffix": " bags" },
      "symbolId": "symbol:1"
    }
  ],
  "behaviors": [],
  "elementHandles": [],
  "keyedRepeats": [],
  "branches": [],
  "asyncBoundaries": []
}
```

The state record beside it holds one cell: `state:bags`, a scalar, starting at `0`.

## Two render modules

The server module defines `marklessRenderSsr`. It renders the cart to HTML and fills in both records. [The payload](/how-it-works/payload) shows what it sends.

For a component this simple, the browser module is a *direct module*. It never starts the full runtime:

```js title="browser module"
export function Cart() {
	const graph = createMarklessPublicGraph();
	const root = renderMarklessDirectChunk(graph, loadSymbol);
	return { root, graph, runtime: { async dispatch() {} } };
}
```

`createMarklessPublicGraph()` sits in the same module and keeps the state in a plain `Map`, seeded at compile time: `new Map([["state:bags", 0]])`. `renderMarklessDirectChunk` clones the elements from a template, fills in the text, and puts a click listener on the button itself.

The compiler writes a direct module only when it can prove the simple path covers the whole component. Each of these, among others, sends a component down the general path:

- props, or a child component
- a scoped `<style>`
- a `computed()`, `shared()`, an element handle or an `attach={...}` behavior
- an async block
- more than one root element
- a dynamic attribute other than `class`

[Resuming](/how-it-works/resuming) follows the first click down each path.
