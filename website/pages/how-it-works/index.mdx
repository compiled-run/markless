# Design choices

<PageMeta time="2 min" assumes="state, events" />

<Subtitle text="Markless decides how each page works when you compile it, for any device, and picks it up in the browser on the first interaction." terms="compile" />

```tsrx title="weather.tsrx"
import { state } from '@markless/core';

export default function Weather() @{
	let unit = state('Celsius');

	<p>Showing: {unit}</p>
}
```

**`unit`** is a value the page watches, and **`{unit}`** is the one spot that shows it. Before this file runs anywhere, the compiler knows both. Reading code for what it means, not only for how it is spelled, is called semantic analysis.

## The analyzer maps the whole project at compile time

The compiler's *analyzer*, built on yuku, reads every `.tsrx` file for its names and references:

- each file becomes a plan: its values, the spots that read them, and the code each event runs
- a link step joins the plans into one map of the project
- the bundler packs each page's code from that map

## The browser does less work

Flip the switch, then press **Get Started**:

<CoverageAnatomy />

- The [shadcn/ui home page port](https://github.com/compiled-run/markless#migrate-an-existing-app) executes 131 kB of JavaScript at load, down from 1,403 kB.
- The original runs its components again in the browser to attach their events. Markless decided that at compile time.
- On the compile-time side, a click adds one row: that button's own code, run only then.

## The page resumes instead of starting over

When a server renders the page, its HTML arrives already wired. The browser doesn't run your components again; code loads only when an event needs it. [Resuming](/how-it-works/resuming) shows the first press.

## What it costs

- A handler can read only what crosses to the browser: state, element handles, props, imports and constants.
- State sent from a server must be data, not functions.
- Components live in `.tsrx` files, which need the Markless compiler and `@markless/typescript-plugin`.
- Native screens are early proofs. The web is what ships.

The rows for other projects come from their public docs. They compare mechanisms, not speed.

| | How you write a value | On update | Effect API | Over server HTML |
| --- | --- | --- | --- | --- |
| React | `useState` and a setter | Runs the component again, then diffs a virtual DOM | `useEffect` | Runs components again |
| Solid | `createSignal`, read as `count()` | Signals write the DOM | `createEffect` | Runs components again |
| Svelte 5 | The `$state` rune | Compiled signals | `$effect` | Runs components again |
| Qwik | `useSignal`, read as `.value`, with `$` on lazy code | Signals | `useTask$` | Resumes |
| Markless | `state('Celsius')`, then plain `unit` | Writes the compiler planned | None | Resumes |
