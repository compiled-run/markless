<Subtitle text="At build time the analyzer maps your whole project, so Markless can plan every update for any environment and resume the page only when someone uses it." />

```tsrx title="cart.tsrx"
import { state } from '@markless/core';

export default function Cart() @{
	let bags = state(0);

	<section>
		<p>In your cart: {bags} bags</p>
		<button onClick={() => bags++}>Add to cart</button>
	</section>
}
```

Before this file runs anywhere, the compiler knows that `bags` is state, that one text shows it, and that the click changes it. Reading code for what it means, not only for how it is spelled, is called semantic analysis.

This section is for contributors and agents who want to weigh the design. You don't need it to ship an app.

## The analyzer maps the whole project at build time

The compiler's analyzer, built on yuku, reads every `.tsrx` file for its scopes, names and references. From that it maps the project:

- Each file becomes a plan: its state, the text and attributes that read it, and the code each event runs.
- A link step joins the plans: which component renders which, and which code each page's first interactions need.
- The bundler packs each page's code from that map.

[The compiler](/how-it-works/compiler) shows the plan for the cart, line by line.

## One plan, every environment

The same compiled component renders in the browser, on a server and in tests. [The big idea](/how-it-works/the-big-idea) lists the call for each one. Native screens are early proofs: iOS and macOS drive real buttons from a hand-written plan, and the compiler doesn't write that plan yet.

## The page resumes instead of starting over

When a server renders the page, its HTML arrives already wired. The browser does not run your components again. It reads the records the server wrote, and code loads only when an event needs it. [Resuming](/how-it-works/resuming) follows the first click.

## What it costs

For the cart above, built as a one-page `@markless/router` app and measured in Chromium (uncompressed, main at `2efb1c6e2`):

- **Executed at load:** 8.4 kB, four small inline scripts and the router's link script.
- **Downloaded at load, not executed:** 23.6 kB, the code the first click needs, fetched at low priority.
- **Executed on the first click:** that same 23.6 kB. Nothing new downloads.

On a whole site, the [shadcn/ui home page port](https://github.com/compiled-run/markless#migrate-an-existing-app) executes 131 kB of JavaScript at load, down from 1,403 kB in the original.

The design also has limits:

- A handler can read only what the compiler can find again later: state, element handles, props, imports and plain constants. Anything else fails with `MARKLESS_EVENT_HANDLER_EMIT_UNSUPPORTED`.
- State a server sends must be data. A function fails with `MARKLESS_SERIALIZE_UNSUPPORTED_VALUE`.
- Components live in `.tsrx` files, which need the Markless compiler to build and `@markless/typescript-plugin` to type-check.
- Rendering pages at build time is a preview behind `MARKLESS_PRERENDER=1`, with no public option.
