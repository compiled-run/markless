# What a server sends

<PageMeta time="2 min" assumes="state, events" />

<Subtitle text="When a server renders a page, it sends finished HTML plus a small payload of data, so the browser can carry on without running your components." terms="payload" />

```tsrx title="calendar.tsrx"
import { state } from '@markless/core';

export default function Calendar() @{
	let day = state(13);

	<p>Booked: March {day}</p>
}
```

**`<p>Booked: March 13</p>`** arrives as plain HTML. **`day`** arrives as data, so the browser knows `13` is a value that can change.

## The page is real HTML

Hover the page, press a day, then switch JavaScript off:

<SourceAnatomy />

- Every element is plain HTML, so the page shows in full even with JavaScript off.
- An element with a handler carries `m:on`, naming its handler's record.
- The first click fetches one small chunk of click code. The data itself never runs.

## The two blocks are data

Everything the server adds to your HTML is the *payload*. It's two script tags that hold JSON, not code:

- **`markless/state`** holds the values: `state:day` is `13`.
- **`markless/view`** says which element does what: the paragraph shows `state:day`, and each button's click runs its own symbol.

Here is the real response of `renderToString()` for the full calendar, with the two inline scripts and the file names cut:

```html title="response"

<script>…</script>
<div data-async-container data-markless-paths="…">
```

## Only pages that can react get a payload

- Values must be data: `@markless/serializer` refuses a function with `MARKLESS_SERIALIZE_UNSUPPORTED_VALUE`.
- A page with nothing to react to gets no scripts at all, just `<div data-async-container>` and its HTML.
- In the browser alone, `render()` keeps the same records in memory and writes none of these scripts.

[Resuming](/how-it-works/resuming) shows what the browser does with them on the first press.
