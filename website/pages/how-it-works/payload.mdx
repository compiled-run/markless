# What a server writes into its HTML

<PageMeta time="2 min" assumes="state, events" />

<Subtitle text="A server adds the state values and which element does what to its HTML, so the browser can carry on without running your components." />

Everything the server adds is called the *payload*. It applies only when a server renders the page, with `renderToString()`, `renderToStream()` or `@markless/router`. In the browser alone, `render()` keeps the same records in memory and writes none of these scripts.

## The real response

Here is the whole response of `renderToString()` for the [cart](/how-it-works/compiler), built with the Markless Vite plugin. The inline script bodies and the chunk file names are cut to `…`, and line breaks are added:

```html title="response"
<link rel="modulepreload" href="/build/chunk-….js" crossorigin="anonymous" fetchpriority="high">
<script>(function captureEarlyEvents(eventNames) { … })(["click"]);</script>
<div data-async-container data-markless-paths="7section,p,button|010001011112|42|ksjuku">
  <section><p>In your cart: 0 bags</p><button m:on="click:0">Add to cart</button></section>
  <script type="markless/state">{"version":1,"cells":[{"graphNodeId":"state:bags","name":"bags","valueKind":"scalar","value":{"version":1,"root":0,"records":[]}}],"computed":[],"sharedDefinitions":[]}</script>
  <script type="markless/view">{"version":1,"locators":[{"hostNodeId":"h1","strategy":"dom-order","index":2,"tagName":"p"},{"hostNodeId":"h2","strategy":"dom-order","index":3,"tagName":"button"}],"events":[{"hostNodeId":"h2","eventName":"click","symbolIds":["symbol:0"]}],"domUpdates":[{"hostNodeId":"h1","graphNodeId":"state:bags","path":[],"target":{"kind":"text","prefix":"In your cart: ","suffix":" bags"},"symbolId":"symbol:1"}],"behaviors":[],"elementHandles":[],"keyedRepeats":[],"branches":[],"asyncBoundaries":[]}</script>
  <script data-async-resumer data-markless-resume-module="/build/chunk-….js">…</script>
</div>
```

Read it top to bottom:

- **The `link`** fetches the resume module early. Fetching it does not run it.
- **The first script** records events that fire while the document is still loading.
- **The container `div`** marks the part of the page this render owns. `data-markless-paths` records how many elements the server wrote and where each one sits, so the browser can tell when another script has changed the page.
- **`m:on="click:0"`** says the button has a click handler, and that its record is number `0` in the view record. The browser reads it straight off the pressed element.
- **`markless/state`** holds the state: `state:bags` is `0`.
- **`markless/view`** holds the locators, the events and the text update.
- **The last script** is the *inline resumer*. It waits for the first interaction.

The locator `index` is `2` here and `1` in the compiler's own output, because the server counts the container `div` as element `0`.

## How a value travels

In `"value":{"version":1,"root":0,"records":[]}`, `root` holds the number `0` itself. An object or an array goes into `records`, and `root` points at it. An object that shows up twice is written once, and both places point at the same record.

- Values must be data. `@markless/serializer` refuses a function with `MARKLESS_SERIALIZE_UNSUPPORTED_VALUE`.
- Both scripts hold plain `JSON.stringify` output. The serializer escapes only `</` and `<!`, the two sequences that could end the script tag early.

## A page with nothing to react to

Render the same paragraph with no button, and this is the whole response:

<MugSpot mood="proud" from="left" />

```html title="response"
<div data-async-container><p>In your cart: 0 bags</p></div>
```

No state script, no view script and no inline resumer. If nothing on the page can react, the browser has nothing to wake up.

Pages rendered at build time, a preview, write a different payload, and this page doesn't cover them.
