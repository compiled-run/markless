# Resuming

<PageMeta time="2 min" assumes="state, events" />

<Subtitle text="Markless works the page out ahead of time, so the browser can resume mid-game on your first press instead of running your components again." terms="resume" />

```tsrx title="like.tsrx"
import { state } from '@markless/core';

export default function Like() @{
	let liked = state(false);

	<button onClick={() => (liked = !liked)}>
		{liked ? 'Liked' : 'Like'}
	</button>
}
```

**`liked`** arrives with the page as data, and **`onClick`** arrives as a name, not as code. The first press loads just that handler and runs it. `Like()` itself never runs again.

## The page arrives mid-game

Press the board for the next move, or drag a piece:

- The position was worked out ahead of time, so the next move is the only work.
- Nothing is set up again from move one.
- An illegal move slides back, the way a handler only does what its code says.

## Three ways in

Who hears the first press depends on how the page was made:

| | Browser, direct module | Browser, general path | Server-rendered page |
| --- | --- | --- | --- |
| Who builds the elements? | The compiled module | Markless, from the compiled output | The server |
| Who listens? | Each element with an event | The container, one listener per event name | The inline resumer, on the container |
| What starts on the first click? | That click's symbol | Its symbols, the state graph and the full runtime | The resume module, then only what it needs |

## On a server-rendered page

- Each element with a handler carries an `m:on` attribute. A tiny inline script reads it off the pressed element.
- The press loads the page's *resume module*. If the compiler specialized the page's events and text updates, the full runtime never starts.
- A press during loading is replayed in order, and a pointer or focus landing on a handler loads its code early.
