# One write wakes only its readers

<PageMeta time="2 min" assumes="state, computed, events" />

<Subtitle text="The compiler writes down who reads what before the page exists, so a write reaches only the spots that read it." />

<PlaylistAnatomy />

Pick a song. The value `playing` is ruled to the two spots that read it, so only those two change. The title reads nothing, so nothing ever redraws it.

```tsrx title="playlist.tsrx"
import { state } from '@markless/core';

export default function Playlist() @{
	let playing = state('Harbour Lights');

	<section>
		<h2>Road trip</h2>
		<p>Now playing: {playing}</p>
		<button
			class={playing === 'Slow Train' ? 'on' : ''}
			onClick={() => (playing = 'Slow Train')}
		>
			Slow Train
		</button>
	</section>
}
```

## The rules are the state graph

- A **node** holds one value: `state()` makes `state:playing`, and `computed()` makes a node of its own.
- A **subscription** is one ruled line: a node, a path into its value, and a small function to run when it changes.
- The **journal** is the list of page changes those functions return: here a `setText` for the paragraph and a class update for the button. The compiler reads the class through a small computed node it adds on its own.

## One write, two readers

For `playing = 'Slow Train'`, the graph in `@markless/runtime`:

1. stops if the value didn't change,
2. marks `state:playing` changed, and any computed that reads it stale,
3. schedules one flush right after the current code,
4. runs only the subscriptions ruled to it, and applies the journal entries they return.

Two writes in the same turn share one flush. A write to `song.title` doesn't reach a reader of `song.artist`; replacing `song` reaches both.

Not on this path:

- A component on the [direct module](/how-it-works/compiler) keeps a plain `Map` instead, and rewrites only the text that changed.
- `@markless/core` has no effect function. The compiler plans every subscription.
