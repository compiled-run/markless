# The state graph

<PageMeta time="2 min" assumes="state, computed, events" />

<Subtitle text="The state graph is a map, written at compile time, of which values each spot on the page reads." terms="state values" />

```tsrx title="player.tsrx"
import { computed, state } from '@markless/core';

const SONGS = ['Harbour Lights', 'Slow Train', 'Northbound'];

export default function Player() @{
	let playing = state('Harbour Lights');
	let liked = state(new Set<string>());
	let volume = state(6);
	const isLiked = computed(() => liked.has(playing));
	const title = computed(() => playing.toUpperCase());
	const cover = computed(() => '/covers/' + playing + '.jpg');

	<section>
		<h2>{title}</h2>
		<button
			class={isLiked ? 'heart on' : 'heart'}
			onClick={() => (liked = new Set([...liked, playing]))}
		>
			♥
		</button>
		<ul>
			@for (const song of SONGS; key song) {
				<li
					class={song === playing ? 'row on' : 'row'}
					onClick={() => (playing = song)}
				>
					{song}
				</li>
			}
		</ul>
		<img src={cover} alt="" />
		<label>
			Volume {volume}
			<input
				type="range"
				max="10"
				onInput={(e) => (volume = Number(e.target.value))}
			/>
		</label>
	</section>
}
```

**`playing`**, **`liked`** and **`volume`** are values the page watches. **`isLiked`** reads two of them, and **`title`** and **`cover`** read one. Each spot in the markup that reads a value gets an edge from it, so one value can feed many spots, and one spot can depend on many values.

## You build the graph by building the page

The compiler turns each `state()` and `computed()` into a *node*, and each spot that reads one into a *subscription*, drawn as an edge. Drag pieces onto the page, then pick a song, like it, or turn the volume:

<GraphAnatomy />

- Each piece brings its computed value and its spot, with edges from every value they read. The heart brings `isLiked`, which reads both `liked` and `playing`.
- The heading reads nothing, so it never gets a node.
- A write travels only its own branch: liking a song never touches the header or the cover. Drag a reader off again and a song pick reaches fewer spots.

## A write runs only its own path

When `playing` changes, `@markless/runtime`:

1. marks `state:playing` changed, and any computed that reads it stale,
2. waits for the current code to finish, then runs one *flush*,
3. runs only the subscriptions on that path and applies the page changes they return.

```tsrx title="player.tsrx"
import { state } from '@markless/core';

export default function Player() @{
	let playing = state('Harbour Lights');

	<p>Now playing: {playing}</p>
}
```
</Code>

- Two writes in the same turn share one flush.
- A write to `song.title` doesn't reach a reader of `song.artist`; replacing `song` reaches both.
- `@markless/core` has no effect function. The compiler plans every subscription.
