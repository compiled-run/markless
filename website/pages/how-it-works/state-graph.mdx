# One write wakes only its readers

<PageMeta time="2 min" assumes="state, computed, events" />

<Subtitle text="The compiler writes down who reads what before the page exists, so a write reaches only the text that reads it." />

<RoundAnatomy />

Press the drawing to print a new edition of `bags`. It goes only to the houses on its round, and the house with no round gets nothing.

```tsrx title="cart.tsrx"
import { computed, state } from '@markless/core';

export default function Cart() @{
	let bags = state(2);
	const total = computed(() => bags * 14);

	<section>
		<p>House blend · 250 g</p>
		<p>In your cart: {bags} bags</p>
		<p>Total: ${total}</p>
		<button onClick={() => bags++}>Add to cart</button>
	</section>
}
```

## The round book is the state graph

- A **node** holds one value: `state()` makes `state:bags`, and `computed()` makes `computed:total`.
- A **subscription** is one house on a round: a node, a path into its value, and a small function to run when it changes.
- The **journal** is the list of page changes those functions return, such as `setText`.

## One write, one round

For `bags++`, the graph in `@markless/runtime`:

1. stops if the value didn't change,
2. marks `state:bags` changed and `computed:total` stale,
3. schedules one flush right after the current code,
4. runs only the subscriptions on that round, and applies the journal entries they return.

Two writes in the same turn share one flush. A write to `order.grind` doesn't reach a reader of `order.bags`; replacing `order` reaches both.

Not on this path:

- A component on the [direct module](/how-it-works/compiler) keeps a plain `Map` instead, and rewrites only the text that changed.
- `@markless/core` has no effect function. The compiler plans every subscription.

[Lazy chunks](/how-it-works/lazy-chunks) shows where those small functions live.
