# The state graph

<PageMeta time="2 min" assumes="state, computed, events" />

<Subtitle text="The state graph is a list, written at compile time, of which values each spot on the page reads." terms="state values" />

```tsrx title="player.tsrx"
import { state } from '@markless/core';

export default function Player() @{
	let playing = state('Harbour Lights');

	<p>Now playing: {playing}</p>
}
```

**`playing`** is a value the page watches. **`{playing}`** is a spot that reads it, so the compiler draws an edge from one to the other. A spot that reads nothing gets no edge.

## You build the graph by building the page

The compiler turns each `state()` into a *node*, and each spot that reads one into a *subscription*, drawn as an edge. Drag pieces onto the page, then pick a song:

<GraphAnatomy />

- The label and the cover read `playing`, so each one inks an edge as it lands.
- The heading reads nothing, so it never gets an edge.
- Drag a reader off again: its edge is erased, and one write makes fewer updates.

## A write runs only its own path

When `playing` changes, `@markless/runtime`:

1. marks `state:playing` changed, and any computed that reads it stale,
2. waits for the current code to finish, then runs one *flush*,
3. runs only the subscriptions on that path and applies the page changes they return.

```tsrx title="player.tsrx"
import { state } from '@markless/core';

export default function Player() @{
	let playing = state('Harbour Lights');

	<p>Now playing: {playing}</p>
}
```
</Code>

- Two writes in the same turn share one flush.
- A write to `song.title` doesn't reach a reader of `song.artist`; replacing `song` reaches both.
- `@markless/core` has no effect function. The compiler plans every subscription.
