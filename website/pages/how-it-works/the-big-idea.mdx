	let bags = state(0);

		<button onClick={() => bags++}>
			Add to cart
		</button>
	</section>

## Decided before anything runs

From that file, the compiler works out three things:

1. **The state.** `bags` becomes a node in a graph, with the ID `state:bags`.
2. **The update.** The text `In your cart: {bags} bags` becomes one planned text write.
3. **The event code.** The click becomes a *symbol*, `symbol:0`: one function with a stable ID that the browser can load on its own.

The same compile writes two render modules: one builds the cart in a browser, the other renders it to HTML on a server. [The compiler](/how-it-works/compiler) prints both.

## Rendered where you need it

The compiled component is the same in each environment:

| Environment | How you call it | What it is good for |
| --- | --- | --- |
| Browser | `render(App, { target })` from `@markless/core` | A plain Vite app with no server at all |
| Server | `renderToString()` from `@markless/core`, or `renderToStream()` from `@markless/web/render-to-stream` | HTML that is ready when it arrives |
| Multi-page app | `@markless/router` | File routes on Nitro, which deploys to many hosts |
| Tests | `render()` and `renderSSR()` from `@markless/vitest-browser` | Browser tests, with or without a server render first |
| Build time | `MARKLESS_PRERENDER=1` in the repo's demos | A preview, with no public option yet |
| iOS and macOS | See [native targets](/how-it-works/native-targets) | Hand-written proofs, not wired to the compiler |

A browser-only app needs an `index.html` with a `<div id="app">`, a `vite.config.ts` that adds `markless()` from `@markless/core/vite`, and this:

```ts title="main.ts"
import { render } from '@markless/core';
import App from './App.tsrx';

await render(App, { target: document.querySelector('#app')! });
```

## What stays the same

- **Setup runs once.** In the browser the component builds its elements one time. On a server the body runs there, and the browser never runs it.
- **No handler runs before its event.** A build may fetch the click code early, but fetching is not running. [Lazy chunks](/how-it-works/lazy-chunks) explains the difference.
- **A write updates its readers and nothing else.** After `bags++`, only the text that reads `bags` changes. Nothing compares an old page with a new one.

A server page with nothing that can react, such as `<p>In your cart: {bags} bags</p>` with no button, ships no script at all: `renderToString()` sends the HTML in a container `div` and nothing else.
