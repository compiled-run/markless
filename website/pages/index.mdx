## Try it

Here is an order like the one in the drawing, as code. Press **Mark ready**, and watch which part of the page changes. Then change the code, and watch the order change with it.

<Code steps={[{ label: 'Rename `Mark ready 🔔` to `Done 🎉`.', shows: 'Done 🎉' }, { label: "Start the order at `'Queued 📋'` instead of `'Brewing ⏳'`.", source: "state('Queued 📋')" }, { label: 'Under line 8, add `<p>Again: {status}</p>`. Press the button, and both lines update.', rewrites: 2 }]}>
```tsrx title="order.tsrx"
import { state } from '@markless/core';

export default function Order() @{
	let status = state('Brewing ⏳');

	<section>
		<p>☕ Latte for Marcus</p>
		<p>Status: {status}</p>
		<button onClick={() => {
			status = 'Ready for pickup ✅';
		}}>
			Mark ready 🔔
		</button>
	</section>
}
```
</Code>

`status` is a plain variable. `state()` gives it a starting value, and you change it by assigning to it.

`Order` runs once, to set up the page. A click runs only the code in `onClick`, and only the text showing `status` changes.

## Markless reads your code first

Most tools figure out how your page fits together by running your code in the visitor's browser. **Markless finds out while it builds your app, before anyone visits.** The browser gets the finished map, so nothing has to run to create it.

## Why the name Markless?

Many frameworks ask you to mark your code for them: a special prefix, a `$` sign, a `.value` to read through, a hook with its rules. Every mark is one more rule to remember, for you and your agent, instead of your product. We want you both focused on what you are building.

Markless reads plain code instead. A value is a `let`, a change is a plain assignment, and the compiler works out the rest on its own. No marks needed. That is the name.
