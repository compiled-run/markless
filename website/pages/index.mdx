# Write a variable. The page follows it.

<PageMeta level="Start here" time="4 min" assumes="nothing" sprite="crown" />

<ThemeToggle />

<Subtitle text="Markless is a way to build websites and apps with TypeScript. The same code can run in a browser, on a server, or on your phone, like an iPhone or Android." />

Here is a button that counts its clicks. Click it a few times. Then change the code, and watch the button change with it.

<Code note="Change the label from Count to Clicks. Then change count++ to count += 10, and click again.">
```tsrx title="counter.tsrx"
import { state } from '@markless/core';

export default function Counter() @{
	let count = state(0);

	<button onClick={() => count++}>
		Count {count}
	</button>
}
```
</Code>

`count` is a plain variable. You read it by writing `count`, and you change it with `count++`. There is no setter to call and nothing to unwrap.

`state(0)` is the one new word. It starts `count` at 0 and keeps the page in step with it. When `count` changes, the text that shows it changes too.

## Markless reads your code first

So how does the page know which number to change?

Before your app runs, Markless reads your code the way you read it. It sees that `count` shows up in the button text, and that the click changes it. It writes that down. So when `count` changes, it already knows the one piece of text to update.

## Your function runs once

Here is a second function. It rolls a die with `Math.random()` during setup. Click **Count** a few times, and watch the die.

<Code note="Click Count a few times, and the roll stays put. Then change the 6 to 100. Your edit runs the function again, so it rolls once more.">
```tsrx title="rolled-once.tsrx"
import { state } from '@markless/core';

export default function RolledOnce() @{
	let count = state(0);
	const roll = Math.floor(Math.random() * 6) + 1;

	<section>
		<img
			src="/illustrations/die-light.png"
			alt="A die"
			width="56"
		/>
		<p>Rolled at setup: {roll}</p>
		<button onClick={() => count++}>
			Count {count}
		</button>
	</section>
}
```
</Code>

The count goes up. The die does not roll again.

The function body ran one time, to set up the page. On this site, that happened before the page reached you. After that, a click runs `count++` and nothing else. Only the text that shows `count` changes.

This is the whole model. You write setup code that runs once. You change values with plain code. The page keeps up.

## Render it anywhere

Markless builds what you write for any target. Learn it once, and you know how to render to each one:

| Where | How |
| --- | --- |
| A page in the browser | `render(App, { target })` from `@markless/core` draws your code into an element. |
| A multi-page app | `@markless/router` turns each file in `pages/` into a URL. |
| HTML from a server | `renderToString()` from `@markless/core` turns your code into HTML. |
| Tests | `@markless/vitest-browser` runs your code in the Vitest browser mode. |
| Native apps | Two experiments drive iOS and macOS buttons from the same kind of counter. |

You write the code the same way for each one. The browser, server and test targets work today. iOS and macOS run as early proofs.
