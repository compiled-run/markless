# Write a variable. The page follows it.

<PageMeta level="Start here" time="4 min" assumes="nothing" sprite="crown" />

<ThemeToggle />

<Subtitle text="Markless is a way to build user interfaces from TypeScript functions with markup in them. The same component runs in a browser tab, on a server, or in a test." />

Here is a whole component. Click the button a few times. Then change the code, and the result changes with it.

<Code note="Change the label from Count to Clicks. Then change count++ to count += 10, and click again.">
```tsrx title="counter.tsrx"
import { state } from '@markless/core';

export default function Counter() @{
	let count = state(0);

	<button onClick={() => count++}>Count {count}</button>
}
```
</Code>

`count` is a plain variable. You read it by writing `count`, and you change it with `count++`. There is no setter to call and nothing to unwrap.

`state(0)` is the one new word. It tells Markless this value can change, so the page has to follow it.

## Markless reads your component first

So how does the page know which number to change?

Before your app runs, Markless reads your component the way you read it. It sees that `count` shows up in the button text, and that the click changes it. It writes that down. So when `count` changes, it already knows the one piece of text to update.

## Your component runs once

Here is a second component. It rolls a die with `Math.random()` when it runs. Click **Count** a few times, and watch the die.

<Code note="Click Count a few times, and the roll stays put. Then change the 6 to 100. Your edit runs the component again, so it rolls once more.">
```tsrx title="rolled-once.tsrx"
import { state } from '@markless/core';

export default function RolledOnce() @{
	let count = state(0);
	const roll = Math.floor(Math.random() * 6) + 1;

	<section>
		<p>Rolled when the component ran: {roll}</p>
		<button onClick={() => count++}>Count {count}</button>
	</section>
}
```
</Code>

The count goes up. The die does not roll again.

The function body ran one time, to set up the page. On this site, that happened before the page reached you. After that, a click runs `count++` and nothing else. Only the text that shows `count` changes.

This is the whole model. You write setup code that runs once. You change values with plain code. The page keeps up.

## Render it anywhere

Markless does not need a server. The same component renders wherever your app needs it:

| Where | How |
| --- | --- |
| A page in the browser | `render(App, { target })` from `@markless/core` puts a component into an element. |
| A multi-page app | `@markless/router` turns each file in `pages/` into a URL. |
| HTML from a server | `renderToString()` from `@markless/core` turns a component into HTML. |
| Tests | `@markless/vitest-browser` runs components in the Vitest browser mode. |
| Native apps | Two experiments drive iOS and macOS buttons from the same kind of counter. |

You write the component the same way for each one. Pick the place your app needs.
