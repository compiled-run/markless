# A hidden branch is not hidden, it is gone

<PageMeta level="Start here" time="5 min" assumes="state, events" sprite="corner-bracket" />

<ThemeToggle />

Here is a bug you have met. A panel with a message box in it. You type half a sentence, close the
panel by accident, open it again, and your half sentence is not there.

Markless does not let you write that bug. Once you can see why, the fix is one line, and the build
tells you the day you forget it.

**`@if` puts real elements into the page and takes them out again, and anything declared inside the
branch would go out with them.**

## The version Markless refuses

Here is the tempting way to write the panel. The value typed into the field, `draft`, is declared
inside the `@if`, next to the field that uses it.

<Callout
	sticker="spring"
	sprite="cross"
	title="This first file does not build, on purpose"
	text="Do not paste the next file into your project: Markless stops the build on it. The file is here so you can see the mistake the build error is pointing at. The file after it is the one to use."
/>

```tsrx
// Refused example: the build stops on the line that creates draft.
import { state } from '@markless/core';

export default function DraftLost() @{
	let open = state(false);

	<section>
		<button onClick={() => (open = !open)}>Toggle the panel</button>

		@if (open) {
			let draft = state('');

			<label>
				Your message
				<input value={draft} onInput={(event) => (draft = event.currentTarget.value)} />
			</label>
			<p>Draft: {draft}</p>
		}
	</section>
}
```

Think about what this would do if it ran. `draft` lives inside the branch, so when the panel closes
and the branch leaves the page, `draft` leaves with it. Opening the panel again would not restore
anything. It would build a new field with a new, empty `draft`, and whatever you had typed would be
gone without a word.

Rather than ship that, Markless stops the build and names the line. The error code is
`MARKLESS_STATE_CREATION_SITE_UNSTABLE`, and the message reads: state() creates "draft" inside a
branch. In plain words: a value made with `state()` has to be created in a place that exists for as
long as the component does, and the inside of an `@if` is not that place. The same build run may
list a couple of other errors on the same lines; they are knock-on effects of this one and go away
with it.

## The fix is to move one line up

Take `draft` out of the branch and put it in the component body, above the `@if`. The branch still
comes and goes, but the value it reads does not:

```tsrx
import { state } from '@markless/core';

export default function DraftKept() @{
	let open = state(false);
	let draft = state('');

	<section>
		<button onClick={() => (open = !open)}>Toggle the panel</button>

		@if (open) {
			<label>
				Your message
				<input value={draft} onInput={(event) => (draft = event.currentTarget.value)} />
			</label>
			<p>Draft: {draft}</p>
		}
	</section>
}
```

This one builds. Open the panel, type something into the field, close the panel, then open it again:
your text is still there. The only difference between the two components is which side of the `@if`
the declaration sits on.

The rule to carry away: **where you declare a value decides how long it lives.** Above a branch
means "for as long as the component is". Markless does not let you create state inside a branch,
because there it would only last as long as the branch is on screen.

## The rest of the shapes

`@else` covers the other side of the same condition:

```tsrx
import { state } from '@markless/core';

export default function Either() @{
	let open = state(false);

	<section>
		<button onClick={() => (open = !open)}>Toggle</button>
		@if (open) {
			<p class="open">Shown</p>
		} @else {
			<p class="closed">Hidden</p>
		}
	</section>
}
```

Choosing between more than two reads better as `@switch` than as a chain. It renders the one `@case`
whose value matches, and `@default` catches everything else:

```tsrx
import { state } from '@markless/core';

export default function Pick() @{
	let kind = state('alpha');

	<section>
		<button onClick={() => (kind = 'beta')}>Choose beta</button>
		@switch (kind) {
			@case 'alpha': {
				<p>A</p>
			}
			@case 'beta': {
				<p>B</p>
			}
			@default: {
				<p>Other</p>
			}
		}
	</section>
}
```

These are part of the language, not a trick played with JavaScript expressions inside the markup.
That is what lets the compiler treat a branch as a real thing with a beginning and an end, rather
than as an opaque expression it has to re-evaluate.

## What actually happens when the condition flips

Not much, and that is the point. Flipping a branch swaps a range of real DOM nodes in or out and
cleans up anything that belonged only to the branch. No component function runs again, not the one
holding the `@if` and not any component inside it.

A branch has an identity the compiler can name, so it can be given its own scope, its own disposal and its own place in the page. That is why the draft in the first file would really be destroyed rather than merely hidden, since there is no retained shadow copy of the tree anywhere for it to hide in, and why the build refuses to create it there."
/>

## Try it yourself

Take the second component and move `let draft = state('');` back inside the `@if`, then build.
Read the error the build prints and find the line it points at. Move the declaration back above the
branch and build again. Seeing the error once is the fastest way to make the rule stick.
