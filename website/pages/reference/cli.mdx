# Create an app from the command line

<PageMeta time="3 min" assumes="nothing" />

<Subtitle text="create-markless makes a new app in one command. It asks a few questions, or takes flags instead." />

```bash
npm create markless@latest my-app -- --yes --starter app --no-git
```

That makes the `app` starter in `my-app/`, installs its packages, and skips `git init`. With npm, put the flags after `--`. Without it, npm reads `--yes` as its own option and stops on flags it doesn't know. pnpm, Yarn and Bun pass flags through without `--`.

## Flags

This is what `npx create-markless --help` prints:

```txt
create-markless

Create Markless apps

Usage:
  create-markless <target> [--yes]

Options:
  --yes, -y          Use defaults
  --format <name>   node or bun
  --starter <name>  minimal, app, docs, or full-stack
  --editor <name>   vscode, zed, or none
  --agents <list>   claude-code, codex, gemini-cli, github-copilot, or none
  --no-install      Skip dependency installation
  --no-git          Skip git initialization
  --workspace       Add the app to the enclosing workspace, if there is one
  --no-workspace    Keep the app separate from the enclosing workspace
  --force           Write into a non-empty directory
```

With `--yes` you must name the folder, and it takes these defaults:

- the `node` format and the `minimal` starter
- it installs the packages and runs `git init`
- editor settings for the editor whose terminal you're in, or VS Code
- a skill file for the coding agent running the command, if one is
- a folder that must be empty, unless you pass `--force`
- an app kept separate from any workspace around it, unless you pass `--workspace`

## Starters

All four starters are apps with pages, built on `@markless/router` and Nitro. That's a choice of the starters: Markless itself needs no server, and `render()` from `@markless/core` mounts an app in the browser alone.

| `--starter` | The question's label | What you get |
| --- | --- | --- |
| `minimal` | Learn Markless | A counter in `pages/index.tsrx`, and `document.tsrx` around it. |
| `app` | Build an app | The `minimal` files plus `404` and `500` pages. |
| `docs` | Write docs | An MDX docs site with a layout and sidebar components. |
| `full-stack` | Full-stack app | The `app` files plus `api/` and `middleware/` folders. |

Every starter also writes `package.json`, `tsconfig.json`, `vite.config.ts`, `README.md`, `.gitignore`, `public/` and `scripts/markless-doctor.mjs`. `--editor vscode` adds `.vscode/`, `--editor zed` adds `.zed/`, and `--editor none` adds neither.

## Coding agent skills

The CLI can give your coding agent a Markless skill file. It goes into the agent's folder in your home folder, like `~/.claude/skills/markless/SKILL.md`. It works for:

<MarkedList items="claude:Claude Code|codex:Codex|gemini:Gemini CLI|copilot:GitHub Copilot" />

Add or remove the file later with `create-markless agents <add|remove> [--agents <list|none>]`. Cursor shows in the list, but you can't pick it: its rules apply to every project, so the CLI doesn't write one.

## Scripts in a new app

| Script | Runs | What it does |
| --- | --- | --- |
| `npm run dev` | `vp dev` | Starts the dev server on `http://localhost:3000`. |
| `npm run build` | `vp build` | Builds the app and its server into `.output/`. |
| `npm run preview` | `vp preview` | Serves the build. |
| `npm run check` | `vp check` | Checks the formatting and lints the code. |
| `npm run doctor` | `node scripts/markless-doctor.mjs` | Checks the Markless packages and `tsconfig.json`, then runs `vp build`. Add `-- --no-build` to skip the build. |
| `npm run fmt` | `vp fmt` | Formats the code. |
| `npm run test` | `vp test` | Runs Vitest. |

`vp` is the Vite+ command line. Run Vite commands through it, as `vp build -c other.config.ts`, not `vite build`. The app's `vite` is an alias for `@voidzero-dev/vite-plus-core`, so plugins that ask for `vite` get Vite+, and that package has no `vite` command.

To run the built server without Vite, use `node .output/server/index.mjs`. It reads the `PORT` variable.

When the build stops on a Markless error, [error codes](/errors) has a page for each one.
