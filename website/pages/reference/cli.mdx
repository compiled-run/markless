# The create-markless CLI

<PageMeta time="5 min" assumes="nothing" />

<Subtitle text="create-markless is the command that writes a new Markless app into a folder, asking a few questions unless flags answer them first." />

```txt title="Usage"
create-markless <target> [options]
create-markless agents <add|remove> [--agents <list|none>]
```

**`<target>`** is the folder to create, and **options** answer the questions ahead of time. The **`agents`** command adds or removes a coding agent's skill file in an app you already have. For a walkthrough, see [Create an app](/start/new-app).

## Every option

| Option | Default | What it does |
| --- | --- | --- |
| `--yes`, `-y` | off | Asks nothing and takes every default. Needs a `<target>`. |
| `--starter <name>` | `minimal` | The starter to copy: `minimal`, `app`, `docs` or `full-stack`. |
| `--format <name>` | `node` | A `package.json` set up for `node` or `bun`. |
| `--editor <name>` | your terminal's editor, else `vscode` | Which settings folder to write: `vscode`, `zed` or `none`. |
| `--agents <list>` | the agent running it, if any | Comma-separated `claude-code`, `codex`, `gemini-cli`, `github-copilot`, or `none`. |
| `--no-install` | install | Skips the package manager's `install`. `--install` forces it. |
| `--no-git` | `git init` | Skips `git init`. `--git` forces it. |
| `--workspace` | kept separate | Joins the app to a workspace around the folder. `--no-workspace` keeps it out. |
| `--force` | off | Writes into a folder that isn't empty. |
| `--help`, `-h` | | Prints the usage and options. |
| `--version`, `-v` | | Prints the CLI's version. |

Options take a value as `--starter app` or `--starter=app`. An unknown option stops the CLI, and a value it doesn't know gets an error naming the choices.

## Every prompt has an option

A *flag* is a word starting with `--` that answers a prompt before it's asked. The figure runs `npm create markless@latest my-app -- --yes --starter app --no-git`. Press the terminal to run it bare, then press a flag; tear off the `--` and try again:

<SessionFigure />

| Prompt | Answers | Option |
| --- | --- | --- |
| What are you building today? | Learn Markless, Build an app, Write docs or Full-stack app | `--starter` |
| What should we call it? | a folder name, `my-markless-app` by default | `<target>` |
| Where should it run? | Node, Bun | `--format` |
| Which editor do you use? | VS Code, Zed, Other | `--editor` |
| Add Markless to your agents? | the agents found on this machine | `--agents` |
| Install dependencies now? | Yes, No | `--install`, `--no-install` |
| Initialize git? | Yes, No | `--git`, `--no-git` |
| Ready to create? | Create app, Cancel | `--yes` skips it |

Inside an existing workspace it also asks "How should my-app be installed?", which `--workspace` or `--no-workspace` answers. In CI, or from a coding agent, pass every answer at once:

```bash title="Terminal"
npm create markless@latest my-app -- --yes --starter app \
  --format node --editor none --agents none --no-git
```

With npm, everything after **`--`** goes to the CLI. Without it, npm reads `--yes` as its own option and stops on flags it doesn't know.

## Each starter's files

Every starter is an app with pages, built on `@markless/router` and Nitro. Each also gets `package.json`, `tsconfig.json`, `vite.config.ts`, `README.md`, `.gitignore`, `public/` and `scripts/markless-doctor.mjs`, plus `.vscode/` or `.zed/` for the editor you pick.

```txt title="minimal"
document.tsrx
pages/index.tsrx
```

```txt title="app"
document.tsrx
pages/index.tsrx
pages/404.tsrx
pages/500.tsrx
```

```txt title="full-stack"
document.tsrx
pages/index.tsrx, pages/404.tsrx, pages/500.tsrx
api/health.ts
middleware/request.ts
```

```txt title="docs"
document.tsrx
pages/index.mdx
pages/docs/index.mdx
pages/docs/[...slug].mdx
components/docs/Sidebar.tsrx
components/layouts/DocsLayout.tsrx
```

## A new app's scripts

| Script | Runs | What it does |
| --- | --- | --- |
| `dev` | `vp dev` | Starts the dev server on `http://localhost:3000`. |
| `build` | `vp build` | Builds the app and its server into `.output/`. |
| `preview` | `vp preview` | Serves the build. |
| `check` | `vp check && markless-tsc` | Checks formatting and lint, then type-checks `.tsrx` files (from the next release). |
| `doctor` | `node scripts/markless-doctor.mjs` | Checks the Markless packages and `tsconfig.json`, then builds. Add `-- --no-build` to skip the build. |
| `fmt` | `vp fmt` | Formats the code. |
| `test` | `vp test` | Runs Vitest. |

`vp` is the Vite+ command line, so run `vp build`, not `vite build`. `node .output/server/index.mjs` runs the built server and reads the `PORT` variable.

## Exit codes and the environment

- **Exit code 0:** the app was created, or you pressed Ctrl+C at a prompt.
- **Exit code 1:** anything else. The CLI prints one line saying why: a Node.js it can't run on (it needs 22.18+, 24.11+ or 26+), an unknown option, a folder that isn't empty, a failed `install` or `git init`, or choosing Cancel.
- **`npm_config_user_agent`:** the package manager that ran the CLI sets it. It decides which one installs the app.
- **`TERM_PROGRAM`:** `vscode` or `zed` picks the default editor.

## Package managers

- **npm:** `npm create markless@latest my-app -- --yes`. Options go after `--`.
- **pnpm:** `pnpm create markless my-app --yes`.
- **Yarn:** `yarn create markless my-app --yes`.
- **Bun:** `bun create markless my-app --yes`. Add `--format bun` for a Bun app.

Whichever one runs the CLI also installs the app. Run with `--yes` inside a workspace, the app stays out unless you pass `--workspace`. Bun and Yarn 1 can't install a member of their own workspace on its own, so if you keep a declared member out, the CLI skips the install and says so.
