## Create an app

```bash
npm create markless@latest my-app
```

With no flags, the CLI asks you questions. With `--yes`, it takes the defaults, and you must give a folder name.

```bash
npm create markless@latest my-app -- --yes --starter app --no-git
```

With npm, put the flags after `--`. Without it, npm reads them as its own options: it keeps `--yes` and `--editor` for itself, and stops on `--no-install`. pnpm, yarn and bun pass flags through without `--`.

## Flags

This is the real `--help` output of `create-markless` 0.5.0.

```txt
create-markless

Create Markless apps

Usage:
  create-markless <target> [--yes]

Options:
  --yes, -y          Use defaults
  --format <name>   node or bun
  --starter <name>  minimal, app, docs, or full-stack
  --editor <name>   vscode, zed, or none
  --agents <list>   claude-code, codex, gemini-cli, github-copilot, or none
  --no-install      Skip dependency installation
  --no-git          Skip git initialization
  --workspace       Add the app to the enclosing workspace, if there is one
  --no-workspace    Keep the app separate from the enclosing workspace
  --force           Write into a non-empty directory
```

With `--yes`, the format is `node` and the starter is `minimal`. The CLI also installs the packages and runs `git init`. The target folder must be empty unless you pass `--force`.

If the folder sits inside an existing workspace, the CLI keeps the app separate by default. Pass `--workspace` to add it to that workspace.

## Starters

All four starters are multi-page apps built on `@markless/router` and Nitro. That is a choice of the starters. Markless itself does not need a server: `render()` from `@markless/core` mounts an app in the browser alone.

| `--starter` | Prompt label | What you get |
| --- | --- | --- |
| `minimal` | Learn Markless | A small TSRX counter app in `pages/index.tsrx`. |
| `app` | Build an app | The `minimal` files plus `document.tsrx` and `404` and `500` pages. |
| `docs` | Write docs | An MDX docs site with a layout and sidebar components. |
| `full-stack` | Full-stack app | The `app` files plus `api/` and `middleware/` folders. |

A `minimal` app made with `--yes --no-install --no-git --agents none --editor vscode` holds these files (`--editor zed` writes `.zed/settings.json` instead of the `.vscode` files, and `--editor none` writes neither):

```txt
.gitignore
.vscode/extensions.json
.vscode/settings.json
README.md
package.json
pages/index.tsrx
public/.gitkeep
scripts/markless-doctor.mjs
tsconfig.json
vite.config.ts
```

## Coding agent skills

The CLI can write a Markless skill file for a coding agent. The file goes into the agent's folder in your home folder, like `~/.claude/skills/markless/SKILL.md`. A subcommand adds or removes it later.

```txt
Usage: create-markless agents <add|remove> [--agents <list|none>]
```

Cursor shows in the list, but you can't pick it. Its User Rules apply to every project, so the CLI does not write one.

## Scripts in a new app

- `npm run dev` runs `vp dev`. Starts the dev server on `http://localhost:3000`.
- `npm run build` runs `vp build`. Builds the app and its server into `.output/`.
- `npm run preview` runs `vp preview`. Serves the build.
- `npm run check` runs `vp check`. Runs the Vite+ checks.
- `npm run doctor` runs `node scripts/markless-doctor.mjs`. Checks the Markless packages and `tsconfig.json`, then runs `vp build`. Add `-- --no-build` to skip the build.
- `npm run fmt` runs `vp fmt`. Formats the code.
- `npm run test` runs `vp test`. Runs Vitest.

Run Vite commands through `vp`, as these scripts do: `vp build -c other.config.ts`, not `vite build`. The app lists `vite` as an alias for `@voidzero-dev/vite-plus-core`, so that plugins asking for `vite` get Vite+, and that package has no `vite` command.

To run the built server without Vite, use `node .output/server/index.mjs`. It reads the `PORT` variable.
