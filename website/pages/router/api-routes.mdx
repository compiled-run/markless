# API routes

<PageMeta time="2 min" assumes="routes" />

<Subtitle text="An API route is a file in api/ that answers a request with data instead of a page." />

```ts title="api/users/[id].get.ts"
import type { EndpointHttpContext } from '@markless/router';

export default function user({ params }: EndpointHttpContext<{ id: string }>) {
	return Response.json({ id: params.id });
}
```

`GET /api/users/42` answers `{"id":"42"}`. The **path** gives the address, **`.get`** in the name gives the method, and the **default export** is the function that runs.

## The file name picks the method

An *endpoint* is one file in `api/`, at the app root next to `pages/`. Its name sets what it answers:

- `[id]` is one part of the address, read as `params.id`.
- `.get`, `.post`, `.put`, `.patch`, `.delete`, `.head`, `.options`, `.connect` or `.trace` picks one method.
- No method in the name answers every method.

Type an id, then drop the coin in GET or POST.

<VendingAnatomy />

Only the file that matches both the method and the path answers. A `POST` to `/api/users/42` matches no file and gets a 404.

## One function gets the whole request

The default export gets one object, the *context*:

- `request`, `url` and `params` describe what was asked.
- `locals` holds what middleware set.
- `response.headers` lets you add headers; or return your own `Response`.

```ts title="api/users/[id].get.ts"
export const cache = { maxAge: 60 };
```

That line lets the answer be cached for 60 seconds.

## Middleware runs on every request

A file in `middleware/` runs before every page and endpoint. The full-stack starter ships this one:

```ts title="middleware/request.ts"
export default function request(http: import('@markless/router').MiddlewareHttpContext) {
	http.response.headers.set('x-markless-router', '1');
}
```

Keep in mind:

- Files in `api/` and `middleware/` end in `.ts`, and each has one `export default` function.
- Don't export a function named `GET` or `POST`; the file name gives the method.
- A page in `pages/api/` is still a page, so a reference page can live at `/api/` beside your endpoints.
