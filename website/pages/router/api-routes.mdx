# Answer requests with API routes

<PageMeta time="2 min" assumes="routes" />

<Subtitle text="A file in api/ is an endpoint: a function that takes a request and returns a response, for JSON, webhooks or a health check." />

```ts title="api/users/[id].get.ts"
import type { EndpointHttpContext } from '@markless/router';

export const cache = { maxAge: 60 };

export default function user({ params }: EndpointHttpContext<{ id: string }>) {
	return Response.json({ id: params.id });
}
```

`GET /api/users/42` now answers `{"id":"42"}`. `export const cache = { maxAge: 60 }` lets the answer be cached for 60 seconds; leave it out to answer fresh every time.

## The path is the address, the name is the method

`api/` sits at the root of your app, next to `pages/`, and follows the same address rules. The file name can also end with the one HTTP method it answers.

| File in `api/` | What it answers |
| --- | --- |
| `health.ts` | every method on `/api/health` |
| `index.ts` | `/api` |
| `users/[id].get.ts` | only `GET` on `/api/users/` plus one part |
| `files/[...path].ts` | `/api/files/` plus one part or more |

A `POST` to `/api/users/42` finds no endpoint, because the file name says `get`. The method names a file can end with are `get`, `post`, `put`, `patch`, `delete`, `head`, `options`, `connect` and `trace`.

## One function gets the whole request

The function gets one object with `request`, `url`, `params`, `locals` and `response`. Return a `Response`, or set headers on `response.headers`.

- Each file has one `export default` function.
- Don't export a function called `GET` or `POST`. The method comes from the file name, and only the default export answers.

## Run code on every request with middleware

A file in `middleware/` runs for every request to your pages and endpoints. The full-stack starter ships this one:

```ts title="middleware/request.ts"
export default function request(http: import('@markless/router').MiddlewareHttpContext) {
	http.response.headers.set('x-markless-router', '1');
}
```

That header shows up on your pages and on your `/api/` answers. A middleware file follows the endpoint rule: one `export default` function.

Keep in mind:

- Files in `api/` and `middleware/` end in `.ts`. A `.tsrx` file there is not an endpoint.
- Keep both folders at the app root, not inside `pages/`. A page in `pages/api/` is a page, so a reference page can live at `/api/` beside your endpoints.
