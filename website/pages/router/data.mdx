# Page data arrives in the same response

<PageMeta time="2 min" assumes="async, routes" />

<Subtitle text="A page loads its data with an async computed() inside @try. The fast part shows first, and the data follows in the same response." />

```tsrx title="pages/shops/[shop].tsrx"
import { computed } from '@markless/core';
import type { PageProps } from '@markless/router';
import { recentOrders } from '../../src/orders.ts';

export default function Orders({ params }: PageProps<{ shop: string }>) @{
	const orders = computed(async () => recentOrders(params.shop));

	<main>
		<h1>Orders</h1>
		@try {
			<p>{orders.length} orders</p>
		} @pending {
			<p>Loading…</p>
		} @catch {
			<p>Couldn't load the orders.</p>
		}
	</main>
}
```

There is no loader function. A page loads data the way any component does, as an [async value](/concepts/async).

## One response, in two parts

Press the machine to print the page. Then tug the tape while it waits.

<TickerAnatomy />

The heading and the `@pending` text go out first. When the orders are ready, the same response carries on with the `@try` content. The browser never asks twice, and fast data never sends `Loading…` at all.

Keep in mind:

- The call can read the page's props before or after an `await`, and Markless tracks both.
- On the server, `fetch` needs a full address. Build it from the `url` prop: `new URL('/api/orders', url.href)`.
- The router can't wait for all the data first. A slow `@try` always sends its `@pending` content first.
