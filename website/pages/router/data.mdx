# Page data arrives in the same response

<PageMeta level="Building" time="4 min" assumes="async, routes" sprite="drops" />

<ThemeToggle />

A page needs data from somewhere slow, like a database. You don't want the whole page to wait for
it. You also don't want the browser to make a second trip to fetch it.

There is no special loader function for this. A page loads data the way any component does: with an
async `computed()` inside `@try`.

Think of a restaurant that brings the bread first. The main dish comes later, to the same table.
That is an analogy. In the router, the bread is everything fast, and the main dish is the `@try`
content.

Step through one page request. Then switch to quick data and step again.

<FeedStepsDemo />

With slow data, the reader sees the heading and **Loading...** first. The data comes later, in the
same response. The browser never asks a second time.

## The code

```tsrx
import { computed } from '@markless/core';
import type { PageProps } from '@markless/router';
import { slowGreeting } from '../lib/slow.ts';

export default function Feed({ url }: PageProps) @{
	const data = computed(async () => slowGreeting(url.pathname));

	<main>
		<h1>Feed</h1>
		@try {
			<p>{data.text}</p>
		} @pending {
			<p>Loading...</p>
		} @catch {
			<p>Failed</p>
		}
	</main>
}
```

`slowGreeting` stands for any slow call that returns `{ text }`. If it is slow, one response comes in
two parts:

1. The heading and the `@pending` content come first.
2. When the data is ready, the same response adds the `@try` content. The page puts it in place, and
   the response ends.

If the data is ready quickly, it goes in the first part, and the server never sends `Loading...`. You turn
nothing on. For the rules of async values, see [async](/concepts/async).
