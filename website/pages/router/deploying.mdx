# Write once, then pick where it runs

<PageMeta time="2 min" assumes="routes" />

<Subtitle text="One build turns your pages, endpoints and middleware into a Node server. A preset turns the same files into output for another host." />

```bash
npm run build
PORT=3000 node .output/server/index.mjs
```

That is the default: a Node server that reads its port from `PORT`. Run `npm run preview` to try the build first.

## Pick another host with a preset

The router builds on [Nitro](https://nitro.build), a server toolkit that writes output for many hosts. A *preset* names the host. Press the tin to switch it, or drag the dough in.

<DoughAnatomy />

The dough never changes: your files stay the same, and only the output takes the host's shape.

| Host | `NITRO_PRESET` | Output |
| --- | --- | --- |
| Node | none, the default | `.output/` |
| Vercel | `vercel` | `.vercel/output/` |
| Cloudflare Workers | `cloudflare-module` | `.output/` |

```bash
NITRO_PRESET=vercel npm run build
```

These three are tested with Markless. Treat Nitro's other presets as untested, and try a preview deploy first.

## What the build writes

| Path | What it holds |
| --- | --- |
| `.output/server/index.mjs` | the server you start |
| `.output/public/build/` | the browser code, sent with long-lived cache headers |
| `.output/markless/router/types/` | the route types your editor uses to check links |

The starter's `.gitignore` already leaves `.output/` out of git.

## Serve prerendered pages free on Cloudflare

Deploy with `npx wrangler deploy --config .output/server/wrangler.json`. Cloudflare serves files in `.output/public/` without running your Worker, so prerendered pages cost nothing:

- Give the page `prerender: true` in its route rule, and give its `/_markless/fragment/...` path the same rule, so a click on a link to it is served from a file too.
- Pages that aren't prerendered render in the Worker and stream, so `@pending` content still shows first.
- Name the Worker with `name` in a `wrangler.json` next to `vite.config.ts`.

## Keep shared data out of memory

A host runs many copies of your server, called *instances*, and each has its own memory. Put counters, sessions and carts in a database or a key-value store. For one copy per instance, such as a database pool, put it on `globalThis`:

```ts
const pool = (globalThis.dbPool ??= createPool(process.env.DATABASE_URL));
```

<Collapsible summary="Nitro settings in vite.config.ts">

Put Nitro settings under a top-level `nitro` key, and the router merges them in. This app serves from a sub-path:

```ts title="vite.config.ts"
import { markless } from '@markless/core/vite';
import { router } from '@markless/router/vite';
import { defineConfig } from 'vite-plus';

export default defineConfig({
	base: '/shop/',
	nitro: { baseURL: '/shop/' },
	plugins: [markless(), router()],
});
```

Don't add `nitro()` to `plugins` yourself; the build stops and asks you to remove it.
