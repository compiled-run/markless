# Write once, then pick where it runs

<PageMeta time="2 min" assumes="routes" />

<ThemeToggle />

You have pages, endpoints and maybe some middleware. Now they need to run somewhere other than your
laptop.

The router builds on [Nitro](https://nitro.build). Nitro turns one app into output for many hosts,
and a preset picks the host. Your files stay the same. Only the output folder changes.

<BuildTargets />

## The default: a Node server

<MugSpot mood="cheers" />

```bash
npm run build
PORT=3000 node .output/server/index.mjs
```

The build runs three steps: the browser build, the server build, then Nitro. By default, Nitro
builds a Node server. The server reads the port from the `PORT` variable.

To try the build on your own machine, run `npm run preview`.

## What is in `.output/`

| Path | What it holds |
| --- | --- |
| `.output/server/index.mjs` | the server you start |
| `.output/public/build/` | the browser code, sent with long-lived cache headers |
| `.output/markless/router/types/` | the route types your editor uses to check links |
| `.output/nitro.json` | Nitro's notes about this build |

## Other hosts

Nitro reads the preset from the `NITRO_PRESET` variable. This build writes output for Vercel:

```bash
NITRO_PRESET=vercel npm run build
```

The output goes to `.vercel/output/`, with a `static/` folder and a `functions/` folder. This
website deploys the same way.

## Cloudflare Workers

This build writes output for a Cloudflare Worker with static assets:

```bash
NITRO_PRESET=cloudflare-module npm run build
npx wrangler deploy --config .output/server/wrangler.json
```

Cloudflare answers a request for a file in `.output/public/` without running your Worker, and those
requests are free. So everything you prerender costs nothing to serve: give a page
`prerender: true` in its route rule, and give its `/_markless/fragment/...` path the same rule, so
links to it are served from files too. The router writes `/guide` as `guide.html` and `/guide/` as
`guide/index.html`, the names Cloudflare serves at exactly those URLs without a redirect.

Pages that are not prerendered render in the Worker and stream, so a `@pending` arm still shows
before its data is ready. A Worker can be at most 64 MiB, so the router leaves out of it the code of
every page whose page and fragment URLs were both prerendered: those requests never reach it.

Browser code under `/build/` is static too, kept by browsers for a year. Cloudflare compresses it at
its edge, so the router writes no `.gz` or `.br` copies for this preset.

Some packages ship a Node build and a default build, and no build for Workers or browsers. Their
default build is for runtimes without Node's APIs and can miss functions the Node build has. A Worker
with `nodejs_compat` (Nitro's default) has those APIs, so the router bundles the Node build of such a
package into the Worker, the code a Node server would run. A package with its own Worker or browser
build keeps that one.
CommonJS code bundled into the Worker can still read `__filename` and `__dirname`, which a Worker never
defines, so a Worker build defines them as `/index.mjs` and `/`.

The Worker also leaves out Nitro's list of every uploaded file, which Cloudflare never needs because
it serves those files before the Worker runs. On a large site that list is megabytes of code an
isolate would parse every time it starts. A `run_worker_first` in your `wrangler.json` keeps it.

Name the Worker with `name` in a `wrangler.json` next to `vite.config.ts`; Nitro merges that file
into the one it writes.

Nitro has presets for many other hosts. We have tested three of them with Markless: the default Node
server, Vercel and Cloudflare Workers. Treat the others as untested for now, and try a preview
deploy first.

## Caches in front of your server

When a link swaps in the next page, the router asks for that page under its own path, such as
`/_markless/fragment/docs` for `/docs`, and the server answers with just the page area. Every
request for `/docs` itself gets the whole page. Because the two never share an address, a CDN or a
Vercel ISR cache keeps them apart, even one that ignores the query string. With an ISR rule for
`/**`, Vercel caches the page areas too; with a narrower rule, they render fresh on each click.

Your middleware and route rules see the page path, `/docs`, for both requests.

## Memory is not shared

A host runs your server as many copies, called instances, and starts or stops them as traffic
changes. Each instance has its own memory. No host shares it between instances: not Vercel, not
Netlify, not Cloudflare. A value you keep in a variable is gone on the next instance, and the
next visitor may land there.

A variable at the top of a module exists once per instance. It can also exist more than once inside
one instance, because Nitro may load the same module into more than one bundle. To keep exactly one
copy per instance, put it on `globalThis`:

```ts
const pool = (globalThis.dbPool ??= createPool(process.env.DATABASE_URL));
```

This is the right place for a database pool or a client: make it once per instance, then reuse it.

State that must outlive a request, or that every visitor must see, belongs in a database or a
key-value store. Counters, sessions and carts all go there, not in memory.

## The compile cache

A build keeps each `.tsrx` file's compiled result in `node_modules/.vite/markless-compile/`. The next build
reads a result back instead of compiling again, as long as the file, everything it was compiled against, and
the Markless compiler itself are unchanged, so it builds the same output. The cache holds at most 1 GB and
drops the results no recent build used. To compile everything every time, pass `markless({ compileCache:
false })`. Deleting the folder is always safe.

## Nitro configuration

Put Nitro configuration under a top-level `nitro` key in `vite.config.ts`. The router merges it into
the Nitro setup it makes for you. This is how an app serves from a sub-path:

```ts
import { markless } from '@markless/core/vite';
import { router } from '@markless/router/vite';
import { defineConfig } from 'vite-plus';

export default defineConfig({
	base: '/shop/',
	nitro: { baseURL: '/shop/' },
	plugins: [markless(), router()],
});
```

## Try it yourself

Build your app twice: once with no preset, once with `NITRO_PRESET=vercel`. Compare `.output/` with
`.vercel/output/`. Your own files did not change between the two builds.
