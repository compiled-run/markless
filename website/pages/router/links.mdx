# Links the build can check

<PageMeta time="3 min" assumes="routes" />

A link with a typo hides until somebody clicks it. Then they get a 404, and you get an email.

The router knows every file in `pages/`. Link to a route pattern, like `/blog/[slug]`, and the
build checks it. The route must exist, and you must pass its params. A wrong pattern stops the
build, and the bad link never ships.

## Link to a page

```tsrx
import { Link } from '@markless/router';

export default function Home() @{
	<nav>
		<Link href="/about">About</Link>
		<Link href="/blog/[slug]" params={{ slug: 'hello' }}>First post</Link>
	</nav>
}
```

`Link` renders a real `<a href>`. For the second link, the build writes `href="/blog/hello"` and
drops `params`. A plain `<a>` with a pattern and `params` works the same way.

## What the build checks

| You wrote | What happens |
| --- | --- |
| `href="/blog/[slug]"` with `params={{ slug }}` | the build passes, and `href` becomes the real address |
| `href="/blog/[id]"`, and no such route exists | the build stops: `Typed route error: /blog/[id] does not match any route in pages/.` |
| `href="/blog/[slug]"` with no `params` | the build stops: `Typed route error: /blog/[slug] requires params:` |
| `<Link href="/abuot">` | the build passes, and your editor flags the typo |

A plain address like `/about` has no brackets, so the build does not check it. On a `Link`, your
editor does.
The router writes your route types to `.output/markless/router/types/routes.d.ts`. The file
`markless-router-env.d.ts` in your app root points TypeScript at them.

## What a click does

When someone clicks a link to one of your pages, the browser keeps the page it has. The router asks
the server for the next page and swaps in only the page area. The address bar changes, and Back and
Forward bring back each page and its scroll position.
A scrolled box such as a sidebar keeps its scroll too. If the next page puts that box inside a
different element, give the box an `id` so the router can find it there.

If `document.tsrx` reads a prop other than `children`, such as the URL, a click loads the whole new
page instead.

The router also starts that request a little early. A pointer over a link, a focus, or a press
starts it. When the browser is idle, a few visible links start too, on a fast connection with data
saver off. If the request fails, the browser loads the address the normal way.

Plain `<a>` links to your pages navigate the same way.

/>

The router never requests these early:

| Link | Why |
| --- | --- |
| another site's address | the router only fetches your own pages |
| a path under `/api/` | an endpoint can do anything on a GET |
| `download`, `target="_blank"` (any `target` but `_self`), or `rel="external"` | the click leaves this tab or this app |
| `<Link prefetch={false}>` | you said so |

Everything else that names one of your pages is fair game, plain `<a>` included. `rel="nofollow"`
does not stop it: that tells search engines what to trust, not browsers what to fetch. Next.js,
Nuxt, SvelteKit and Turbo prefetch the same way, and opt out the same way, per link.

Each early request carries the header `Purpose: prefetch`, so your server can tell it from a click.
A page with a side effect can answer an early request without doing the work. Safer still, make the
action a form that posts: the router never requests a `POST` early.

```tsrx
import { Link } from '@markless/router';

export default function Header() @{
	<nav>
		<Link href="/settings">Settings</Link>
		<Link href="/logout" prefetch={false}>Log out</Link>
	</nav>
}
```

A page fetched early is shown for up to 30 seconds, and only while it can still match what the
server would send:

- After a write from this page, every page fetched early is dropped and the next click asks the
  server again. A write is a submitted form, or a `fetch` to your own site that is not a `GET` or
  `HEAD`. Back and Forward ask again too. To see these writes, the router wraps `window.fetch` once
  it starts. The wrapper passes your arguments to the browser's `fetch` unchanged and returns its
  promise as is.
- A page that answers `Cache-Control: no-store` is fetched again at the click, unless the early
  request is still arriving. One that answers `max-age=N` with `N` above 0 is shown for at most `N`
  seconds. `max-age=0`, `no-cache` and `must-revalidate` change nothing here: they ask a cache to
  check with the server, and hosts such as Vercel send them on every page by default.

In a built app, the code that handles these clicks is one small file the browser downloads once and
caches for every page. It starts when the browser finishes reading the page. A link clicked before
that, while a long page is still loading, loads the whole new page the normal way. Nothing is lost;
only that one click skips the swap.

## Props that change a click

| Prop | What it does |
| --- | --- |
| `prefetch={false}` | the router requests nothing before the click |
| `replace` | replaces the current history entry instead of adding one |
| `scroll={false}` | keeps the scroll position |

To turn early requests off for every link, write `router({ prefetch: false })` in `vite.config.ts`.
Links still work.

## Navigate from code

To change pages from code, such as after an order is placed, call `navigate`. It does exactly what a
click on a `Link` to the same address does.

```tsrx
import { navigate } from '@markless/router';

export default function Checkout() @{
	<button
		type="button"
		onClick={async () => {
			await fetch('/api/orders', { method: 'POST' });
			await navigate('/orders', { replace: true });
		}}
	>
		Place order
	</button>
}
```

| Option | What it does |
| --- | --- |
| `replace: true` | replaces the current history entry instead of adding one |
| `scroll: false` | keeps the scroll position |

`navigate` returns a promise that resolves once the new page is in place. If the address is not one
of your pages, the browser loads it the normal way, and the promise never resolves because this page
is gone. `navigate` runs in the browser only, so call it from an event handler, not while the page
renders.
