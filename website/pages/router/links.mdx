# Links

<PageMeta time="2 min" assumes="routes" />

<Subtitle text="A link points at one of your pages, and the build checks that the page exists." />

```tsrx title="pages/index.tsrx"
import { Link } from '@markless/router';

export default function Home() @{
	<nav>
		<Link href="/about">About</Link>
		<Link href="/blog/[slug]" params={{ slug: 'hello' }}>
			First post
		</Link>
	</nav>
}
```

**`Link`** renders a real `<a>`. **`params`** fills the brackets, so the build writes the second link as `href="/blog/hello"`.

## The build checks every link

`/blog/[slug]` is a *route pattern*: a file path in `pages/`, with brackets for the parts that change.

- A pattern that matches no file in `pages/` stops the build.
- A pattern without its `params` stops the build and names them.
- A plain address like `/about` isn't checked by the build. Your editor flags its typos.

## A click swaps in only the page

An *in-place navigation* keeps the page you're on and swaps in only its middle.

- The address changes when the new middle lands, not at the click.
- Back and Forward bring back each page and its scroll.
- Plain `<a>` links to your pages do the same.

Swap the sheet, then try to pull the clip off.

## Early fetches are real requests

A pointer resting on a link, a focus or a press starts fetching the next page before the click. That fetch is a real `GET`, so turn it off for a link that does something:

```tsrx
<Link href="/logout" prefetch={false}>Log out</Link>
```

- The router never fetches other sites or `/api/` paths early.
- Links with `download`, a `target` or `rel="external"` aren't fetched early either.
- `router({ prefetch: false })` in `vite.config.ts` turns early fetches off everywhere.

## `navigate()` is a click from code

```tsrx title="checkout.tsrx"
import { navigate } from '@markless/router';

export default function Checkout() @{
	<button
		onClick={async () => {
			await fetch('/api/orders', { method: 'POST' });
			await navigate('/orders', { replace: true });
		}}
	>
		Place order
	</button>
}
```

**`navigate()`** resolves once the new page is in place. **`replace`** swaps the current history entry instead of adding one, on `navigate()` and on `Link`.

Not yet:

- `prefetch={false}` works on `Link`, a plain `<a>`, or a component that passes it to one. Anywhere else stops the build with `MARKLESS_ELEMENT_ONLY_ATTRIBUTE_MISPLACED`.

Pages often need data from somewhere slow. [Load it in the page](/router/data).
