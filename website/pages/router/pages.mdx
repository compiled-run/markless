# Make a file, get a URL

<PageMeta level="Building" time="5 min" assumes="components" sprite="square" />

<ThemeToggle />

So far, everything has been one page. A real app has an about page, a blog, and a post for each
entry. Each one needs its own address.

You don't need a router to use Markless. A single page can call `render()` in the browser, and that is
all it needs. The router is for apps with many pages. `@markless/router` gives those apps file routes, links,
page data and API endpoints. Every `npm create markless` starter already includes it.

Think of the `pages/` folder as a street map. That is an analogy, but a close one. Each file path is
an address. When a request comes in, the router picks the file that matches the URL.

Pick an address.

## The rules

| File in `pages/` | Address |
| --- | --- |
| `index.tsrx` | `/` |
| `about.tsrx` | `/about`, and `/about/` too |
| `docs/index.mdx` | `/docs` |
| `blog/[slug].tsrx` | `/blog/` plus one part, like `/blog/hello` |
| `docs/[...slug].mdx` | `/docs/` plus one part or more |
| `404.tsrx` | any address with no matching file, with status 404 |
| `500.tsrx` | a page that throws in a production build, with status 500 |

Page files end in `.tsrx` or `.mdx`. The router skips every other file in `pages/`. So a helper file
can live next to the page that uses it.

If two files match one address, a plain name wins over `[param]`. A `[param]` wins over
`[...rest]`. So `blog/new.tsrx` answers `/blog/new`, and `blog/[slug].tsrx` answers the rest.

## Read the params

A page gets three props: `params`, `url` and `status`.

```tsrx
import type { PageProps } from '@markless/router';

export default function Post({ params }: PageProps<{ slug: string }>) @{
	<h1>Post {params.slug}</h1>
}
```

Save that as `pages/blog/[slug].tsrx`. Then `/blog/hello` shows **Post hello**. A catch-all param
is one string: for `/docs/guide/intro`, `slug` is `guide/intro`.

## One document around every page

There is no layout file. Instead, `document.tsrx` in the app root wraps every page. It uses `Html`
from `@markless/router`, and each page arrives as `children`:

```tsrx
import type { Children } from '@markless/core';
import { Html } from '@markless/router';

export default function Document({ children }: { readonly children?: Children }) @{
	<Html>
		<head>
			<meta charset="utf-8" />
			<meta name="viewport" content="width=device-width, initial-scale=1" />
		</head>
		<body>{children}</body>
	</Html>
}
```

For a header and footer that some pages share, write a component that takes `children`. Each page
wraps its content in it. See [components](/build/components).
