# One command, then a counter on localhost

<PageMeta level="Start here" time="5 min" assumes="nothing" sprite="plus" />

<ThemeToggle />

You want a real project on your machine, with pages, a dev server and a production build. One command writes it.

The starters are multi-page apps. Each file in `pages/` becomes a URL. They use `@markless/router`, which runs on Nitro, so `npm run dev` starts a local server.

Want one page and no server at all? Read [Use Markless in the browser](/start/browser-only) instead.

## Before you start

You need Node.js `^20.19.0`, `^22.18.0` or `>=24.11.0`. The build tools in the starter ask for these versions.

## Create the app

Run this in the folder that will hold your project:

```bash
npm create markless@latest
```

It asks a few questions:

1. `What are you building today?` Pick **Learn Markless**. It is the default, a small counter app.
2. `What should we call it?` This is the folder name. The default is `my-markless-app`.
3. `Where should it run?` Node, Deno or Bun. If you are not sure, pick Node.
4. `Install dependencies now?` and `Initialize git?` Both default to yes.

It can ask two more. Inside an existing workspace, it asks if the new app joins that workspace. If it finds coding agents on your machine, it offers to set Markless up for them.

Last, it shows a summary under `Ready to create?` It writes no files until you pick **Create app**.

## Start it

```bash
cd my-markless-app
npm run dev
```

Open `http://localhost:5173`. You see a heading and a button. That page is the file `pages/index.tsrx`. Here it is, and you can edit it. Click **Count 0** a few times first:

<Code note="Add a paragraph above the button that shows {count}, then click the button. Then change the heading text.">
```tsrx title="index.tsrx"
import { state } from '@markless/core';

export default function Home() @{
	let count = state(0);

	<main>
		<h1>Markless Router</h1>
		<button onClick={() => count++}>
			Count {count}
		</button>
	</main>
}
```
</Code>

The file name is `index`, so it is the page at `/`. Add `pages/about.tsrx`, and you have a page at `/about`.

## The scripts

The starter's `package.json` has these scripts. Run each one with `npm run <name>`.

| Script | What it does |
| --- | --- |
| `dev` | Starts the dev server at `http://localhost:5173`. |
| `build` | Makes the production build. |
| `preview` | Serves the production build, so you can click through the real thing. |
| `check` | Runs the format and lint checks. |
| `doctor` | Checks your setup, then runs a production build. |
| `fmt` | Formats your files. |
| `test` | Runs your tests with Vitest. |

`dev` is where you spend your day. Run `preview` before you ship. It serves the real production build, so you click what your users will get.

If something is wrong with the setup, run `npm run doctor` first. It checks that the `@markless/*` packages are there, on matching versions. It checks the editor wiring in `tsconfig.json`, and then it runs a build.

## Pick a different starter

Pass a folder name and `--yes` to skip the questions and take the defaults:

```bash
npm create markless@latest my-app -- --yes
```

Add `--starter` to pick another starter:

```bash
npm create markless@latest my-app -- --yes --starter app
```

| Starter | Shown in the menu as | What you get |
| --- | --- | --- |
| `minimal` | Learn Markless | One counter page. This is the default. |
| `app` | Build an app | A `document.tsrx` page shell, plus 404 and 500 pages. |
| `full-stack` | Full-stack app | The `app` starter, plus `api/` and `middleware/` folders. |
| `docs` | Write docs | A docs site written in MDX, with a layout and a sidebar. |

Other flags: `--format` with `node`, `deno` or `bun`, `--no-install`, `--no-git`, `--agents none`, and `--workspace`.
