## How it works

You keep your app running the whole time. A new Markless app sits in front of it and passes every page it has not taken over yet straight to the old one, so you can ship on day one.

1. **Plan.** The tool reads your app, live and from its source, and lists every page, link, form, script and library it uses.
2. **Convert.** Your coding agent moves one page to Markless.
3. **Check.** The tool opens that page in the old app and the new one, side by side in a real browser, and compares what users, search engines and screen readers would get. Anything different comes back with the line to fix, and your agent fixes it.
4. **Switch.** When the page matches, it switches over. Then the next page.

## What "matches" means

A page only switches when all of these match the original:

- what it shows, at desktop and phone sizes, in light and dark mode, hovered and focused
- every button, link, menu, dialog and form, clicked and typed into
- the requests it makes to your API or CMS, and what it saves
- the title, description, links and metadata search engines read
- what a screen reader announces, and the order the Tab key follows
- every language your site offers
- who can see it when signed in, signed out, or as each role
- its fonts, images and files, at the same addresses

Each page also shows how much JavaScript runs when it loads, before and after.

Something you changed on purpose, like a fixed typo, can be accepted with a reason. Only a person can accept a difference, never the agent.

## Use your own agent

There is no new AI to sign up for. The tool works through the agent you already pay for: Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot or opencode. One command adds the migration tools and instructions to each one it finds on your machine:

```bash
npx @markless/migrate setup
```

Then ask your agent to migrate your app. Or let it run on its own, page by page, until every page matches or one needs you:

```bash
npx @markless/migrate run --agent claude
```

## What doesn't carry over

Libraries built for another framework, like React component kits, can't run inside Markless. The tool lists exactly which parts of each library your app uses. Plain libraries like zod or date-fns stay as they are. Components like menus and dialogs move to [@markless/ui](/ui). For the rest, your agent writes a Markless version of only the parts you use, and the same checks prove it behaves the same everywhere it appears.
