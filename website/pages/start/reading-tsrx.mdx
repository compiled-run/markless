# Reading a .tsrx file

<Subtitle text="A .tsrx file is JavaScript with your page's elements written right inside it." />

```tsrx title="cart.tsrx"
import { state } from '@markless/core';

export default function Cart() @{
	let bags = state(2);

	<button onClick={() => bags++}>{bags} bags</button>
}
```

## Elements are the things on the page

An **element** is one thing on the page: a button, a paragraph, a list. You write it as a **tag**. `<button>` opens it, `</button>` closes it, and whatever sits between them is inside it: here, the words "2 bags".

Elements go inside other elements, the way a list holds its items. An opening tag can also carry **attributes**, settings like `class="big"`. An element with nothing inside closes itself with a slash: `<input />`.

Seen HTML before? The tags will look familiar, and attributes use their HTML names, like `class` and `for`. The difference is that these tags can also hold JavaScript. That's what the curly braces are for.

## Two kinds of slots

- **`{ }` means "a value goes here."** `{bags}` puts the number on the button. `onClick={() => bags++}` hands the button what to do when it's clicked: add one to `bags`. (For developers: a JavaScript *expression*.)
- **`@{ }` means "instructions run here, top to bottom."** First `let bags = …` runs, then the `<button>` at the end is what shows up. (For developers: JavaScript *statements*.)

Everything else in a `.tsrx` file is built from these two.

## `{ }`: a value goes here

Braces hold one value, or code that works one out. They go in the words between tags and in attributes. Quotes are fixed text, as in `class="card"`. Braces are code, as in `title={'Add ' + name}`.

## `@{ }`: instructions run here, top to bottom

A component's body is a statement slot. The instructions run in order, and the body ends with the one thing it shows: an element, a fragment or a block. There's no `return`.

To show several elements side by side, wrap them in `<>` and `</>`. That pair is a **fragment**: it holds elements together and adds nothing to the page. You can also open a fresh `@{ }` among the elements, and write `//` comments between them.

<Code note="After </section>, add <p>Thanks!</p> and read the build error. Then wrap both in <> and </>.">
```tsrx title="receipt.tsrx"
export default function Receipt() @{
	const price = 14;
	const bags = 3;
	const total = price * bags;

	<section>
		<p>{bags} bags at {price} dollars</p>
		// the tip only matters here
		@{
			const tip = total / 10;
			<p>Tip: {tip} dollars</p>
		}
		<p>Total: {total} dollars</p>
	</section>
}
```
</Code>

Two things at the end of a body, or an instruction after its element, stop the build with `MARKLESS_PARSE_ERROR`, and the message says how to fix it. One limit today: a fresh `@{ }` works inside an element, but not straight inside a `<>` at the top of a component.

Already use TypeScript? It works here too: add types wherever you want them.

## Calls that tell Markless how a value behaves

Some instructions call a function from `@markless/core`. They're ordinary function calls, and each one tells Markless how that value behaves:

- `let bags = state(2)` is a value the page keeps up with. You read it and change it like any variable. [State](/concepts/state)
- `const total = computed(() => bags * 14)` is a value worked out from others, and kept up to date for you. [Computed](/concepts/computed)
- `const field = element()` is a handle to a real element, for code that needs the element itself. [Reach a real element](/build/elements)

### Follow the wire

The jar is `bags` and the box is `total`, both set up by the instructions in `@{ }`. Each wire ends at a `{ }` slot, so **Add to cart** redraws the badge, the cart line and the total, and nothing else.

## Blocks that start with `@`

Among the elements, a line that starts with `@` is a block. Its parentheses hold a value, like a `{ }` slot. Its braces are a small statement slot: instructions first, then one thing to show.

- `@if (test) { … } @else { … }` shows one side or the other.
- `@for (const bag of bags; key bag.id) { … } @empty { … }` repeats once per item. `key` names each item, so rows stay put when the list changes.
- `@switch (value) { @case 'a': { … } @default: { … } }` picks one case.
- `@try { … } @pending { … } @catch { … }` waits for a value that takes time. [Async](/concepts/async) shows it running.

<Code steps={[{ label: 'Click Add a decaf until shipping is free.', shows: 'Free shipping!' }, { label: 'Click Empty the cart. The `@empty` row takes over.', shows: 'Your cart is empty.' }, { label: 'Make shipping free from four bags: change `3` to `4`.', source: '4 - bags.length' }]}>
```tsrx title="cart-list.tsrx"
import { computed, state } from '@markless/core';

export default function CartList() @{
	let bags = state([
		{ id: 'house', name: 'House blend' },
		{ id: 'dark', name: 'Dark roast' },
	]);
	const left = computed(() => 3 - bags.length);

	<section>
		<ul>
			@for (const bag of bags; key bag.id) {
				<li>{bag.name}</li>
			} @empty {
				<li>Your cart is empty.</li>
			}
		</ul>
		@if (left <= 0) {
			<p>Free shipping!</p>
		} @else {
			<p>Add {left} more for free shipping.</p>
		}
		<button
			onClick={() =>
				(bags = [
					...bags,
					{
						id: 'decaf' + bags.length,
						name: 'Decaf',
					},
				])
			}
		>
			Add a decaf
		</button>
		<button onClick={() => (bags = [])}>
			Empty the cart
		</button>
	</section>
}
```
</Code>

A few limits today. Write `@else` with its `@`; a plain `else` stops the build with `MARKLESS_BRANCH_ELSE_SPELLING`. An `@if` or `@switch` inside another `@if` stops the build with `MARKLESS_BRANCH_ARM_UPDATE_UNSUPPORTED`, so put them side by side. And a `const` at the top of an `@try`, `@pending` or `@catch` body doesn't work yet; a fix is on the way. [Conditionals](/concepts/conditionals) and [Lists](/concepts/lists) go deeper.

## Other things you'll spot

- `onClick={…}`, `onInput={…}` and the other `on…` attributes run code when something happens. [Events](/concepts/events)
- `attach={…}` runs your code with the real element, and `el={…}` links an `element()` handle to one. [Reach a real element](/build/elements)
- A `<style>` block holds CSS that only reaches the elements in its own file. [Styling](/concepts/styling)

## Which code runs when

| What you wrote | When it runs |
| --- | --- |
| Instructions in `@{ }` | Once, when that piece of the page is built: on the server for the first visit, or in the browser when a block adds it later. |
| `{ }` in the elements | Once to fill the spot, then again only when a value it reads changes. |
| A `computed()` recipe | When the page first needs it, then after a value it reads changes. |
| `onClick` and other `on…` handlers | In the browser, every time the event happens. |
| `attach` | In the browser, once the element needs it. |
| `<style>` | Never. It becomes a CSS file. |

The quick way to read it: a function handed to something, as in `onClick={…}`, `attach={…}` or `computed(…)`, runs later and maybe many times. Everything else in `@{ }` runs once, top to bottom.

That's why `let total = bags * 14` in a body never catches up with `bags`: the line ran once. A value made from `state()` belongs in `computed()`.

Most of it will feel familiar. Here's what's different:

- **No `return`.** A component's body opens with `@{` and ends with what it shows.
- **HTML names.** Write `class` and `for`, the way HTML does.
- **No setters or hooks.** `state()` gives you a plain variable. Assign to it.
- **No dependency arrays and no effects.** `computed()` finds what it reads, and side work goes in the handler that causes it.
- **Braces hold values, not elements.** Use `@if` and `@for`, not `{open && <p>…</p>}` or `{items.map(…)}`.
- **The key lives in the loop.** Write `key bag.id` in the `@for` line.
- **Nothing re-renders.** A component runs once to build its piece of the page. A click runs only its handler, and only the spots that read a changed value update.

## The other files in an app

An app from `npm create markless` has a few files around its components:

| File | What it does |
| --- | --- |
| `pages/index.tsrx` | The page at `/`. The file name is the URL, so `pages/about.tsrx` is `/about`. |
| `pages/404.tsrx`, `pages/500.tsrx` | The pages for "not found" and "something went wrong", in the `app` starter. |
| `document.tsrx` | The page around every page, built with `<Html>` from `@markless/router`. |
| `public/` | Files served as they are, like images. |
| `vite.config.ts` | Turns on Markless and its router. |
| `tsconfig.json` | Lets your editor read `.tsrx` files. |
