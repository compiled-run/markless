# A .tsrx file is TypeScript with markup in it

<PageMeta level="Start here" time="6 min" assumes="nothing" sprite="bookmark" />

<ThemeToggle />

Open a `.tsrx` file and most of it looks familiar. Imports are imports. A component is a function. Types are types.

A few things are new. This page goes through each of them. Then it walks through the other files in a starter app.

## The counter, line by line

Here is the counter again. Click it once, so you know what the code does:

<CounterDemo />

```tsrx
import { state } from '@markless/core';

export default function Counter() @{
	let count = state(0);

	<button onClick={() => count++}>Count {count}</button>
}
```

<LineToPart />

**`import { state } from '@markless/core'`** is a normal import. `@markless/core` is the main Markless package.

**`export default function Counter() @{`** starts a component. A component is a function, and its body opens with `@{` instead of `{`.

**`let count = state(0)`** makes a value the page follows. It is still a `let`, and it starts at `0`.

**`<button ...>`** is the markup. You do not `return` it. You write it in the body as a statement, like the `let` line above it.

**`onClick={() => count++}`** handles a click. An event prop is `on` plus the event name, so `onInput` and `onKeyDown` work the same way.

**`{count}`** is a hole in the markup. Curly braces hold any expression, in text or in an attribute. When `count` changes, that text changes with it.

## More than one element

A body can make more than one element. Write them one after the other, the same way you write two statements.

<Code note="Add a third line that shows count times two, with {count * 2}. Then move the paragraph below the button.">
```tsrx title="labelled-counter.tsrx"
import { state } from '@markless/core';

export default function LabelledCounter() @{
	let count = state(0);

	<p>You clicked {count} times.</p>
	<button onClick={() => count++}>Click me</button>
}
```
</Code>

The paragraph reads `count`. Click the button, and only the number in the paragraph changes.

## Lines that start with @ control the markup

An at sign at the start of a line inside markup starts a block. `@if` shows markup only while a condition is true. `@for` repeats markup for each item in a list.

<Code note="After the closing brace of the @if, add @else { <p>The note is hidden.</p> } and press the button. Then change the note text, and the class name in both places.">
```tsrx title="tea-note.tsrx"
import { state } from '@markless/core';

export default function TeaNote() @{
	let open = state(false);

	<section>
		<style>
			.note {
				font-style: italic;
			}
		</style>
		<button onClick={() => (open = !open)}>{open ? 'Hide' : 'Show'} the note</button>
		@if (open) {
			<p class="note">Steep it for three minutes.</p>
		}
	</section>
}
```
</Code>

This file shows one more thing: the `<style>` block. Its rules reach the elements in this file and nothing else. Another file can use the class `note` for something different.

[Conditionals](/concepts/conditionals), [Lists](/concepts/lists) and [Styling](/concepts/styling) go deeper on each of these.

## The other files in a starter app

A new app from `npm create markless` has more files around your components. Here is the `app` starter:

```txt
my-app/
  pages/
    index.tsrx
    404.tsrx
    500.tsrx
  public/
  scripts/
    markless-doctor.mjs
  .vscode/
  .zed/
  document.tsrx
  vite.config.ts
  tsconfig.json
  package.json
  README.md
  .gitignore
```

The default `minimal` starter has the same files, minus `document.tsrx`, `404.tsrx` and `500.tsrx`.

| File | What it does |
| --- | --- |
| `pages/index.tsrx` | The page at `/`. It holds the counter. |
| `pages/404.tsrx` | The page you get when no page matches the URL. It says "Not found". |
| `pages/500.tsrx` | The page you get when a page fails with an error. It says "Something went wrong". |
| `document.tsrx` | The HTML shell around every page, built with `<Html>` from `@markless/router`. |
| `public/` | Files your app serves as they are, like images. It starts empty. |
| `vite.config.ts` | Adds the `markless()` and `router()` plugins. |
| `tsconfig.json` | Lets your editor read `.tsrx` files. |
| `scripts/markless-doctor.mjs` | Checks your setup. Run it with `npm run doctor`. |
| `.vscode/`, `.zed/` | Editor settings. VS Code suggests the TSRX extension. |

Every starter has this `vite.config.ts`:

```ts
import { markless } from '@markless/core/vite';
import { router } from '@markless/router/vite';
import { defineConfig } from 'vite-plus';

export default defineConfig({
	plugins: [markless(), router()],
});
```

Compare it with the [browser-only setup](/start/browser-only). It has one more plugin, `router()`, and that plugin turns `pages/` into URLs.

The `full-stack` starter adds two more files. `api/health.ts` answers a request with `ok`. `middleware/request.ts` adds a header to every response.
