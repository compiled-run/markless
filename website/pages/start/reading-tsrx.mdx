## Write an element

Here's one button, taken apart: its code on one sheet, the page it makes on the other. Press the drawing.

<PartsAnatomy />

The click ran `bags++`, and the one number wired to `{bags}` changed. Nothing else on the page moved.

An **element** is one piece of the page: a button, a paragraph, a list. You write it as a **tag**. `<button>` opens it, `</button>` closes it, and whatever sits between the two is inside it. Here that's the text `Add to cart:` and a value.

An **attribute** is a setting on the element, written inside the opening tag as `name="value"`. They're the attributes HTML already has: `class`, `type`, `href`, `disabled`.

Elements go inside elements. That's how you build a whole page:

<Code steps={[{ label: 'Change the heading to `Dark roast`.', shows: 'Dark roast' }, { label: 'Under the first paragraph, add `<p>250 g bag</p>`.', shows: '250 g bag' }, { label: 'Give the input a `placeholder="How many?"` attribute.', source: 'placeholder="How many?"' }]}>
```tsrx title="bean-card.tsrx"
export default function BeanCard() @{
	<article class="card">
		<h2>House blend</h2>
		<p>Chocolate, hazelnut, a little cherry.</p>
		<label>
			Bags
			<input type="number" />
		</label>
	</article>
}
```
</Code>

Text goes straight between tags, no quotes needed. An element with nothing inside, like `<input />`, closes itself with `/>`. Leave the slash off and the build stops.

## Put a value on the page with `{ }`

Click **Add a bag** and watch both lines.

<Code steps={[{ label: 'Click **Add a bag**. Both lines change together.', rewrites: 2 }, { label: 'Make a bag cost 16: change `14` to `16`.', source: 'bags * 16' }, { label: 'Start with 5 bags.', source: 'state(5)' }]}>
```tsrx title="cart-line.tsrx"
import { state } from '@markless/core';

export default function CartLine() @{
	let bags = state(2);

	<section>
		<p>In your cart: {bags} bags</p>
		<p>Total: {bags * 14} dollars</p>
		<button title={'You have ' + bags} onClick={() => bags++}>
			Add a bag
		</button>
	</section>
}
```
</Code>

Curly braces hold an **expression**: any bit of code that produces a value. `bags` is an expression. So are `bags * 14` and `'You have ' + bags`. Markless puts the value on the page, in text or in an attribute, and keeps it current.

`state(2)` makes a value the page follows, starting at 2. [State](/concepts/state) covers it properly.

Quotes or braces? Quotes are fixed text: `class="buy"`. Braces are code: `title={'You have ' + bags}`.

## Run code on a click

`onClick={() => bags++}` is an **event handler**. Its value is a function, and Markless calls it every time someone clicks. The name is `on` plus the event, with a capital letter: `onClick`, `onInput`, `onKeyDown`, `onSubmit`.

Write it in lowercase, as `onclick`, and it's a plain attribute, not a handler. The build warns you.

## Statements go in `@{ }`, values go in `{ }`

There are two kinds of code, and a `.tsrx` file has a box for each.

An **expression** produces a value. `bags * 14` is 28 when `bags` is 2.

A **statement** does something. `let bags = state(2)` makes a variable. `if` decides. `for` repeats. A statement has no value to show.

Press the drawing to run the file.

<BoxesAnatomy />

The statements ran in order, top to bottom. Then the paragraph showed up, and its braces handed it one value.

| | `@{ }` statement container | `{ }` expression container |
| --- | --- | --- |
| Holds | statements: `let`, `const`, `@if`, `@for`, then elements | one expression |
| Gives the page | the one element it ends with | a value, in text or an attribute |
| Example | `function Cart() @{ let bags = state(2); <p>…</p> }` | `<p>Total: {bags * 14}</p>` |

A component's body is a statement container: it opens with `@{` instead of `{`. Write your statements first, then one element at the end. No `return`.

One element? To show several, wrap them in `<>` and `</>`. That pair is a **fragment**: it holds elements together and adds nothing to the page.

<Code note="Add a third paragraph that shows {count * 2}. Then take the <> and </> away and read the build error.">
```tsrx title="labelled-counter.tsrx"
import { state } from '@markless/core';

export default function LabelledCounter() @{
	let count = state(0);

	<>
		<p>You clicked {count} times.</p>
		<button onClick={() => count++}>
			Click me
		</button>
	</>
}
```
</Code>

Try putting a statement in braces, like `{let x = 1}`. The build stops: braces take one expression, nothing more.

## Show and repeat with @if and @for

Here's where statements pay off. Right among your elements, a line that starts with `@` is a block: `@if` shows its elements only while its test is true, and `@for` repeats its elements once per item.

Press the drawing to add a third bag.

<FlowAnatomy />

The `@for` drew one more row. With three bags, the `@if` test turned true, so its note landed on the page. Press again and both go away.

<Code steps={[{ label: 'Click **Add a bag** until shipping is free.', shows: 'Free shipping!' }, { label: 'Click **Empty the cart**. The `@empty` row takes over.', shows: 'Your cart is empty.' }, { label: 'Make shipping free from 2 bags: change `2` to `1` in the `@if` test.', source: 'bags.length > 1' }]}>
```tsrx title="cart-list.tsrx"
import { state } from '@markless/core';

export default function CartList() @{
	let bags = state([
		{ id: 'house', name: 'House blend' },
		{ id: 'dark', name: 'Dark roast' },
	]);

	<section>
		<ul>
			@for (const bag of bags; key bag.id) {
				<li>{bag.name}</li>
			} @empty {
				<li>Your cart is empty.</li>
			}
		</ul>
		@if (bags.length > 2) {
			<p>Free shipping!</p>
		} @else {
			const left = 3 - bags.length;
			<p>Add {left} more for free shipping.</p>
		}
		<button onClick={() => (bags = [...bags, { id: 'bag' + bags.length, name: 'Decaf' }])}>
			Add a bag
		</button>
		<button onClick={() => (bags = [])}>Empty the cart</button>
	</section>
}
```
</Code>

Look at the `@else` block. It starts with `const left = ...`, a statement, right where the elements are. Each block's body is a statement container too.

`@for` needs a `key`: something that names each item, like `bag.id`. That's how a row keeps its own state when the list changes. `@empty` shows when the list has nothing in it.

Two more blocks work the same way. `@switch` picks one of several cases, and `@try` waits for data. [Conditionals](/concepts/conditionals), [Lists](/concepts/lists) and [Async](/concepts/async) go deeper.

<Callout
	sprite="cross"
	title="Why did plain else stop the build?"
	text="After an @if, write @else with the at sign. A plain else stops the build with MARKLESS_BRANCH_ELSE_SPELLING."
/>

<Collapsible sprite="star-badge" summary="Coming from JSX?">

Most of it will feel familiar. Here's what's different:

- **No `return`.** A component's body opens with `@{` and ends with its element.
- **HTML names.** Write `class` and `for`, the way HTML does. The type checker rejects `className`.
- **Braces hold values, not elements.** `{open && <p>…</p>}` and `{items.map(…)}` render once and never update, and the build warns. Use `@if` and `@for`.
- **The key lives in the loop.** Write `key bag.id` in the `@for` line, not on the element. Every `@for` needs one.
- **Comments are plain.** Write `// note` on its own line among elements. No `{/* */}` needed.
- **Styles stay local.** A `<style>` block inside a component only reaches that component's elements.
- **Nothing re-renders.** A component runs once, to set up the page. A click runs only its handler, and only the spots that read a changed value update.

</Collapsible>

## The other files in a starter app

A new app from `npm create markless` has more files around your components. Here is the `app` starter:

```txt
my-app/
  pages/
    index.tsrx
    404.tsrx
    500.tsrx
  public/
  scripts/
    markless-doctor.mjs
  .vscode/
  .zed/
  document.tsrx
  vite.config.ts
  tsconfig.json
  package.json
  README.md
  .gitignore
```

The default `minimal` starter is the same, minus `404.tsrx` and `500.tsrx`.

| File | What it does |
| --- | --- |
| `pages/index.tsrx` | The page at `/`. It holds the counter. |
| `pages/404.tsrx` | The page you get when no page matches the URL. It says "Not found". |
| `pages/500.tsrx` | The page you get when a page fails with an error. It says "Something went wrong". |
| `document.tsrx` | The HTML shell around every page, built with `<Html>` from `@markless/router`. |
| `public/` | Files your app serves as they are, like images. It starts empty. |
| `vite.config.ts` | Adds the `markless()` and `router()` plugins. `router()` turns `pages/` into URLs. |
| `tsconfig.json` | Lets your editor read `.tsrx` files. |
| `scripts/markless-doctor.mjs` | Checks your setup. Run it with `npm run doctor`. |
| `.vscode/`, `.zed/` | Editor settings. VS Code suggests the TSRX extension, `ripple-ts.ripple-ts-vscode-plugin`. |

The `full-stack` starter adds two more files. `api/health.ts` answers a request with `ok`. `middleware/request.ts` adds a header to every response.
