## Create your app

<CreateAnatomy />

Run this in the folder that will hold your project:

```bash
npm create markless@latest
```

That needs Node.js. On Bun, run `bun create markless`. On Deno, run `deno run -A npm:create-markless`. If your Node.js is too old for a new app, the command says so and stops before writing anything.

It asks a few questions. Each one has a default, so you can press Enter all the way through.

1. `What are you building today?` **Learn Markless** is the default, a small counter app.
2. `What should we call it?` This is the folder name. The default is `my-markless-app`.
3. `Where should it run?` Node, Deno or Bun. Not sure? Pick Node.
4. `Install dependencies now?` and `Initialize git?` Both default to yes.

It can ask two more. Inside an existing workspace, it asks whether the new app joins that workspace. If it finds coding agents on your machine, it offers to set Markless up for them.

Last comes a summary under `Ready to create?` Nothing is written until you pick **Create app**.

## Start it, and open your page

```bash
cd my-markless-app
```

```bash
npm run dev
```

<DevServer />

Open `http://localhost:3000`. You see a heading and a button. That whole page is one file, `pages/index.tsrx`.

## Change one line, see your page change

Here is that file, live. Click **Count 0** a few times, then try these:

<Code steps={[{ label: 'Change the heading to `My first app`.', shows: 'My first app' }, { label: 'Start the count at `10` instead of `0`.', source: 'state(10)' }, { label: 'Under the button, add `<p>Clicked {count} times</p>`. Click the button, and both lines update.', rewrites: 2 }]}>
```tsrx title="index.tsrx"
import { state } from '@markless/core';

export default function Home() @{
	let count = state(0);

	<main>
		<h1>Markless Router</h1>
		<button onClick={() => count++}>
			Count {count}
		</button>
	</main>
}
```
</Code>

Make the same change in your own `pages/index.tsrx` and save it. The page at `localhost:3000` shows it.

The file is named `index`, so it is the page at `/`. Add `pages/about.tsrx`, and you have a page at `/about`.

## Ship it, one script at a time

Your folder's `package.json` has seven scripts:

```bash
npm run dev       # starts the dev server at localhost:3000
npm run build     # makes the production build
npm run preview   # serves the production build, so you click the real thing
npm run check     # runs the format and lint checks
npm run doctor    # checks your setup, then runs a production build
npm run fmt       # formats your files
npm run test      # runs your tests with Vitest
```

`dev` is where you spend your day. Before you ship, run `build` and then `preview`. It serves the real production build, so you click what your users will get.

Something wrong with the setup? Run `npm run doctor` first. It checks that the `@markless/*` packages are there, on matching versions. It checks the editor wiring in `tsconfig.json`, and then it runs a build.

On Deno the scripts are tasks, so you run `deno task dev`. Deno has no `doctor` task.

## Try a different starter

Every starter writes the same base files, then a few of its own. Pick a different answer to the first question in the terminal above to see exactly which files each one writes.

To skip the questions, name the folder, add `--yes` and pick a starter:

```bash
npm create markless@latest my-app -- --yes --starter minimal      # Learn Markless: one counter page
npm create markless@latest my-app -- --yes --starter app          # Build an app: plus 404 and 500 pages
npm create markless@latest my-app -- --yes --starter full-stack   # Full-stack app: plus api/ and middleware/
npm create markless@latest my-app -- --yes --starter docs         # Write docs: an MDX docs site
```

`--yes` takes the default for every question a flag did not answer. The other flags: `--format` with `node`, `deno` or `bun`, `--no-install`, `--no-git`, `--agents` with a list or `none`, `--workspace` or `--no-workspace`, and `--force` to write into a folder that is not empty.
