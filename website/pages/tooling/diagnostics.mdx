# Diagnostics

<PageMeta time="2 min" assumes="lists" />

<Subtitle text="A diagnostic is the message Markless gives when it can't compile your code: what broke, why, how to fix it, and where to read more." terms="compile" />

```text title="npm run build"
MARKLESS_COMPILE_BLOCKED: pages/list.tsrx has 1 compiler error(s).

MARKLESS_REPEAT_KEY_REQUIRED: @for (const item of items) repeats reactive state without a key. When items changes, the rows of this list have no identity to update, reorder, or resume by. (pages/list.tsrx:8:4)
```

**`MARKLESS_REPEAT_KEY_REQUIRED`** is the code, and every code has [its own page](/errors/MARKLESS_REPEAT_KEY_REQUIRED). The sentence after it says what broke, and **`pages/list.tsrx:8:4`** is the file, line and column.

## An error has four parts

An *error* stops the page. In the dev server, the browser shows it on top of the page. Remove the key, then add it back:

<OverlayFigure />

- The code, what broke, and where.
- **Why** Markless can't build it.
- **Suggested fix**: the first fix to try.
- A link to the page for that code.

## A key fixes this list

This list builds. Try it:

<Code steps={[{ label: 'Press Add an item.', shows: 'Tea 2' }, { label: 'Key the rows by position: change `key item` to `index i; key i`.', source: 'index i; key i' }]}>
```tsrx title="list.tsrx"
import { state } from '@markless/core';

export default function List() @{
	let items = state(['Milk', 'Eggs']);

	<section>
		<ul>
			@for (const item of items; key item) {
				<li>{item}</li>
			}
		</ul>
		<button
			onClick={() => {
				items = [...items, 'Tea ' + items.length];
			}}
		>
			Add an item
		</button>
	</section>
}
```
</Code>

Delete the key from the `@for` line, and the error shows under the result.

## A reason silences a warning

A *warning* is a wavy line in your editor, and the page still builds. To accept one on purpose, write `// markless-allow CODE: reason` above it:

```tsrx
// markless-allow MARKLESS_REPEAT_KEY_IS_INDEX: a fixed list
@for (const item of items; index i; key i) {
```

A comment with no reason doesn't silence anything; the figure above shows what happens instead.

[All error codes](/errors) lists every one, grouped by the package that raises it, and each has a page with its fix.
