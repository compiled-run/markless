# Make your editor read `.tsrx` files

<PageMeta time="2 min" assumes="reading-tsrx" sprite="cursor" />

<ThemeToggle />

Open a `.tsrx` file in a fresh editor and you get plain grey text. No suggestions, no red lines, no
help.

Two pieces fix that. An editor extension knows the TSRX syntax, so it adds the colours. A
TypeScript plugin, named in `tsconfig.json`, knows Markless. It adds everything else.

Turn each piece on, and watch what changes.

<EditorDemo />

Only the colours come from the extension. The hint after `<widget.trigger`, the wavy line under
`onClik`, and the menu after `@` all come from the plugin. Any editor that runs TypeScript's own
language server can load the plugin.

## Check `tsconfig.json`

An app from `npm create markless` already has these lines:

```json
{
	"tsrx": {
		"compiler": "@markless/typescript-plugin/volar"
	},
	"compilerOptions": {
		"jsx": "preserve",
		"plugins": [
			{ "name": "@markless/typescript-plugin" },
			{ "name": "@markless/router/typescript-plugin" }
		]
	}
}
```

| Line                                 | What it does                                                 |
| ------------------------------------ | ------------------------------------------------------------ |
| `tsrx.compiler`                      | Tells the TSRX tools to read `.tsrx` files the Markless way. |
| `@markless/typescript-plugin`        | Adds Markless suggestions, part hints, and `.tsrx` imports.  |
| `@markless/router/typescript-plugin` | Suggests your page addresses inside `href`.                  |

## Pick your editor

**VS Code.** Install the TSRX extension. The starter's `.vscode/extensions.json` recommends it, so VS
Code offers it when you open the app.

```bash
code --install-extension ripple-ts.ripple-ts-vscode-plugin
```

Markless no longer ships its own extension. If you installed an old build by hand, remove it.
Otherwise two extensions fight over `.tsrx` files.

```bash
code --uninstall-extension markless.markless
```

**Zed.** The starter writes `.zed/settings.json` for you. It opens `.tsrx` files as TSX and loads
the Markless plugin into Zed's TypeScript server. You have nothing to install.

**Other editors.** WebStorm and other editors built on TypeScript's language server read the same
`tsconfig.json` lines.

## What you get

Type `@` in a component body, and the editor offers blocks like `@if`, `@for`, and `@try`. After a
UI component part like `<widget.trigger>`, a small hint names the HTML element it renders.

```tsrx
<widget.trigger value="go">Go</widget.trigger>
```

Here the editor shows `: button` right after `<widget.trigger`. To turn these hints off, add
`"partHints": false` to the plugin's entry in `tsconfig.json`.

## TypeScript 7.1 (experimental)

The Markless plugin runs on TypeScript 5.9. TypeScript 7 cannot load plugins, so it reads `.tsrx`
files through a content mapper instead: a separate program, named in `tsconfig.json`, that hands it
the TSX copy. An editor on the TypeScript 7.1 beta can use `@tsrx/content-mapper`, which follows
the `tsrx.compiler` line above. The [TSRX VS Code setup](https://github.com/tsrx-org/tsrx/tree/main/packages/vscode-plugin#native-backend-setup)
shows the settings.

```json
{
	"contentMappers": [{ "package": "@tsrx/content-mapper", "extensions": [".tsrx"] }]
}
```

Hover, go to definition, member and prop suggestions, and type errors work. These do not, yet:

- the `@` block suggestions, part hints, and the Markless order of tag suggestions
- an auto-import that adds a new `import` line ([microsoft/TypeScript#64119](https://github.com/microsoft/TypeScript/issues/64119))
- rename where the TSX copy spells a name differently ([microsoft/TypeScript#63879](https://github.com/microsoft/TypeScript/issues/63879))
- suggestions right after a fresh `.`; a half-typed file can also show errors in code the editor
  filled in to keep reading it
- Find File References and Go to Source Definition

[tsrx-org/tsrx#136](https://github.com/tsrx-org/tsrx/issues/136) tracks every known gap. Stay on
TypeScript 5.9 for daily work.
