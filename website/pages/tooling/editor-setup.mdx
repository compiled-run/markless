# Make your editor read `.tsrx` files

<PageMeta time="3 min" assumes="reading-tsrx" />

<ThemeToggle />

<Subtitle text="Two pieces make your editor understand a .tsrx file: an extension adds the colours, and a TypeScript plugin adds everything else." />

- **The TSRX extension** colours the syntax. It knows `@if` and `@{ }`, but nothing about Markless.
- **The Markless TypeScript plugin** adds suggestions, hints and red lines under mistakes, like `onClik` for `onClick`.

An app from `npm create markless` sets up both. This page shows where they live, so you can check them.

## Check `tsconfig.json`

The plugin is named in your app's `tsconfig.json`. A new app already has these lines:

```json title="tsconfig.json"
{
	"tsrx": {
		"compiler": "@markless/typescript-plugin/volar"
	},
	"compilerOptions": {
		"jsx": "preserve",
		"plugins": [
			{ "name": "@markless/typescript-plugin" },
			{ "name": "@markless/router/typescript-plugin" }
		]
	}
}
```

| Line | What it does |
| --- | --- |
| `tsrx.compiler` | Tells the TSRX tools to read `.tsrx` files the Markless way. |
| `@markless/typescript-plugin` | Adds Markless suggestions, hints, errors and `.tsrx` imports. |
| `@markless/router/typescript-plugin` | Suggests your page addresses inside `href`. |

Not sure a line is right? Run `npm run doctor -- --no-build`. It checks the `tsrx.compiler` line and prints the line to add if it's missing.

## Pick your editor

- **VS Code, Cursor or Windsurf.** Install the TSRX extension. The app's `.vscode/extensions.json` recommends it, so the editor offers it when you open the folder.
- **Zed.** Nothing to install. The app's `.zed/settings.json` opens `.tsrx` files as TSX and loads the plugin into Zed's TypeScript server.
- **Any other editor** that runs TypeScript's own language server, such as WebStorm, reads the same `tsconfig.json` lines.

```bash
code --install-extension ripple-ts.ripple-ts-vscode-plugin
```

That installs the TSRX extension from a terminal. If you once installed the old `markless.markless` extension by hand, remove it with `code --uninstall-extension markless.markless`, or the two fight over `.tsrx` files.

## What the plugin adds

- Type `@` in a component body, and the editor offers `@if`, `@for` and `@try`.
- After a tag whose props come from one HTML element, a small hint names that element. `<tabs.trigger` shows `: button`.
- A wrong prop, a misspelt handler or an unknown attribute gets a red line, with TypeScript's own message.

To turn the element hints off, add `"partHints": false` to the plugin's entry:

```json title="tsconfig.json"
{ "name": "@markless/typescript-plugin", "partHints": false }
```

## TypeScript 7.1 is experimental

The plugin runs on TypeScript 5.9. TypeScript 7 can't load plugins, so it reads `.tsrx` files through [`@tsrx/content-mapper`](https://github.com/tsrx-org/tsrx/tree/main/packages/vscode-plugin#native-backend-setup) instead. Hover, go to definition, suggestions for members and props, and type errors all work there.

Not yet, on TypeScript 7.1:

- `@` block suggestions and element hints.
- An auto-import that adds a new `import` line ([microsoft/TypeScript#64119](https://github.com/microsoft/TypeScript/issues/64119)).
- Rename, where the TSX copy spells a name differently ([microsoft/TypeScript#63879](https://github.com/microsoft/TypeScript/issues/63879)).
- Suggestions straight after a fresh `.`, Find File References and Go to Source Definition.

Stay on TypeScript 5.9 for daily work. [tsrx-org/tsrx#136](https://github.com/tsrx-org/tsrx/issues/136) tracks every known gap.

Your editor checks the file you have open. [Type checking](/tooling/type-checking) shows how TypeScript checks a `.tsrx` file at all.
