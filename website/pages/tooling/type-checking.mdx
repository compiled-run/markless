# How TypeScript checks a `.tsrx` file

<PageMeta level="Tooling" time="2 min" assumes="components" sprite="check" />

<ThemeToggle />

Your editor underlines mistakes in `.tsrx` files. But TypeScript has never heard of `.tsrx`. So who
checks them?

Markless hands TypeScript a TSX copy of each `.tsrx` file. TypeScript checks the copy, and every
error points back to the line you wrote. Your own file stays exactly as you wrote it.

Pick a value for `label`, then press **Check**.

<TypecheckDemo />

`Nav` wants `label` to be a `string`. Pass it `42`, and TypeScript reports that `number` is not
assignable to `string`. It points at `label` in `App.tsrx`, line 4.

## What gets checked

The copy keeps your real types, so a wrong prop is an error at the exact attribute. The check covers
the whole file: props, attributes, event handlers, and element handles.

```tsrx
import { Nav } from './Nav.tsrx';

export function App() @{
	<Nav label={42} />
}
```

## Working on Markless itself

In your own app, the editor checks types. `npm run build` stops on Markless errors, but it does not
run the type checker.

Inside the Markless repo, `pnpm typecheck` checks the whole workspace. It wraps `tsc`, so `-p`,
`--watch`, and every other `tsc` flag still work.

```bash
pnpm typecheck
```

A type error in a `.tsrx` file shows the file, the line, and the column. A file that does not parse
fails the run too:

```text
broken.tsrx(6,1): error TS91001: Markless TSRX parse error: Unexpected '}' in JSX text
counter.tsrx(9,8): error TS2322: Type 'string' is not assignable to type 'number'.
Found 1 Markless TSRX compile error.
```
