# The look is yours, the state is an attribute

<PageMeta level="Start here" time="6 min" assumes="styling" sprite="flower" />

<ThemeToggle />

Your select works. It opens, it picks, it talks to screen readers. It also looks like plain HTML
from 1998. Here is how you give it a look.

`@markless/ui` ships no stylesheet. Instead, each part writes its state onto its own element as a
`ui-*` attribute. You put a class on the part, and a plain CSS selector does the rest.

## A class and an attribute

Open the picker. Pick **Ink**, then open it again. Try to pick **Neon**.

<Code note="In the .picker[ui-open] .trigger rule, change the background to plum. Open the picker: the trigger turns plum while the list is open.">
```tsrx title="styled-picker.tsrx"
import { select } from '@markless/ui';

export default function StyledPicker() @{
	<section class="frame">
		<select.root class="picker">
			<select.label class="label">Theme</select.label>
			<select.trigger class="trigger">Choose a theme</select.trigger>
			<select.content class="list">
				<select.item class="option" value="paper">
					<select.itemlabel>Paper</select.itemlabel>
					<select.itemindicator class="mark">✓</select.itemindicator>
				</select.item>
				<select.item class="option" value="ink">
					<select.itemlabel>Ink</select.itemlabel>
					<select.itemindicator class="mark">✓</select.itemindicator>
				</select.item>
				<select.item class="option" value="neon" disabled>
					<select.itemlabel>Neon</select.itemlabel>
					<select.itemindicator class="mark">✓</select.itemindicator>
				</select.item>
			</select.content>
		</select.root>

		<style>
			.picker {
				display: grid;
				gap: 0.4em;
				width: min(16rem, 100%);
			}

			.label {
				font-weight: 700;
			}

			.trigger {
				padding: 0.5em 0.9em;
				border: 2px solid var(--ink);
				border-radius: 6px;
				background: var(--paper);
				color: var(--ink);
				font: inherit;
				text-align: start;
				cursor: pointer;
			}

			.picker[ui-open] .trigger {
				background: var(--yellow);
				color: var(--on-accent);
			}

			.list:not([hidden]) {
				display: grid;
				border: 2px solid var(--ink);
				border-radius: 6px;
				overflow: clip;
			}

			.option {
				display: flex;
				justify-content: space-between;
				padding: 0.45em 0.9em;
				cursor: pointer;
			}

			.option:focus-visible {
				outline: 2px solid var(--ink);
				outline-offset: -4px;
			}

			.option[ui-selected] {
				font-weight: 700;
			}

			.option[ui-disabled] {
				opacity: 0.5;
				cursor: not-allowed;
			}

			.mark[ui-hidden] {
				visibility: hidden;
			}
		</style>
	</section>
}
```
</Code>

The trigger turned yellow while the list was open, because `.picker[ui-open] .trigger` matched. **Ink** went
bold because its option gained `ui-selected`. **Neon** looks faded because it carries `ui-disabled`.
No line of TypeScript adds or removes a class. The family writes the attribute, and your
stylesheet reads it.

Most of these attributes are on/off flags with no value. `ui-open` is on the element while the
state holds, and gone when it does not. So `[ui-open]` is the whole selector.

A few attributes carry a value instead. An accordion item writes its own `value`, so
`[ui-value='returns']` reaches that one section:

```css
.section[ui-value='returns'][ui-open] {
	border-color: rebeccapurple;
}
```

## Your class names stay yours

The `<style>` block in a component belongs to that file. Markless scopes it, so a `.picker` here
cannot collide with a `.picker` two folders away. A class you put on a family part still reaches
it. The package's tests check exactly that, both in the browser alone and from server HTML.

These are the same [scoping rules](/concepts/styling) your own components already get.

## Defaults you can beat

A few families need some CSS to work at all. A tooltip has to sit next to its trigger. A drawer's
backdrop has to cover the page. Sixteen families ship that CSS inside a CSS layer named `markless`. They are
`colorpicker`, `crop`, `drawer`, `gridlist`, `hovercard`, `ink`, `menu`, `menubar`, `pad`,
`popover`, `rating`, `resizable`, `table`, `tokenbox`, `tooltip` and `tour`.

A rule in a layer loses to any rule outside a layer. So one plain rule of yours beats the default,
with no `!important` and no specificity fight.

Here is the line in the tooltip's own CSS that places the tip. It puts the tip above its trigger:

```css
@layer markless {
	[overlay] {
		position-area: block-start;
	}
}
```

This tip has one rule of yours on it, `position-area: inline-end`. That is enough to move it to the
right of **Save**:

<Code note="Change position-area: inline-end to block-end. The tip moves below Save, because your rule still beats the default in the layer.">
```tsrx title="save-tip.tsrx"
import { tooltip } from '@markless/ui';

export default function SaveTip() @{
	<section class="frame">
		<tooltip.root open={true}>
			<tooltip.trigger class="save">Save</tooltip.trigger>
			<tooltip.content class="tip">Keeps a copy in your drafts</tooltip.content>
		</tooltip.root>

		<style>
			.tip {
				position-area: inline-end;
				margin-inline-start: 0.5em;
				padding: 0.35em 0.65em;
				border-radius: 4px;
				background: var(--slab);
				color: var(--slab-ink);
				font-size: var(--step--1);
			}

			.frame {
				padding-block-end: 3rem;
				padding-inline-end: 12rem;
			}

			.save {
				padding: 0.5em 0.9em;
				border: 2px solid var(--ink);
				border-radius: 6px;
				background: var(--paper);
				color: var(--ink);
				font: inherit;
				font-weight: 700;
			}
		</style>
	</section>
}
```
</Code>

You moved the tip with CSS, not a prop. The tooltip has no prop for where it sits. Placement lives
in CSS, where your rule can change it.

## Parts that nest

A tree or a submenu does not need new parts for the next level down. It uses the same ones again.
A `tree.item` holds a `tree.itemcontent`, and that holds more `tree.item`s. Each nested item keeps
its own open or closed state, and the same CSS styles every level.

Click the arrow next to **src**. Then use the arrow keys to walk the rows.

<Code note="Add a third leaf under src, such as styles.css at level 2. Open src, then walk to the new row with the arrow keys.">
```tsrx title="files.tsrx"
import { tree } from '@markless/ui';

export default function Files() @{
	<tree.root class="files" aria-label="Project files">
		<tree.item class="row" level={1}>
			<tree.itemtrigger class="arrow-button">
				<tree.itemindicator class="arrow">▸</tree.itemindicator>
			</tree.itemtrigger>
			<tree.itemlabel>src</tree.itemlabel>
			<tree.itemcontent class="group">
				<tree.item class="row" leaf level={2}>
					<tree.itemlabel>index.ts</tree.itemlabel>
				</tree.item>
				<tree.item class="row" leaf level={2}>
					<tree.itemlabel>app.tsrx</tree.itemlabel>
				</tree.item>
			</tree.itemcontent>
		</tree.item>
		<tree.item class="row" leaf level={1}>
			<tree.itemlabel>README.md</tree.itemlabel>
		</tree.item>

		<style>
			.files {
				width: min(16rem, 100%);
				font-family: ui-monospace, monospace;
			}

			.row {
				padding: 0.2em 0.4em;
				border-radius: 4px;
			}

			.row[ui-leaf] {
				padding-inline-start: 2em;
			}

			.row:focus-visible {
				outline: 2px solid var(--ink);
			}

			.arrow-button {
				width: 1.4em;
				padding: 0;
				border: 0;
				background: none;
				box-shadow: none;
				color: var(--ink);
				font: inherit;
				cursor: pointer;
			}

			.arrow {
				display: inline-block;
			}

			.arrow[ui-open] {
				rotate: 90deg;
			}

			.group:not([hidden]) {
				margin-inline-start: 1em;
				border-inline-start: 2px dashed var(--ink);
			}
		</style>
	</tree.root>
}
```
</Code>

`index.ts` and `app.tsrx` use the same `tree.item` part as `src`, one level down. The
`.arrow[ui-open]` rule turns the arrow on any row at any depth. Menus nest the same way: a submenu
is a `menu.itemcontent` written inside a `menu.item`.
