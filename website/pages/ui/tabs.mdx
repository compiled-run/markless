# tabs

<ThemeToggle />

`tabs` is a row of tabs over a set of panels. Each tab shows one panel, and only one panel shows
at a time.

<Playground scenario="basic" />

Click a tab, then press the Right arrow. Focus moves to the next tab and shows its panel. The
arrows walk past **Team**, because it is disabled.

Switch off **SelectOnFocus**, and the arrows move focus without showing the panel. Then Enter
shows it.

A tab and a panel with the same `value` are a pair. The family never matches them by position.
The root's `value` names the tab that shows first. If you leave it out, no tab shows.

## When to use it

Use `tabs` when a person switches between views of the same thing, such as the pages of an
account. If several sections can be open at once, use [accordion](/ui/accordion) instead.

## Parts

<AnatomyTable />

- `tabs.root` holds which tab shows, the arrow-key axis, and the focus rules. It renders a
  `<div>`.
- `tabs.list` is the row of tabs, with `role="tablist"`. It also writes `aria-orientation`.
- `tabs.trigger` is one tab. It is a `<button>` with `role="tab"`, and its `value` is required.
- `tabs.content` is one panel, with `role="tabpanel"`. Its `value` is required.

The whole row of tabs is one Tab stop. Only the showing tab has `tabindex="0"`. The showing
panel is a Tab stop too, so Tab from the tabs lands on the panel.

Every panel stays in the page. A panel that is not showing gets `hidden`. So what a person typed
in a panel, and its scroll position, are still there when they come back.

## Styling hooks

| Attribute | On | Present when |
| --- | --- | --- |
| `ui-selected` | trigger, content | This tab or panel is the one showing. |
| `ui-vertical` | root, list, trigger | `orientation` is `vertical`. |

A horizontal set writes no orientation attribute. Only the vertical one does.

## Keyboard

The family's tests check each of these rows.

| Key | What it does |
| --- | --- |
| Right arrow or Left arrow | Moves to the next or the previous tab. In a vertical set, use Down and Up. |
| Home or End | Moves to the first or the last tab. |
| Enter or Space | Shows the focused tab. You need this only when `selectOnFocus` is `false`. |

By default a tab shows as soon as focus reaches it. Set `selectOnFocus={false}` and the arrows move
focus only. Then Enter or Space shows the tab.

The arrows stop at the ends. Set `loop` and they wrap around from the last tab to the first.
The arrows skip a disabled tab. An arrow pressed with Alt, Ctrl or Cmd is left to the browser.

## Gotchas

<Callout
	sprite="speech-bubble"
	title="Why does a screen reader not say which tab a panel belongs to?"
	text="The family does not link a panel to its tab with aria-labelledby yet. Its own screen reader test for that is marked as a known failure. Until it lands, give each tabs.content an aria-label, as the demo does."
/>

<Callout
	sprite="bolt"
	title="Why does the close button inside my tab not work for screen readers?"
	text="role=tab tells a screen reader to treat everything inside the tab as plain text. A button or a link inside a tabs.trigger loses its own role. Put a close button next to the tab, not inside it."
/>
